## 1. 文档概述

### 1.1 背景

App 内存在媒体浏览场景，列表中的每个 Item 可能是图片、视频、实况图（olive/Live Photo），也可能是完全自定义的布局。现有解决方案在超大图（2亿像素级别）加载、HDR 显示、实况图播放、视频 Item 集成、深度自定义布局等方面能力不足，需要一套专为 Android 打造的高性能媒体浏览 SDK，以组件化方式向业务层提供完整的媒体浏览能力。

### 1.2 目标

- **业务目标**：提供一个可接入主流 Android 应用的媒体浏览 SDK 组件，使接入方无需自行实现复杂的图片/视频/实况图浏览逻辑。
- **用户目标**（最终用户）：流畅浏览各种格式、各种分辨率的图片，观看视频，体验实况图动效，支持手势操控、HDR 效果。
- **成功标准**：
  - 2亿像素图片可稳定加载、分块显示，无 OOM；
  - 手势缩放、旋转、切换流畅（≥60fps，❓ 待确认目标帧率）；
  - 视频 Item 可正常播放，不影响相邻图片 Item 的手势交互；
  - 接入方可在不修改 SDK 源码前提下完全自定义每页布局。

### 1.3 范围

**包含范围**

- 图片格式解码与渲染（JPEG / PNG / HEIF / WebP / BMP / GIF）
- 超大图分块（Tile）加载与区域解码
- 手势交互：双击放大、双指缩放、单指平移、双指旋转（旋转仅适用于图片 Item）
- 媒体列表（Pager）左右翻页，支持四种内置 Item 类型：图片、视频、实况图（olive）、自定义
- 视频 Item 播放（作为 Pager 独立 Item 类型）
- 实况图（olive / Live Photo）Item：静态展示 + 长按播放动效
- 每页 Item 布局完全可自定义（支持纯自定义 View 替代整页内容）
- HDR 效果显示
- 沉浸式浏览：edge-to-edge 内容延伸、点击空白区触发 UI 显隐回调
- 翻页指示器（Indicator）：SDK 提供默认样式，支持自定义替换，支持进度显示
- 幻灯片自动播放（Slideshow）
- 双形态动态布局切换：展示态（图片+周边装饰）↔ 浏览态（纯媒体），无缝动画过渡
- Demo App：与 SDK 一同交付，演示各典型使用场景

**不包含范围**

- 图片编辑（裁剪、滤镜、标注等）
- 图片/视频上传、分享、下载功能
- 图片压缩工具
- 非 Android 平台（iOS、Web 等）
- 通用流媒体播放器（视频 Item 为本地/URI 播放，不含直播流、HLS 等）
- 网络 URL 图片和视频加载（URL → 本地缓存）

## 4. 功能需求详述

### 4.1 多格式图片解码（FR-001）

**目标**
使 SDK 接入方无需关心格式兼容，统一传入图片数据源，SDK 自动识别并解码。

**前置条件**

- 接入方已向 SDK 提供合法图片数据源（本地路径、ContentResolver URI、网络 URL）

**主流程**

1. SDK 接收图片数据源。
2. 识别图片格式（通过文件头 Magic Bytes 或扩展名）。
3. 调用对应解码器解码并渲染。

**异常与边界**


| 场景     | 条件        | 系统响应                  | 备注                      |
| ------ | --------- | --------------------- | ----------------------- |
| 格式不支持  | 传入非支持格式文件 | 回调错误事件，展示 placeholder | ⚠️ placeholder 样式待接入方定义 |
| 文件损坏   | 图片数据不完整   | 回调错误事件，展示 placeholder | —                       |
| 格式识别失败 | 无法判断格式    | 回调错误事件                | —                       |


**验收标准**


| 编号     | 验收项     | 标准                                |
| ------ | ------- | --------------------------------- |
| AC-001 | JPEG 显示 | JPEG 图片正确解码并渲染                    |
| AC-002 | PNG 显示  | PNG（含透明通道）正确解码并渲染                 |
| AC-003 | HEIF 显示 | HEIF/HEIC 图片正确解码（Android 9+ 硬件解码） |
| AC-004 | WebP 显示 | WebP（含动态 WebP）正确解码                |
| AC-005 | BMP 显示  | BMP 图片正确解码                        |
| AC-006 | GIF 显示  | GIF 动图按帧率播放                       |

### 4.2 超大图分块加载与区域解码（FR-002、FR-003）

**目标**
在有限内存下加载并展示 2 亿像素级超大图，防止 OOM，保证用户缩放后细节清晰。

**前置条件**

- 图片文件已可寻址读取（本地文件或支持随机访问的数据源）

**主流程**

1. 首次加载时，以缩略图精度解码全图用于初始展示。
2. 根据当前视口（Viewport）和缩放倍率计算可见区域对应的图片坐标范围。
3. 只对可见区域所在的 Tile 块进行解码渲染。
4. 用户缩放或平移时，重新计算可见区域，加载新 Tile，释放不可见 Tile 缓存。

**业务规则**

- Tile 大小：可配置，SDK 提供默认值（❓ 具体默认值留技术方案确定）
- 内存占用上限：可配置，SDK 提供合理默认值
- 解码线程数：可配置，SDK 提供合理默认值

**异常与边界**


| 场景   | 条件         | 系统响应                  |
| ---- | ---------- | --------------------- |
| 内存不足 | 可用内存低于安全阈值 | 释放低优先级 Tile 缓存，降级解码精度 |
| 快速滑动 | Tile 来不及解码 | 显示低精度占位图，解码完成后替换      |


**验收标准**


| 编号     | 验收项        | 标准                                 |
| ------ | ---------- | ---------------------------------- |
| AC-007 | 2亿像素图不 OOM | 在 4GB RAM 设备上加载 2 亿像素 JPEG，不发生 OOM |
| AC-008 | 缩放后清晰      | 放大至 5 倍后，对应 Tile 重新解码，无明显模糊        |
| AC-009 | 可见区域解码     | 仅当前视口所在 Tile 处于解码状态，不解码不可见区域       |

### 4.3 手势交互（FR-004 ~ FR-008）

**目标**
提供自然流畅的手势操控体验，缩放、平移、旋转手势不互相干扰。

**适用对象**

| 手势 | 图片 Item | 视频 Item | 实况图 Item |
|------|-----------|-----------|-------------|
| 双击放大 | ✅ | ✅ | ✅ |
| 双指缩放 | ✅ | ✅ | ✅ |
| 单指平移 | ✅ | ✅ | ✅ |
| 双指旋转 | ✅ | ❌ | ❌ |

**主流程（缩放）**

1. 双击：以点击位置为中心，放大 2 倍；再次双击还原 1 倍。
2. 双指捏合：实时追踪双指距离变化，线性映射缩放比例；范围 [1.0, 5.0]。
3. 超出最大值（5 倍）时，提供橡皮筋阻尼感，松手回弹到 5 倍。
4. 缩小到 1 倍以下时，提供橡皮筋阻尼感，松手自动回弹到 1 倍（正常显示）。

**主流程（平移）**

1. 图片/视频放大后，内容超出视口可见区域时，单指拖动可平移查看任意区域。
2. 平移至内容边缘时，提供轻微阻尼过界感，松手回弹到合法范围内。

**主流程（旋转）**

1. 双指旋转手势，图片跟随旋转角度实时旋转。
2. 松手后自动对齐到最近的 90° 倍数（0°/90°/180°/270°），执行对齐动画。

**业务规则**

- 双击放大倍率固定为 2 倍，相对于**当前显示比例**（如当前 1.5×，双击后变为 3×；若已达 5× 上限则不再放大）
- 最大缩放上限：5 倍（相对于原始尺寸）
- 最小缩放下限：1 倍（即完整显示内容的 fit-screen 比例），缩小到 1 倍以下自动回弹
- 图片放大后按当前倍率重新解码对应 Tile，保持清晰；视频由播放器自身处理缩放渲染

**验收标准**


| 编号     | 验收项        | 标准                           |
| ------ | ---------- | ---------------------------- |
| AC-010 | 双击放大      | 双击后图片放大 2 倍，再次双击还原                   |
| AC-011 | 最大缩放回弹   | 捏合放大不超过 5 倍，超出边界有阻尼，松手回弹到 5 倍      |
| AC-012 | 最小缩放回弹   | 缩小到 1 倍以下松手后自动回弹到 1 倍（fit-screen）   |
| AC-013 | 图片缩放清晰度  | 任意缩放倍率下，对应 Tile 重新解码，无拉伸模糊          |
| AC-014 | 视频缩放     | 视频 Item 支持双指捏合放大/缩小，内容不模糊           |
| AC-036 | 平移触发条件   | 内容放大后只要超出视口即可单指平移，不要求"整图超出屏幕"      |
| AC-037 | 平移边缘回弹   | 平移到内容边缘过界后，松手回弹到合法范围               |
| AC-038 | 图片旋转响应   | 双指旋转时图片实时跟随旋转角度变化                   |
| AC-071 | 旋转松手对齐   | 松手后图片自动对齐到最近的 90° 倍数，有对齐动画           |
| AC-044 | 视频不响应旋转  | 视频 Item 上双指旋转手势不触发旋转，不崩溃             |
| AC-045 | 实况图不响应旋转 | 实况图 Item 上双指旋转手势不触发旋转，不崩溃            |

### 4.4 媒体列表翻页（FR-009、FR-010）

**目标**
提供多媒体浏览的左右翻页能力，每页可独立呈现图片、视频、实况图或自定义内容。

**主流程**

1. 接入方提供数据集合，为每个位置指定 Item 类型（图片 / 视频 / 实况图 / 自定义）。
2. 用户向左/右滑动超出阈值后，切换到相邻 Item。
3. SDK 根据 Item 类型调用对应渲染/播放逻辑。
4. 切换动画：❓ 待确认（滑动跟手 / 渐变 / 无动画）

**业务规则**

- 四种内置 Item 类型可在同一列表中任意混用，每个 Item 的布局和类型独立配置。
- 左右滑动有回弹机制：滑动未达到翻页阈值时，自动回弹到当前 Item。
- 不支持循环翻页，第一页左滑和最后一页右滑均有阻尼但不跳转。
- 预加载相邻页数量：❓ 待确认（建议可配置，默认 1）
- 切换离开图片 Item 时：**缩放状态重置**为 1×，**旋转状态保留**（不重置）。
- 切换离开视频 Item 时，视频自动暂停（避免多路音频同时播放）

**验收标准**


| 编号     | 验收项      | 标准                              |
| ------ | -------- | ------------------------------- |
| AC-015 | 左右翻页     | 滑动超过阈值后切换到相邻 Item，动画流畅          |
| AC-016 | 翻页回弹     | 滑动未达翻页阈值时，松手自动回弹到当前 Item        |
| AC-025 | 边界阻尼不越界  | 第一页左滑、最后一页右滑有阻尼感，不跳转，不崩溃         |
| AC-072 | 翻页缩放重置   | 切换到新 Item 后，图片缩放比例重置为 1×         |
| AC-073 | 翻页旋转保留   | 切换到新 Item 后，图片旋转角度保留，不重置为 0°    |
| AC-039 | 混合列表翻页   | 图片/视频/实况图/自定义 Item 混合列表可正常翻页    |

### 4.5 Item 布局深度自定义（FR-010、FR-011）

**目标**
每个 Item 的整体布局由接入方自由定制，同一列表中每个位置的 Item 布局可完全不同；SDK 提供默认布局（大图/视频居中），但不强制使用。

**默认布局（SDK 内置）**
- 图片 Item：图片居中充满容器，fit-screen 比例显示，支持缩放/平移/旋转手势。
- 视频 Item：视频居中播放，默认无控制栏（控制栏由接入方叠加）。
- 实况图 Item：封面帧居中静态展示，与图片 Item 相同。

**主流程**

1. 接入方通过 Adapter / 回调为每个位置独立指定 Item 类型及布局配置。
2. 对于内置类型（图片/视频/实况图），接入方可在默认布局基础上叠加自定义层，也可完全替换布局。
3. 对于自定义 Item 类型，SDK 仅提供容器生命周期管理，不渲染任何默认内容。

**可自定义的典型场景（举例，非穷举）**

| 场景 | 描述 |
|------|------|
| 图片四周边框 | Item 上下左右各有固定边框区域，边框内可放文字、小图片等 |
| 图片下方模糊背景 | 图片实际内容区域上方，下层渲染图片模糊版本作为背景填色 |
| 图片上方贴图叠层 | 图片渲染区域上方可叠加多个可定位的贴纸/小图片 View |
| 完全替换内容区 | 某个 Item 不显示图片，改为地图、WebView 或任意自定义 View |
| 每页独立布局 | 同一列表第 1 页为纯图、第 2 页为图片+底部说明文字、第 3 页为地图，互不干扰 |

**业务规则**

- 每个 Item 的布局配置相互独立，接入方在 Adapter 回调中按 position 返回对应布局。
- 接入方叠加在图片/视频上方的 View 层不能干扰 SDK 的手势识别（SDK 负责手势透传/分发机制）。
- 当某个位置完全由接入方自定义（无图片/视频），SDK 不触发任何媒体加载逻辑。
- SDK 不限制接入方在 Item 内的 View 层级数量和类型。

**验收标准**


| 编号     | 验收项            | 标准                              |
| ------ | -------------- | ------------------------------- |
| AC-017 | 自定义内容区渲染       | 注册自定义 Item 后，该页显示自定义内容，不触发媒体加载  |
| AC-018 | 图片+叠层不干扰手势     | 图片上叠加贴图/文字层后，缩放/平移手势仍正常工作      |
| AC-019 | 边框布局           | 图片四周有边框区域，边框内可渲染文字和图片，图片居中显示  |
| AC-041 | 图片下方模糊背景       | 图片区域下层可叠加模糊背景，不影响图片正常渲染        |
| AC-042 | 每页独立布局         | 同一列表中相邻两页可使用完全不同的布局结构           |
| AC-043 | 完全替换内容区        | 某页注册地图 View 后，SDK 不加载图片，该页正常显示  |

### 4.6 HDR 显示（FR-012）

**目标**
充分利用支持 HDR 的设备显示图片的真实亮度和色彩，提升视觉质感。

**前置条件**

- 设备显示屏支持 HDR（如 HLG、HDR10、Dolby Vision 之一）
- 图片含 HDR 元数据（HEIF/JPEG 的 Gainmap、Ultra HDR 格式等）

**主流程**

1. 加载图片时检测是否含 HDR 元数据。
2. 检测当前设备/窗口是否支持 HDR 渲染。
3. 如双重条件满足，使用 HDR 渲染路径（如 Android Ultra HDR API）。
4. 否则降级为 SDR 渲染，不崩溃。

**业务规则**

- HDR 渲染最低 Android 版本：Android 14（API 34）；低于此版本自动降级为 SDR 渲染
- ❓ 是否需要支持 Gainmap 方案还是仅 Ultra HDR 方案，待确认

**验收标准**


| 编号     | 验收项    | 标准                               |
| ------ | ------ | -------------------------------- |
| AC-020 | HDR 渲染 | 含 HDR 元数据的图片在支持设备上亮度/色域超出 SDR 范围 |
| AC-021 | SDR 降级 | 不支持 HDR 的设备上图片正常显示，不崩溃           |

### 4.7 实况图（olive）Item 播放（FR-013）

实况图（olive / Live Photo）作为独立 Item 类型存在于媒体列表中，默认以静态图片展示，长按触发动效片段播放，松手停止，提升沉浸感。

**验收标准**

| AC-024 | 松手停止播放     | 松手后停止播放，恢复静态封面帧          |

### 4.8 视频 Item 播放（FR-015）

**目标**
视频作为独立 Item 类型集成到媒体列表中，支持基础播放控制，与相邻图片/实况图 Item 共存不互相干扰。

**前置条件**

- Item 类型标识为视频
- 视频数据源为本地文件路径 / ContentResolver URI（❓ 是否支持网络 URL 待确认）
- ❓ 支持的视频编码格式（H.264 / H.265 / AV1 等）待确认

**前置条件**

- 接入方已通过 SDK 注入视频播放器实例（接口/抽象，SDK 不内置播放器）
- 视频数据源为本地文件路径 / ContentResolver URI（❓ 是否支持网络 URL 待确认）

**主流程**

1. SDK 加载视频 Item，通知接入方注入的播放器准备数据源，显示封面/首帧。
2. 根据配置决定播放触发方式：
   - 自动播放模式：Item 进入视口后自动开始播放；
   - 手动播放模式：等待接入方或用户触发播放指令。
3. 视频播放中，控制栏 UI（进度条、音量、全屏等）完全由接入方自行实现，SDK 不提供默认控制栏。
4. 用户左右滑动翻页离开该 Item，SDK 通知播放器暂停。

**业务规则**

- 自动播放行为可通过 SDK 配置项控制（全局配置，❓ 是否支持 per-item 级别配置待确认）。
- 视频控制栏 UI 完全由接入方定义，SDK 仅提供播放状态回调供接入方驱动 UI。
- 播放框架由接入方注入（如 ExoPlayer、Media3、自研播放器），SDK 通过抽象接口与播放器交互。
- SDK 不内置任何播放器，不引入 ExoPlayer 等视频相关依赖。
- 视频 Item 支持双指缩放和单指平移手势（与图片 Item 一致）；不支持双指旋转手势。
- 同一时刻最多一个视频 Item 处于播放状态。

**异常与边界**


| 场景      | 条件       | 系统响应              |
| ------- | -------- | ----------------- |
| 视频格式不支持 | 编解码器不兼容  | 显示错误占位图，回调错误事件    |
| 视频文件损坏  | 无法解码     | 显示错误占位图，不崩溃       |
| 后台切换    | App 进入后台 | 视频自动暂停，返回前台后不自动恢复 |


**验收标准**


| 编号     | 验收项      | 标准                        |
| ------ | -------- | ------------------------- |
| AC-028 | 视频封面展示     | 视频 Item 进入视口后显示封面/首帧                  |
| AC-029 | 自动播放配置     | 配置为自动播放时，Item 进入视口后视频自动播放           |
| AC-030 | 手动播放配置     | 配置为手动播放时，进入视口不自动播放，等待触发             |
| AC-031 | 离页自动暂停     | 滑动翻页离开视频 Item 后，SDK 通知播放器暂停         |

### 4.8.1 沉浸式布局支持（FR-017）

**目标**
SDK 容器内容延伸至系统栏（状态栏/导航栏）下方（edge-to-edge），并提供点击空白区域的事件回调，使接入方可实现沉浸式浏览模式切换（隐藏/显示系统 UI 及页面菜单、Indicator）。

**前置条件**
- 宿主 Activity 已启用 edge-to-edge 模式（`WindowCompat.setDecorFitsSystemWindows(window, false)`）

**主流程**
1. SDK 容器布局时忽略系统栏 insets，内容绘制延伸至系统栏下方。
2. SDK 为接入方提供 insets 信息（系统栏高度/宽度），供接入方自行为菜单、Indicator 等 UI 添加正确的 padding/margin，避免被系统栏遮挡。
3. 用户点击 Item 内非媒体交互区域（如 Item 背景、边框区域等），SDK 触发 `onTapOutsideMedia` 回调。
4. 接入方在��调中调用系统 API（`WindowInsetsController`）隐藏/显示状态栏和导航栏，并自行控制菜单、Indicator 的显隐。
5. SDK 内置 Indicator 响应接入方调用 `setIndicatorVisible(Boolean)` 实现显隐。

**业务规则**
- SDK 本身不直接操作系统栏显隐，仅提供回调和 Indicator 控制接口；系统栏控制权归属接入方。
- 媒体区域内的手势（缩放/平移/旋转）不触发 `onTapOutsideMedia`，仅单击且无位移的 tap 才触发。
- 长按实况图区域触发动效播放，不触发 `onTapOutsideMedia`。

**验收标准**

| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-049 | edge-to-edge 布局 | SDK 容器内容延伸至状态栏和导航栏下方，无黑边 |
| AC-050 | 点击空白触发回调 | 点击 Item 非媒体区域触发 `onTapOutsideMedia`，媒体手势不触发 |
| AC-051 | Indicator 显隐控制 | 调用 `setIndicatorVisible(false)` 后 Indicator 隐藏，`true` 后恢复显示 |
| AC-052 | insets 信息透传 | SDK 向接入方提供当前系统栏 insets 数值，接入方可据此调整 UI 位置 |

### 4.8.2 翻页指示器 Indicator（FR-018）

**目标**
SDK 内置默认翻页指示器，同时支持接入方完全替换为自定义样式；Indicator 每个 Item 单元支持进度显示，用于幻灯片自动播放场景。

**默认 Indicator 样式**
- 每个 Item 对应一个横线形指示单元。
- 当前激活 Item 的指示单元高亮显示。
- 幻灯片模式下，激活单元内显示随时间推进的进度填充动画。
- 默认位置：底部，距屏幕底部 24dp（沉浸模式下需结合 insets 偏移）。

3. SDK 在翻页、幻灯片进度变化时回调 `IndicatorAdapter`，接入方驱动自定义 UI 更新。
4. 接入方可调用 `setIndicatorVisible(Boolean)` 控制整体显隐（配合沉浸模式使用）。

**业务规则**
- 自定义 `IndicatorAdapter` 接口由 SDK 定义，接入方实现。
- 进度值（0.0~1.0）由 SDK 在幻灯片计时器 tick 时推送给 Indicator。
- Indicator 默认固定在底部距屏幕底部 24dp；同时支持完全脱离 SDK 容器独立放置：接入方可将自定义 Indicator View 放在任意布局位置，通过 SDK 回调驱动更新。

**验收标准**

| 编号 | 验收项 | 标准 |

| AC-054 | 翻页同步 | 翻到第 N 页时，第 N 个 Indicator 单元激活 |
| AC-055 | 进度动画 | 幻灯片模式下，当前 Indicator 单元显示随时间推进的进度填充 |
| AC-056 | 自定义 Indicator | 注册自定义 `IndicatorAdapter` 后，默认样式被完全替换 |

### 4.8.3 幻灯片自动播放（FR-019）

**目标**
SDK 支持 Slideshow 模式，按配置的时间间隔自动翻到下一页，Indicator 同步展示当前页剩余进度。

**主流程**
1. 接入方调用 `startSlideshow(intervalMs)` 开启幻灯片模式。
2. SDK 启动计时器，每隔 `intervalMs` 毫秒自动翻到下一页；到达最后一页后循环回第一页。
3. Indicator 当前页单元实时更新进度（从空到满填充，表示当前页剩余停留时长）。
4. 用户手动翻页时，SDK 暂停自动播放；用户停止操作达到空闲超时时长（默认 10 秒，可配置）后，从当前页继续自动播放。
5. 接入方调用 `stopSlideshow()` 时，彻底停止幻灯片模式（不再自动恢复）。

**业务规则**
- `intervalMs`：每页停留时长，由接入方配置，❓ 是否设最小值保护，待确认。
- `resumeDelayMs`：用户手动操作后的空闲恢复等待时长，默认 10000ms，可配置。
- 手动翻页触发暂停后，Indicator 当前页进度冻结在暂停时刻；恢复后从冻结处继续计时（而非重置）。
- 接入方调用 `stopSlideshow()` 后不再自动恢复，需重新调用 `startSlideshow()` 才能再次开启。
- 视频 Item 页面的幻灯片计时方式：按固定 `intervalMs` 翻页，不等视频播完。

**验收标准**

| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-058 | 自动翻页 | 开启 Slideshow 后按 intervalMs 自动翻到下一页 |
| AC-059 | Indicator 进度同步 | 当前页 Indicator 单元进度随时间实时从空到满推进 |
| AC-060 | 手动翻页暂停 | 用户手动翻页后自动播放暂停，Indicator 进度冻结 |
| AC-061 | 空闲后自动恢复 | 用户停止操作达到 resumeDelayMs 后，从当前页继续自动播放 |
| AC-067 | 恢复后进度续播 | 恢复后 Indicator 从冻结位置继续计时，不重置为 0 |
| AC-068 | 彻底停止 | 调用 `stopSlideshow()` 后自动播放停止且不自动恢复 |
| AC-069 | 最后一页循环 | 幻灯片播放到最后一页后自动翻回第一页继续 |
| AC-070 | 视频页固定时间翻页 | 视频 Item 不等视频播完，按 intervalMs 到时间即翻页 |

### 4.8.4 双形态动态布局切换（FR-020）

**目标**
每个 Item 支持定义两种布局形态（展示态和浏览态），接入方可触发无缝切换，SDK 负责媒体内容区域在两种形态间的位置/尺寸动画过渡，确保切换流畅自然。

**概念定义**
- **展示态（Layout A）**：图片/视频周围有接入方自定义的装饰区域（边框、文字、贴图等），媒体内容区域较小，位于 Item 中的某个子区域内。
- **浏览态（Layout B）**：仅显示媒体内容，隐藏周边装饰，媒体内容区域扩展至整个 Item 容器。
- **切换动画**：SDK 自动在两种形态之间对媒体区域执行位置/尺寸插值动画（类 Shared Element Transition），周边装饰的淡入/淡出由 SDK 驱动或接入方自行实现。

**前置条件**
- 接入方在 Item 布局中通过特定方式（❓ 标记 View ID / SDK 提供专用容器 / 回调告知，具体接口待确认）声明媒体内容区域的位置和尺寸。
- 接入方分别提供展示态布局和浏览态布局（两个独立布局或同一布局的两种状态）。

**主流程**
1. 初始状态为接入方配置的默认形态（❓ 默认哪种形态，待确认）。
2. 接入方调用 `switchLayout(mode: LayoutMode)` 触发形态切换。
3. SDK 计算媒体区域从当前形态到目标形态的 Rect 差异（位置、大小）。
4. SDK 执行插值动画，媒体内容在目标位置/尺寸上平滑过渡。
5. 动画结束后，目标形态布局完全就位，SDK 回调 `onLayoutSwitchComplete`。
6. 接入方可在动画进行中或完成后再次触发反向切换。

**业务规则**
- 切换动画时长：可配置，SDK 提供合理默认值。
- 切换期间手势（缩放/平移/旋转）全部禁用，动画结束后恢复。
- 动画过程不可打断：动画进行中再次调用 `switchLayout` 时忽略，动画完成后方可再次触发。
- 切换到浏览态时，图片缩放状态重置为 1×（fit-screen）。
- 不同 Item 可独立处于不同形态（A 页在展示态、B 页在浏览态互不影响）。

**异常与边界**

| 场景 | 条件 | 系统响应 |
|------|------|----------|
| 未声明媒体区域 | 接入方未标注媒体区域 | SDK 降级为无动画直接切换，不崩溃 |
| 动画中再次触发 | 切换动画未完成时又触发切换 | 忽略本次触发，当前动画继续执行至完成 |

**验收标准**

| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-062 | 形态切换触发 | 调用 `switchLayout` 后 Item 在两种形态间切换 |
| AC-063 | 媒体区域动画 | 切换过程中媒体内容在新旧位置/尺寸间平滑过渡，无跳变 |
| AC-064 | 无缝回切 | 从浏览态切回展示态，动画自然，媒体内容回到原展示位置 |
| AC-065 | 多 Item 独立形态 | 不同 Item 可独立处于不同形态，互不影响 |
| AC-066 | 未声明媒体区域降级 | 未标注媒体区域时 SDK 不崩溃，降级为直接切换 |

### 4.8.5 SDK 事件回调系统（FR-021）

**目标**
SDK 向接入方提供完整的事件回调，覆盖翻页、媒体加载状态、视频播放状态等，使接入方能够驱动自定义 UI 并有效控制加载过渡体验（避免直接显示高清图/视频导致的黑屏）。

**回调事件清单**

| 事件类型 | 回调时机 | 典型用途 |
|----------|----------|----------|
| `onPageChanged(from, to)` | 翻页动画完成后 | 更新外部 Indicator、页码、菜单状态 |
| `onPageScrolled(position, offset)` | 翻页拖动过程中（每帧） | 实现联动动画（如外部标题渐变） |
| `onThumbnailLoaded(position)` | 当前 Item 缩略图解码完成，已显示 | 通知接入方缩略图已就绪，可隐藏 placeholder |
| `onHighResLoaded(position)` | 当前 Item 高清图解码完成，已替换 | 接入方可在此时机触发 UI 联动（如渐显）；高清图未加载完前保持显示缩略图 |
| `onVideoFirstFrameReady(position)` | 视频 Item 首帧解码完成，画面已就绪 | 接入方在此时机显示视频画面，避免直接开播时的黑屏 |
| `onVideoPlaybackStateChanged(position, state)` | 视频播放状态变化（播放/暂停/结束/错误） | 接入方据此更新播���控制按钮状态 |
| `onVideoVolumeChanged(position, volume, muted)` | 音量或静音状态变化 | 接入方据此更新音量/静音 UI |
| `onLoadError(position, error)` | 图片/视频加载失败 | 接入方显示错误占位图或重试 UI |

**关键加载时序说明（防黑屏机制）**

```
图片 Item:
  placeholder 显示
    → onThumbnailLoaded()  ← 缩略图就绪，快速显示低精度预览
    → onHighResLoaded()    ← 高清图就绪，SDK 平滑替换（接入方可叠加渐显动画）

视频 Item:
  placeholder / 封面图 显示
    → onThumbnailLoaded()  ← 封面帧就绪
    → onVideoFirstFrameReady() ← 视频首帧解码完成，接入方触发播放（规避黑屏）
```

**业务规则**
- 接入方不注册回调时，SDK 正常工作，不报错。
- `onThumbnailLoaded` 和 `onHighResLoaded` 均以 `position` 标识具体 Item，非当前页也可触发（预加载场景）。
- 视频 Item 在 `onVideoFirstFrameReady` 触发前，SDK 持续显示封面图，不显示黑屏。
- 回调均在主线程执行。

**验收标准**

| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-074 | 翻页回调 | 翻页完成后 `onPageChanged` 触发，from/to 值正确 |
| AC-075 | 缩略图回调 | 缩略图显示后 `onThumbnailLoaded` 触发 |
| AC-076 | 高清图回调 | 高清图替换后 `onHighResLoaded` 触发，先于此时机不显示高清图 |
| AC-077 | 视频首帧回调 | 视频首帧解码完成后 `onVideoFirstFrameReady` 触发，触发前不显示黑屏 |
| AC-078 | 视频状态回调 | 视频播放/暂停/结束时对应状态回调正确触发 |
| AC-079 | 音量回调 | 音量/静音变化时 `onVideoVolumeChanged` 正确触发 |
| AC-080 | 不注册回调不崩溃 | 接入方不注册任何回调，SDK 正常运行 |

## 7. 约束、风险与待确认事项

### 7.1 约束条件

- 目标平台仅为 Android（不包含跨平台方案）。
- 超大图区域解码依赖 `BitmapRegionDecoder`，部分格式在低版本系统上支持有限（如 HEIF 需 API 28+）。
- Ultra HDR 渲染 API 需要 Android 14（API 34）及以上。

### 7.2 风险


| 编号    | 风险描述                                        | 影响                                        | 建议                               |
| ----- | ------------------------------------------- | ----------------------------------------- | -------------------------------- |
| R-001 | HEIF 格式的 BitmapRegionDecoder 在部分厂商 ROM 上不支持 | 超大 HEIF 图片无法分块加载，退回全图解码可能 OOM             | 提前做机型兼容性矩阵测试                     |
| R-002 | Motion Photo 内嵌视频格式存在多厂商差异                  | 三星 / 华为 / 谷歌 Pixel 的 Motion Photo 格式不完全一致 | 明确初版只支持 Google Motion Photo 标准格式 |
| R-003 | HDR Gainmap 渲染性能开销                          | 低端设备帧率下降                                  | 提供 HDR 开关，接入方可按设备能力控制            |
| R-004 | 双指旋转与翻页手势可能冲突                               | 对角方向旋转时可能误触发翻页                            | 旋转手势检测与翻页手势需做冲突仲裁                |
| R-005 | 超大图首次加载内存峰值不可控                              | 2亿像素图缩略图解码阶段也可能占用数百MB                     | 需要压测并设计安全降采样策略                   |

### 8.2 合理推断

- ⚠️ GIF 动图自动按帧率播放：依据为格式支持描述中包含 GIF，且 GIF 的核心价值即动画
- ⚠️ 手势帧率目标 ≥ 60fps：依据为"流畅"是所有触控交互的行业基线
- ⚠️ 内存压力下自动释放缓存：依据为超大图场景下的稳定性基本要求
- ⚠️ 图片加载有 loading / error 状态：依据为网络或本地 IO 延迟场景的基本 UX 规范
- ⚠️ SDK 以 AAR 或 Maven 方式分发：依据为 Android 三方 SDK 行业标准
- ⚠️ 离页/后台时 SDK 通知注入的播放器暂停：依据为多路音频同时播放的体验基线要求
