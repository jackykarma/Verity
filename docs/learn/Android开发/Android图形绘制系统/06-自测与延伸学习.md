## 这次学习最值得记住的 3 句话

1. **Canvas 是指令接收者，不是像素容器**——硬件加速下它录指令，GPU 生像素。
2. **Surface 是 BufferQueue 的生产者接口**——像素的真正载体是 GraphicBuffer，它存在 GPU 可访问的共享内存里，Bitmap 和它是两套体系。
3. **一帧经历五段旅程**：描述（onDraw）→ 录制（DisplayList）→ 栅格化（GPU）→ 缓冲（BufferQueue）→ 合成显示（SurfaceFlinger + 屏幕）。

## 延伸学习方向

### 下一步推荐子主题

| 主题 | 为什么推荐 | 对应本次学习的哪个疑问 |
|------|----------|---------------------|
| **Choreographer 深入** | 理解帧调度的完整细节，学会用它监控帧率 | "一帧的时间边界是哪里" |
| **View 绘制三步曲** | measure/layout 如何影响 draw 的执行 | "invalidate 和 requestLayout 的区别" |
| **Perfetto 实战** | 动手抓 trace，在真实 App 里观察上面所有阶段 | "掉帧到底发生在哪里" |
| **OpenGL ES 基础** | 理解 GPU 渲染管线的细节（顶点/片段着色器） | "GPU 怎么画矩形、圆、文字" |

### 推荐实验

1. **验证 DisplayList 复用**：写一个自定义 View，在 `onDraw()` 里打 log，然后用属性动画改 `translationX`，观察 `onDraw()` 是否被调用

2. **验证双缓冲**：用 `SurfaceHolder.lockCanvas()` 和 `unlockCanvasAndPost()`，在 SurfaceView 上手动画动画，感受 Buffer 申请→写入→提交的节奏

3. **截图实验**：调用 `PixelCopy.request()` 把 SurfaceView 内容截图到 Bitmap，体验从 GraphicBuffer → Bitmap 的 readback

4. **Perfetto 实战**：用 Android Studio Profiler 或命令行 `adb shell perfetto`，抓一次列表滑动的 trace，找到 `Choreographer#doFrame`、`DrawFrame`、`SurfaceFlinger` 的 slice，量一量每帧各阶段耗时
