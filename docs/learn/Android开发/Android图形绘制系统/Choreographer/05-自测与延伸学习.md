## 这次学习最值得记住的 3 句话

1. **Choreographer 不只是接收 Vsync，更是编排者**——它把 Input、Animation、Traversal 按固定顺序排好，保证每帧的工作有序完成，这才是它的核心价值。
2. **invalidate() 只是预约，不是立刻执行**——它向 Choreographer 注册 TRAVERSAL 回调，要等到下一个 Vsync 才真正触发 onDraw()，最快也要 1 个 Vsync 周期（~16ms）之后。
3. **卡顿一定发生在某个具体阶段**——主线程 measure/layout/draw/binder，或 RenderThread 的 GPU 等待，用 Perfetto 可以精确定位，不要凭感觉猜。

### 推荐阅读的 AOSP 源码

```
frameworks/base/core/java/android/view/
  Choreographer.java            ← Choreographer 主逻辑（重点读 doFrame、postCallback）
  ViewRootImpl.java             ← scheduleTraversals()、performTraversals()

frameworks/native/services/surfaceflinger/
  Scheduler/VsyncTracker.cpp    ← Vsync 建模
  Scheduler/EventThread.cpp     ← Vsync 分发
```

### 推荐 adb 命令

```bash
# 查看 SurfaceFlinger 的 Vsync 配置（app-offset、sf-offset）
adb shell dumpsys SurfaceFlinger | grep -A5 "VSYNC"

# 查看当前帧率
adb shell dumpsys SurfaceFlinger | grep "fps"

# 抓取 5 秒的系统 trace
adb shell atrace -z -b 32768 -t 5 gfx view wm am -o /sdcard/trace.ctrace
```
