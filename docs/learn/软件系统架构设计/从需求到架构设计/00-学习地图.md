# 从需求到架构设计｜学习地图

## 1. 主题边界

本主题聚焦“拿到一个需求之后，如何一步步推导出可落地的软件架构设计”，重点覆盖：

- 需求输入如何转成设计输入
- 如何识别业务边界和系统边界
- 如何推导 `0` 层架构设计
- 如何推导 `1` 层架构设计
- 如何识别关键模块
- 如何继续落到 `2` 层详细设计
- 如何选择合适的图表表达设计结果
- 如何做设计评审与迭代

本主题不重点展开：

- 某一门具体语言的编码规范
- 某一个框架的 API 细节
- 某一种固定架构风格的完整教科书式介绍

## 2. 为什么值得学

如果不会这条主线，常见后果是：

- 设计停留在概念层，无法落地
- 图画得很多，但图与需求没有因果关系
- 模块划分看似完整，实际职责交叉
- 详细设计只能“照着写代码”，无法解释为什么这样设计

掌握这条主线后，你会更容易做到：

- 拿到需求后知道先思考什么
- 能把设计说清楚给别人听
- 能画出结构合理、含义清楚的图
- 能把设计推进到可实现、可评审的程度

## 3. 前置知识

建议先具备以下基础：

- 基本的软件开发经验
- 面向对象基础
- 常见模块化和分层概念
- 基本的类图、时序图、流程图认知

如果前置知识不完整，也可以学习本主题，但需要同步补：

- 面向对象设计
- 模块职责划分
- 接口与依赖方向

## 4. 学习顺序

建议按下面顺序学习，不要跳过前半段直接画图：

1. 需求输入与问题澄清
2. 业务边界与系统边界识别
3. `0` 层架构设计
4. `1` 层架构设计
5. 关键模块设计
6. `2` 层详细设计
7. 图表表达与设计文档化
8. 评审、收敛与迭代

## 5. 本主题最重要的 5 个问题

1. 为什么不能一拿到需求就直接画类图或模块图？
2. `0` 层、`1` 层、`2` 层设计分别在回答什么问题？
3. 从需求到模块划分，中间到底需要经历哪些思考步骤？
4. 哪些模块值得做深度设计，哪些只需要保持边界清晰？
5. 如何证明这套设计既能落地，又不是过度设计？

## 7. 学习路线

### 入门路线

- 需求输入与问题澄清
- 业务边界与系统边界
- `0` 层架构设计
- `1` 层架构设计

适合：

- 刚开始学架构设计
- 经常直接跳到实现细节的人

### 实战路线

- 需求输入与问题澄清
- `0` 层架构设计
- `1` 层架构设计
- 关键模块设计
- 图表表达与设计文档化

适合：

- 需要做方案设计
- 需要写设计文档
- 需要和别人讲清设计

### 深入路线

- 边界识别
- `0` 层 / `1` 层 / `2` 层衔接
- 面向对象设计与 DDD 视角
- 评审与收敛

适合：

- 想系统提升架构能力
- 想主导复杂系统设计

### 速查路线

- `0` 层 / `1` 层 / `2` 层区别
- 上下文图画什么
- 模块图画什么
- 类图 / 时序图 / 流程图各自回答什么问题
- 常见设计失误
