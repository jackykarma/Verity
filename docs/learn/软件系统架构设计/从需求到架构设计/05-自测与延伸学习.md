# 从需求到架构设计｜自测与延伸学习

## 1. 这次学习最值得记住的 3 句话

1. 架构设计不是从图开始，而是从问题、边界、协作和权衡开始。
2. `0` 层看外部位置，`1` 层看内部结构，`2` 层看实现协作。
3. 不是所有模块都值得同样细的设计，关键模块才是重点下钻对象。

## 2. 自测题

### 基础理解

1. 为什么说需求输入不能直接等同于设计输入？
2. 业务边界和系统边界分别在帮助你回答什么问题？
3. `0` 层架构设计最核心的产物是什么？
4. `1` 层架构设计和 `2` 层详细设计的区别是什么？
5. 为什么关键模块设计是连接架构和详细设计的关键一步？

### 进阶理解

6. 如果一个系统的上下文图里画了很多内部模块，这通常说明什么问题？
7. 如果模块图里已经充满类、接口和方法名，这通常说明什么问题？
8. 为什么类图、时序图、流程图必须回答不同的问题？
9. 为什么评审时不能只看图是否齐全？
10. 为什么“能讲清代价”是设计成熟的重要标志？

## 3. 自测题答案要点

1. 需求输入是原始问题描述，设计输入是经过澄清后的目标、场景、约束和非目标。
2. 业务边界帮助你识别问题域，系统边界帮助你识别责任归属和外部依赖。
3. `0` 层最核心的是系统上下文图、边界说明和外部依赖视角。
4. `1` 层回答模块如何分工，`2` 层回答关键模块如何协作落地。
5. 因为它决定哪些地方需要继续深入，哪些地方只需保持清晰边界。
6. 说明 `0` 层和 `1` 层混淆了。
7. 说明 `1` 层和 `2` 层混淆了。
8. 因为静态结构、动态调用和业务判断不是同一个问题。
9. 因为图齐全不等于设计正确，核心还是问题、边界、协作和权衡是否合理。
10. 因为所有设计都有收益和成本，不能只讲好处不讲代价。

## 4. 复述任务

请尝试在不看文档的情况下完成下面任务：

1. 用你自己的话讲清楚 `0` 层、`1` 层、`2` 层分别在看什么。
2. 向一个同事解释，为什么拿到需求后不能直接画类图。
3. 用 3 分钟讲清楚“从需求到详细设计”的完整链路。

## 5. 小型设计练习

### 练习 1：做设计输入

任选一个你熟悉的功能，例如：

- 用户注册系统
- 订单取消流程
- 评论审核系统

只做下面这张表：

- 需求目标
- 用户与角色
- 输入输出
- 约束条件
- 成功标准
- 非目标

### 练习 2：做 `0` 层和 `1` 层

继续对上面的功能：

- 画一张 `0` 层上下文图
- 画一张 `1` 层模块图
- 给每个模块写一句职责说明

### 练习 3：挑一个关键模块做 `2` 层

从模块图里选一个最复杂或最重要的模块，补：

- 一张类图
- 一张时序图
- 一张流程图

## 6. 如何判断自己已经学会

你可以用下面标准自检：

- 看到需求后，不会立刻跳到实现细节
- 能先写出设计输入和边界说明
- 能清楚地区分 `0` 层、`1` 层、`2` 层
- 能说明为什么这样分模块
- 能解释类图、时序图、流程图分别在回答什么问题
- 能在评审时指出职责不清、边界不清和过度设计

## 7. 推荐延伸主题

建议按这个顺序继续深入：

1. `0层架构设计`
2. `1层架构设计`
3. `2层详细设计`
4. `面向对象设计`
5. `DDD`
6. `架构评审与设计权衡`
7. `质量属性与架构演进`

## 8. 下一步建议

如果你要继续系统学习，建议直接开始下一个主题：

- 如果你最弱的是“看系统全局”：先学 `0层架构设计`
- 如果你最弱的是“拆模块”：先学 `1层架构设计`
- 如果你最弱的是“落细节”：先学 `2层详细设计`
- 如果你最弱的是“对象建模”：先学 `面向对象设计` 或 `DDD`
