| 维度 | 内容 |

## FR / NFR *（必填）*

### FR（Functional Requirements）

> 每条 FR 必须**可测试**，避免「提升体验 / 更快 / 更稳定」等不可验证表述。

- **FR-001**：[系统必须 / 用户必须能够……]
- **FR-002**：[……]

### NFR（Non-Functional Requirements）

> 每条 NFR 必须**量化**并附带验收方式；细化评估在 design 阶段完成。

- **NFR-PERF-001**：[性能：阈值 + 触发条件，例如：前台 p95 ≤ xxx ms]
- **NFR-POWER-001**：[功耗：Top 5% 用户每日 mAh 上限 + 触发频次]
- **NFR-MEM-001**：[内存：峰值 / 平均增量上限 + 生命周期约束]
- **NFR-SEC-001**：[安全 / 隐私：认证 / 授权 / 数据保护 / 合规要求]
- **NFR-OBS-001**：[可观测性：日志 / 指标 / 埋点 / 告警的最低要求]
- **NFR-REL-001**：[可靠性：可用性 / 容错 / 恢复目标（如 RTO / RPO）]

## 完整场景矩阵 *（必填）*

> 每条场景须关联至少一个 FR/NFR；优先级：**P0**（不通过则不可交付）、**P1**（重要，进入 `/aisdd.techspec` 前确认覆盖）、**P2**（增强，可后续迭代）。
