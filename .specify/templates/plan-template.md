> 目的：明确"数据落在哪里、谁负责持久化、数据生命周期、迁移规则"。具体物理数据结构（表/字段/索引/查询）在 EPIC 软件设计说明书中设计。

### 3.1 存储形态与边界（必须）

- **存储形态**：Room/SQLite / DataStore / SharedPreferences / 文件（JSON/CSV/二进制） / 远端服务 / N/A
- **System of Record（权威来源）**：哪一份数据是权威（例如：DB 为准、文件为准、服务端为准）

- **数据规模与增长**：数量级、写入频次、读写热点（用于索引与分页策略）

### 3.2 数据约束与迁移规则

## 四、接口与契约规范

> 目的：在 plan 阶段明确本 Feature 的**能力承诺**（对外提供什么）与**外部依赖**（需要消费什么），以及接口层面的约束规则。
> 具体接口签名、字段定义、错误码枚举等**接口设计**在 EPIC 软件设计说明书中产出。

### 4.1 本 Feature 对外提供的能力（Capability Feature/跨模块复用场景）

> 目的：声明本 Feature 承诺对外交付哪些能力、给谁用、须遵守什么约束规则。具体接口设计（方法签名、参数、返回值）在 epicdesign 阶段产出。

- **能力清单**：本 Feature 承诺对外提供的能力列表（能力级别描述，非方法级别）
- **消费方**：哪些 Feature/模块将依赖这些能力
- **接口约束规则**（design 阶段设计接口时必须遵守）：
  - 幂等要求：哪些能力必须幂等
  - 线程安全：调用是否必须线程安全；协程/线程调度约束；取消语义
  - 版本与兼容：SemVer 策略；向后兼容约束；新增/弃用规则

### 4.2 本 Feature 依赖的外部接口/契约（存在外部依赖时必须）

> 目的：锁定外部依赖的调用约束与降级策略，避免实现期口径不一致。

- **依赖清单**：依赖的外部模块/服务/API/SDK（含 owner、文档链接）
- **调用约束**：超时/重试/退避/限流；缓存策略；一致性假设
- **失败模式与降级**：超时/限流/不一致/不可用时如何处理
- **已知接口协议**（若外部已提供）：引用 OpenAPI/Proto/JSON Schema 等契约文件；记录版本号与兼容约束

### 4.3 契约工件（contracts/）与引用方式（推荐）

> 推荐：把可机读的契约沉淀为文件，便于测试与演进。

- **contracts/**：`openapi.yaml` / `*.proto` / `json-schema/*.json` / `errors.md` 等
- **变更流程**：契约变更必须更新版本 + 兼容策略 + 关联 Story/Task
