- **单页应用、无服务端持久化**：不得将用户文件或解析结果上传至远程（与 EPIC/FEAT-001 隐私 FR 一致）；禁止默认接入第三方分析上报文件内容。

## 二、跨 Feature 边界与依赖规则

- **分层原则**（逻辑分层，非 Clean Architecture 套用）：
  - **壳层（Shell）**：FEAT-001 — 文件接入、校验、全局状态、布局导航、文件级错误。
  - **格式层（Format）**：FEAT-002 / FEAT-003 — 各自格式的结构树构建、负载类型判定、分区级警告；**互不依赖**。
  - **呈现层（Present）**：FEAT-004 — 唯一负责分区内容多形态渲染与统一提示口径。
  - **共享内核（Shared）**：会话 ID、文件句柄/ArrayBuffer 生命周期、解析任务取消信号、呈现调用契约类型、失败类型枚举 — **无 UI**。
- **依赖方向**：
  - Shell → Format（按主文件类型二选一激活）；Format → Present（调用呈现契约）；Present **不得**依赖 Format 解析实现。
  - Format-002 **禁止**依赖 Format-003；反之亦然。
  - Shared **禁止**依赖 Shell / Format / Present 任一具体 Feature 实现。
- **Feature 边界**：
  - 文件级错误（类型、大小、授权、超时、取消）→ **FEAT-001**。
  - 分区树语义、目录覆盖率、部分成功/失败回传 → **FEAT-002 / FEAT-003**。
  - 预览/播放/可读视图及统一文案 → **FEAT-004**。
- **跨层/跨 Feature 禁止项**：
  - Shell **不得**内嵌 JPEG/HEIC 标记或 box 解析逻辑。
  - Format Feature **不得**直接操作 DOM/Canvas/Video 元素做最终呈现（须经 FEAT-004）。
  - 任何 Feature **不得**将用户文件持久化到 IndexedDB/localStorage 供关闭页面后恢复（本期无历史）。

## 三、统一运行时约束

- **线程/协程**：
  - 每个活跃解析会话对应**至多一个**解析 Worker 任务；用户取消、重新选文件、切换文件时**必须**向 Worker 发送终止信号并释放 ArrayBuffer 引用。
  - 分区选中触发的媒体解码可在 Worker 或主线程执行，由 `epic-design` 选型；**不得**阻塞主线程超过 **3 秒**无反馈（与 FEAT-001 NFR 一致）。
  - 快速连续触发解析（双击等）**必须**合并为单次有效任务（与 FEAT-001 SC-010 一致）。
- **错误处理**：
  - 统一失败类型枚举（文件级）：`UNSUPPORTED_TYPE` | `FILE_TOO_LARGE` | `PERMISSION_DENIED` | `READ_FAILED` | `PARSE_TIMEOUT` | `PARSE_FAILED` | `PARSE_PARTIAL` | `CANCELLED` | `UNKNOWN`。
  - 分区级：`SEGMENT_WARNING` | `SEGMENT_UNREADABLE` | `ENV_UNSUPPORTED`（HEIC）| `PRESENT_PREVIEW_FAILED` | `PRESENT_PLAYBACK_FAILED` — 由 Format/Present 映射到 FEAT-004 统一用户文案。
  - 错误对象向 UI 传递时**不得**包含完整本地路径；可含样例/会话内分区 ID。
- **日志/可观测性**：
  - 开发/测试构建可输出结构化控制台日志（失败类型、格式、耗时、分区 ID）；生产构建默认关闭详细字节 dump。
  - 与 FEAT-001/002/003/004 的 NFR-OBS 对齐：须能按失败类型枚举做对账；**禁止**记录文件内容或用户路径。
- **权限/安全/合规**：
  - 仅通过 `<input type="file">` / 拖放读取用户主动提供的文件；无后台轮询目录。
  - **CSP 与跨域**：静态站点部署时默认无跨域文件上传；若使用 WASM/Worker，须同源加载。
  - 所有解码与渲染在**当前浏览器会话**内完成（FEAT-004 NFR-SEC-001）。

## 四、数据与存储总约束

- **System of Record 原则**：
  - 用户所选主文件的**权威二进制**为会话内内存中的 `ArrayBuffer`（或不可变视图）；分区树与元数据为解析派生结构，**非持久 SoR**。
  - 呈现层对媒体的可解码引用由 Format 层在会话内生成，生命周期随会话结束而释放。
- **缓存策略边界**：
  - **无跨会话持久化**（无 IndexedDB/Room 等等价存储用户文件或解析树）。
  - 会话内：FEAT-004 全分辨率解码缓存**最多 3 个分区**（NFR-MEM-001）；超出 LRU 释放，不得影响当前选中分区。
  - 重新选文件或关闭页签：**必须**清空解析树、呈现缓存与 Worker 状态。
- **迁移/回滚原则**：**N/A**（无服务端数据库）；版本升级仅涉及静态资源部署，不涉及用户数据迁移。
- **详细设计位置**：呈现契约字段、解析结果 DTO、环境检测矩阵在 `interface-design.md`；性能预算表在 `nfr.md`（`/aisdd.epicdesign`）。

**EPIC 级量化红线（不可在实现期擅自放宽）**：

| 指标 | 值 | 来源 |
|------|-----|------|
| 主文件大小上限 | **50MB** | epic / FEAT-001 FR-003 |
| 性能基准文件大小 | **≤ 20MB** | epic 成功标准 / 各 Feature NFR-PERF-001 |
| 列表首次完整渲染 P95 | **≤ 10s** | epic / FEAT-002/003 NFR-PERF-001 |
| 校验反馈 P95 | **≤ 1s** | FEAT-001 NFR-PERF-002 |
| 分区选中到呈现触发 P95 | **≤ 500ms**（不含媒体解码） | FEAT-002/003 NFR-PERF-002 |
| 图片预览首屏 P95 | **≤ 2s**（负载 ≤ 5MB） | FEAT-004 NFR-PERF-001 |
| 视频起播 P95 | **≤ 3s**（负载 ≤ 20MB，支持环境） | FEAT-004 NFR-PERF-002 |
| 解析超时默认 | **120s**（可配置常量，须用户可见「解析超时」） | FEAT-001 SC-009；实现期不得静默挂起 |
| 单文件预览解码内存（Format 增量） | JPEG **≤ 150MB** 峰值；HEIC **≤ 200MB** 峰值（相对基线，20MB 样例） | FEAT-002/003 NFR-MEM-001 |
| 工作台壳层内存增量 | **≤ 30MB** | FEAT-001 NFR-MEM-001 |

#### 3.2 本 Feature 依赖的外部能力

### FEAT-002 · 四、数据、NFR 与安全硬约束

- **存储形态**：会话内树形结构 + 对源 Buffer 的偏移/长度引用（禁止复制整文件多份）。
- **System of Record**：结构语义以源 JPEG 二进制为准；树节点为派生视图。
- **数据生命周期**：换文件 → 销毁树；与 FEAT-001 同步（SC-010）。
- **数据规模与增长**：20MB 样例列表 P95 ≤ 10s；内存峰值 ≤ 150MB（相对基线）。
- **迁移/回滚约束**：**N/A**。
- **性能/功耗/内存约束**：见 EPIC 表；选中到呈现触发 ≤ 500ms（不含解码）。
- **权限/隐私/合规**：分区原始字节不得传出浏览器；引用限于会话安全边界（NFR-SEC-001）。

## Feature FEAT-004：分区内容多形态呈现

| 字段 | 值 |
|------|-----|
| Feature ID | FEAT-004 |
| Feature Version | v0.2.0（来自 `spec.md`） |
| 规约档位 | Standard |
| 类型 | Capability |

### FEAT-004 · 一、规约摘要

- **Feature 目标**：按负载类型统一执行可读/图片预览/视频·音频播放策略矩阵，并向 FEAT-002/003 暴露稳定呈现契约（Owner）。
- **现有代码边界**：**需新增**；为跨格式唯一呈现入口。

### FEAT-004 · 二、增量约束

- **额外依赖**：浏览器 `<img>`/`<canvas>`/`<video>`/`<audio>` 或 WebCodecs 等（`epic-design` 选型）；**禁止**将媒体字节上传外部服务。
- **错误处理增量**：预览/播放失败不得假装成功（FR-009）；统一 FR-006 文案键；失败类型进入 `PRESENT_*` 枚举。
- **日志/可观测性增量**：记录失败类型、负载类型、分区 ID（无路径）。
- **兼容性约束**：图片负载 **100%** 走预览路径；支持环境内视频 **≥ 90%**、音频 **≥ 90%** 连续播放 ≥ 3s；混合负载按 FR-005 默认「可读 + 主媒体」。

### FEAT-004 · 三、能力边界与外部依赖

#### 3.1 本 Feature 对外提供的能力

| 能力 | 消费方 | 边界/约束 | 详细设计位置 |
|------|--------|-----------|--------------|
| 呈现策略矩阵执行 | FEAT-002、FEAT-003 | Owner 定义；消费方仅上报类型与引用 | `interface-design.md` |
| 呈现调用契约（入/出） | FEAT-002、FEAT-003 | 输入：分区 ID、负载类型、可选子类型、内容引用；输出：呈现状态 + 用户说明（FR-007） | `interface-design.md` |
| 统一状态文案 | 用户 | 加载中/无内容/预览失败/播放失败/过大/环境不支持 — JPEG/HEIC 一致（FR-006） | `ux-design.md` |
| 可读↔预览切换 | 用户 | FR-008；不丢失已加载可读摘要 | `epic-design.md` |

#### 3.2 本 Feature 依赖的外部能力

| 依赖能力 | 提供方 | 调用约束 | 失败/降级要求 |
|----------|--------|----------|---------------|
| 负载类型与内容引用 | FEAT-002、FEAT-003 | 引用须会话内有效；空引用 → 「无可用内容」 | 可读/十六进制降级（若提供） |
| 浏览器媒体解码 | 浏览器 | 视频 ≤ 20MB 起播 P95 ≤ 3s；图片 ≤ 5MB 预览 P95 ≤ 2s | 不支持编码 → FR-009 说明 |
| 会话结束清理 | FEAT-001 | 换文件时释放解码缓存（≤3 槽位 LRU） | 无旧图残留（SC-011） |

### FEAT-004 · 四、数据、NFR 与安全硬约束

- **存储形态**：会话内解码缓存（最多 **3** 个全分辨率分区）；无持久化。
- **System of Record**：以消费方提供的会话内引用为准；呈现层不修改源文件。
- **数据生命周期**：换文件/关闭页签 → 释放所有解码缓存与媒体元素。
- **数据规模与增长**：超大图片预览上限在 `nfr.md`/`interface-design` 冻结（默认建议单分区预览解码 **≤ 32MB** 等价像素预算，超出走「过大」+ 降级）；与 spec SC-005 对齐。
- **迁移/回滚约束**：**N/A**。
- **性能/功耗/内存约束**：见 EPIC 表；无交互时持续全速解码 **≤ 5 分钟**（NFR-POWER-001）；单分区呈现失败率 ≤ 5%（不含已知不支持编码样例）。
- **权限/隐私/合规**：本地解码渲染；错误无路径泄露；离线已加载内容仍可呈现（AC-006）。
