# EPIC 规格说明：Web 端图片数据解析器

> **epic.md 纯净度约束（红线）**：本文件与下游各 `spec.md` 同为**需求事实源**（背景/目标/范围、Feature 拆分、跨 Feature 关注点、验收意图）；**禁止**技术实现细节。
>
> 规则全文：`.cursor/rules/aisdd-document-boundaries.mdc`

**EPIC ID**：EPIC-005  
**EPIC Version**：v0.1.4  
**创建时间**：2026-05-22  
**状态**：就绪（可拆分 Feature）  
**输入**：`"开发一款web端的图片数据解析器。支持jpeg格式和heic格式。要求解析出图片格式的不同marker 分区的数据内容，以可读或可看的形式呈现出来。"`；补充：**分区内若为图片数据须预览显示，若为视频数据须可预览播放**。

## 背景、目标与价值 *（必填）*

- **背景**：在影像调试、质量分析、兼容性排查与学习场景中，从业者需要快速理解 JPEG、HEIC 等图片文件内部的结构分区及其承载的数据（如元数据、缩略图、主图像数据等）。现有通用看图工具往往只展示最终画面，难以系统化浏览「文件由哪些分区组成、各分区含义与内容是什么」。
- **目标**：提供一款在浏览器中使用的图片数据解析产品，使用户上传 JPEG 或 HEIC 文件后，能逐级查看文件内各结构分区，并以人类可理解（文本/表格/结构化说明）或可感知（**图片预览、视频可播放预览**）的方式理解分区内容。
- **价值**：
  - 缩短从「拿到异常图片文件」到「定位结构或元数据问题」的时间；
  - 降低学习图片格式内部结构的知识门槛；
  - 为后续测试、排障、培训提供可重复的自助分析入口。
- **产品竞争力**：
  - 同一产品内统一支持 JPEG 与 HEIC 两种常见格式，避免用户在多款工具间切换；
  - 分区树 + 内容多形态呈现（可读 + 图片预览 + 视频播放），兼顾分析与直观验证；
  - 纯 Web 使用路径，无需安装桌面客户端即可开始解析（具体运行环境约束见范围与假设）。
- **技术竞争力**：
  - 面向「结构透明化」的垂直能力，可积累对复杂/非标准文件的解析与友好呈现经验；
  - 为后续扩展更多图片格式建立可复用的「分区解析 + 多形态呈现」产品模式（本期仅 JPEG/HEIC）。
- **成功标准（EPIC Level）**：
  - 目标用户在无额外培训前提下，**90%** 的试点用户能在 **5 分钟内** 完成「上传 JPEG 或 HEIC 文件 → 在分区列表中定位任意一个分区 → 查看该分区可读或可看内容」的完整路径；
  - 对体积 **≤ 20MB** 的常见样例文件，从用户确认开始解析到**首次展示完整分区列表**的时间，**P95 ≤ 10 秒**（在用户网络与设备处于常规办公环境的前提下）；
  - 对 EPIC 范围内约定的标准样例集（含至少各 **10** 个 JPEG、**10** 个 HEIC 样例），**≥ 95%** 能正确列出主要结构分区且分区层级与行业通用说明一致（由产品在 spec 阶段冻结样例清单）；
  - 样例集中标注为「含图片负载」的分区，**≥ 95%** 可在产品内完成**静态预览**；「含视频负载」**≥ 90%** 可**视频播放**；「含音频负载」**≥ 90%** 可**音频播放**；
  - 含 **MakerNote** 的 JPEG/HEIC 样例，**≥ 95%** 达到**字段级**可读；含**深度图/HDR 增益**的 HEIC，**≥ 90%** 可静态预览或明确不支持原因；
  - 试点阶段（见上项节奏）收集的可用性反馈中，与「看不懂分区内容 / 找不到目标分区」相关的阻断性问题占比 **< 10%**。

## 范围 *（必填）*

- **In Scope**：
  - Web 端（浏览器访问）图片数据解析器；
  - 支持用户上传或选择 **JPEG**、**HEIC** 两类文件并触发解析；
  - 解析并展示文件内**结构分区**（JPEG 标记段/数据段、HEIC 容器与图像/视频项——**完整目录见 FEAT-002/003 `spec.md` §解析内容目录**）及其层级关系；
  - 对每个可解析分区，按负载类型提供对应呈现（具体策略矩阵在 FEAT-004 / 各 `spec.md` 冻结）：
    - **非媒体或元数据类**：至少一种**可读**呈现（结构化字段说明、文本化摘要、十六进制辅助阅读等）；
    - **图片类负载**（含缩略图、主图、嵌入图像等）：**必须**提供**静态预览**（可看），并可辅以可读说明；
    - **视频类负载**（含 HEIC 内运动影像、容器内视频轨等）：**必须**提供**可播放预览**（可看），并可辅以可读说明；
    - **音频类负载**（容器内音频轨等）：**必须**提供**可播放预览**（可听），并可辅以可读说明；
    - **辅助图像**（深度图、HDR 增益图、透明蒙版等）：可解码时**必须**静态预览；
    - **EXIF/MakerNote**：**字段级**可读（与 FEAT-002/003 §解析内容目录 一致），不得仅十六进制；
  - 当分区同时含多种负载或无法解码时，须明确提示原因及已提供的降级呈现（见假设与风险）；
  - 分区列表浏览、选中、内容查看的基础交互闭环；
  - 解析失败、文件不符合范围、文件过大等场景下的明确用户提示。
- **Out of Scope**：
  - 以 **JPEG / HEIC 以外格式**作为**主输入文件**的解析（如单独上传 PNG、WebP、RAW、MP4 等）；**不**排除在已上传的 JPEG/HEIC **内部**识别并预览/播放其分区中的图片或视频负载；
  - 在线协作、账号体系、云端历史记录与跨设备同步；
  - 对图片进行编辑、转码、压缩、修复或重新封装并导出为新文件；
  - 批量目录扫描、命令行接口、移动端原生 App；
  - 与第三方云存储的深度集成（本期仅本地文件选择/拖放为主）；
  - 专业级取证鉴定报告、司法鉴定效力文书；
  - 对加密、DRM 保护或需专有密钥才能解读的内容进行破解或绕过。
- **上项范围**：
  - 地区：全球（界面语言首期以中文为主，是否增加其他语言在 Feature spec 中决策）；
  - 销售渠道：不适用（工具型产品，直接面向目标用户发布）；
  - 设备类型：桌面与笔记本浏览器为主；平板浏览器为兼容目标，手机浏览器不保证完整体验；
  - 机型定位：不适用；
  - 运行环境：主流 Chromium、Firefox、Safari 的**最近两个大版本**；HEIC 相关能力以 Safari 及用户常见办公环境为优先验证对象（详见假设）；
  - 保密等级：内部/公开试点（不涉及绝密级客户数据托管）。
- **上项节奏**：
  - **MVP 试点**：先交付 JPEG 解析 + 基础呈现 + 文件接入闭环，邀请影像/测试相关同事试用；
  - **Beta**：补齐 HEIC 解析与呈现，扩大样例覆盖；
  - **GA**：完成 EPIC 完成条件中全部必需 Feature 验收后对外说明可用范围与已知限制。

## 约束与假设 *（必填）*

- **约束**：
  - 产品形态限定为 **Web**，须遵守浏览器对本地文件访问、内存与用户隐私的通用限制；
  - 仅处理用户主动提供的文件；不得在未告知用户的情况下将文件内容发送至外部服务（若未来引入可选云能力，须单独立项并更新范围）；
  - 须遵守适用的数据保护与隐私要求：不上传、不持久化用户文件到服务端（本期）；
  - 单文件大小上限默认 **50MB**（可在 tech-spec 阶段按性能验证调整，但须在 spec 中同步用户可见说明）。
- **假设**：
  - **目标用户**默认为影像相关研发、测试、技术支持及进阶摄影爱好者；若实际以纯 C 端消费者为主，需调整交互简化程度（假设不成立时：重做信息架构与 Feature 优先级）；
  - **HEIC 样例**以常见移动设备拍摄的 `.heic` / `.heif` 为主；极冷门编码变体可能无法完整解析（假设不成立时：在界面标明不支持原因并纳入样例集迭代）；
  - 用户理解「分区 / 段 / 盒子」等行业通用概念，产品可在 UI 中对 JPEG、HEIC 使用一致或格式特定的用户向术语（在 ux-design / spec 中统一）；
  - 浏览器环境足以完成本期解析与呈现（含常见图片预览与声明支持范围内的视频播放），不依赖用户安装额外插件（假设不成立时：评估降级提示或缩小格式/编码支持声明）；
  - 分区内视频多为容器常见编码；极冷门或受 DRM 保护的轨可能无法播放，产品以明确说明替代沉默失败（假设不成立时：扩展样例集与「不支持播放」清单）；
  - 首期不提供解析结果导出为文件；用户通过截图或浏览器自带能力自行留存（假设不成立时：新增「结果导出」Feature 并调整范围）。

## 依赖关系 *（必填）*

- **上游依赖**：
  - 产品/设计提供分区呈现的信息架构原则与样例文件清单；
  - 若需品牌视觉规范，依赖设计资产交付时间；
  - 无强制依赖其他业务系统账号或后端服务（本期）。
- **下游影响**：
  - 可作为影像管线、相册、相机 SDK 等团队的自助排障辅助工具（非阻塞集成）；
  - 培训与文档团队可引用本产品作为「图片文件结构」教学演示。
- **外部依赖故障模式**：
  - 浏览器不支持所选 HEIC 能力 → 用户看到明确说明与建议环境，而非空白或崩溃；
  - 用户提供的文件损坏或截断 → 提示无法完整解析，尽可能展示已识别分区；
  - 分区内视频编码浏览器无法解码 → 展示可读元数据（若有）并说明无法播放原因，不假装播放成功；
  - 分区内图片损坏或过大 → 预览失败时保留可读/十六进制等降级路径（若 spec 允许）；
  - 文件超过大小上限 → 拒绝解析并提示上限与建议处理方式；
  - 用户中途关闭页面 → 解析状态不保留（本期无持久化），再次打开需重新上传。

### Feature 边界说明（每个 Feature 必填）

#### FEAT-001 - 图片接入与解析工作台

- **类型**：Product
- **用户价值**：用户无需其他工具即可完成「选文件 → 知道是否支持 → 开始解析 → 进入分区浏览」的全过程。
- **目标**：提供 Web 端统一工作台，支持 JPEG/HEIC 文件接入、解析触发、整体状态反馈及向格式专属浏览能力的导航。
- **范围（In）**：
  - 文件选择、拖放接入；
  - 文件类型与大小校验及友好错误提示；
  - 解析进度/状态（进行中、成功、失败、部分成功）；
  - 解析完成后进入「分区浏览」视图的导航框架（具体分区树由 FEAT-002/003 提供内容）；
  - 重新选择文件、放弃当前解析。
- **非范围（Out）**：
  - 各格式分区的语义解析规则（归属 FEAT-002/003）；
  - 分区内容的可读/可看渲染细节（归属 FEAT-004）；
  - 用户账号、历史记录列表。
- **依赖**：无；为 FEAT-002、FEAT-003 的前置入口。
- **验收意图**：用户能在典型办公环境下独立完成上传与解析启动；不支持格式与超大文件有明确说明；解析失败不导致页面不可恢复。
- **拆分动机**：入口与格式专属解析解耦，便于 MVP 先交付 JPEG 路径时仍保留统一产品壳。
- **交接给 `/aisdd.featurespec` 的输入**：`统一 Web 工作台：JPEG/HEIC 文件接入、校验、解析状态与导航；In：拖放/选择、大小与类型校验、状态与错误提示；Out：分区语义与内容渲染；依赖：无；NFR：易用性、隐私（用户文件仅本地处理）、失败可恢复。`

#### FEAT-002 - JPEG 分区解析与浏览

- **类型**：Product
- **用户价值**：用户能系统化查看 JPEG 文件由哪些结构分区组成，并逐层选中查看详情。
- **目标**：对 JPEG 文件完成结构分区识别，以层级列表（或等价导航）展示，并与呈现能力联动展示各分区内容。
- **范围（In）**：
  - 识别并列出 JPEG 主要结构分区（含常见应用标记段、图像数据段等，具体清单在 spec 中冻结）；
  - 分区层级、名称/类型标识（用户向描述，非实现层术语堆砌）；
  - 选中分区后向 FEAT-004 提供负载类型（含图片/视频/其他）及内容引用，以触发对应预览或播放；
  - 对无法识别或损坏段落的提示策略。
- **非范围（Out）**：
  - HEIC 容器解析；
  - 修改或重写 JPEG 文件；
  - 非 JPEG 格式。
- **依赖**：FEAT-001（接入与导航）、FEAT-004（内容呈现）。
- **验收意图**：标准样例集上分区列表完整性与层级正确率满足 EPIC 成功标准；用户能定位到指定分区并看到内容。
- **拆分动机**：JPEG 规则独立、可先于 HEIC 交付 MVP，降低 EPIC 首期风险。
- **交接给 `/aisdd.featurespec` 的输入**：`JPEG 结构分区解析与层级浏览；In：分区识别、负载类型判定（图片/视频/其他）、列表/树导航、与呈现联动；Out：HEIC、文件编辑导出；依赖：FEAT-001、FEAT-004；NFR：正确性、≤20MB 样例 P95 性能、损坏文件降级。`

#### FEAT-003 - HEIC 分区解析与浏览

- **类型**：Product
- **用户价值**：用户能像对待 JPEG 一样，系统化查看 HEIC 文件内部结构与各分区内容。
- **目标**：对 HEIC 文件完成容器/图像相关分区识别与层级展示，并联动呈现能力。
- **范围（In）**：
  - 识别并列出 HEIC 主要结构分区（具体清单在 spec 中与样例集对齐）；
  - 分区层级与选中浏览；
  - 向 FEAT-004 提供负载类型（含图片/视频/其他）及内容引用，以触发预览或播放；
  - 浏览器不支持时的明确说明（与 EPIC 假设一致）。
- **非范围（Out）**：
  - JPEG 段解析；
  - 专有 DRM/加密内容破解；
  - 非 HEIC 格式。
- **依赖**：FEAT-001、FEAT-004。
- **验收意图**：在声明支持的浏览器与样例集上，分区浏览路径与 JPEG 体验一致；不支持环境有清晰指引。
- **拆分动机**：HEIC 兼容性风险高，独立 Feature 便于分阶段发布与验收。
- **交接给 `/aisdd.featurespec` 的输入**：`HEIC 结构分区解析与层级浏览；In：分区识别、负载类型判定（含运动影像/视频轨）、导航、呈现联动、不支持环境提示；Out：JPEG、编辑导出；依赖：FEAT-001、FEAT-004；NFR：正确性、浏览器兼容矩阵、视频播放兼容。`

#### FEAT-004 - 分区内容多形态呈现

- **类型**：Capability
- **用户价值**：无论 JPEG 还是 HEIC，用户查看某一分区时都能获得一致的「读得懂 / 图看得见 / 片播得出」体验。
- **目标**：根据分区**负载类型**自动选择呈现方式：**图片负载 → 静态预览**；**视频负载 → 可播放预览**；**其余 → 可读呈现**（可组合）；并定义统一交互（视图切换、播放控制、复制摘要等是否在 spec 中决策）。
- **范围（In）**：
  - **呈现策略矩阵**（Owner 定义，消费方遵守）：
    - 判定为**图片数据**的分区：**必须**展示静态预览；可选叠加结构化可读说明；
    - 判定为**视频数据**的分区：**必须**提供可播放预览（含基础播放控制是否在 spec 中列明）；可选叠加轨/时长等可读说明；
    - 判定为**文本/元数据/未知二进制**等：以可读呈现为主；未知且过大时提示而非强行预览；
  - **图片预览**：缩放适配、加载失败提示、过大负载降级；
  - **视频播放**：起播、暂停、进度与时长展示（是否在首期全部纳入由 spec 决策）、无法解码时的明确说明；
  - 通用交互：加载中、无内容、不支持预览/播放、过大负载的提示；
  - 供 FEAT-002、FEAT-003 调用的统一呈现入口（业务契约在 spec/plan 定义，不在本 epic 写实现）。
- **非范围（Out）**：
  - 各格式分区识别与树构建；
  - 文件上传与全局导航壳。
- **依赖**：无硬上游；作为 Owner 应先于消费方完成 spec/plan 契约。
- **验收意图**：样例集中图片分区 **100%** 触发预览路径（失败须可归因提示）；视频分区在支持环境下 **≥ 90%** 可完成起播并播放 **≥ 3 秒**；JPEG 与 HEIC 在预览/播放交互口径上一致。
- **拆分动机**：被 2 个及以上 Feature 复用，且需独立版本化呈现规则与验收。
- **交接给 `/aisdd.featurespec` 的输入**：`跨格式分区内容呈现；In：负载类型判定、图片必预览、视频必可播、可读降级与统一错误提示、供格式 Feature 调用的契约；Out：格式解析与上传；依赖：无（Owner 先行）；NFR：一致性、预览/播放性能、浏览器播放兼容与降级。`
