## 背景与价值 *（必填）*

| 项 | 内容 |
|---|---|
| 背景 | JPEG 文件由多个结构分区（标记段/数据段等）组成；用户需要逐级查看各分区含义与内容，而非仅看最终图像。 |
| 目标 | 对已由工作台接入的 JPEG 文件完成结构分区识别与层级展示，并向呈现能力上报负载类型与内容引用。 |
| 价值 | 用户能系统化理解 JPEG 构成，定位元数据、缩略图、主图等问题分区。 |
| In Scope | JPEG 结构分区识别（见 §解析内容目录，尽量完整）；层级列表/树导航；选中分区；负载类型判定；调用 FEAT-004；无法识别/损坏段提示。 |
| Out of Scope | HEIC 解析（FEAT-003）；文件接入壳（FEAT-001）；呈现渲染实现（FEAT-004）；编辑/导出 JPEG。 |

## 解析内容目录 *（必填，验收基准）*

> **说明**：本目录定义「必须解析并展示」的 JPEG 结构分区范围。表中**行业标识**为影像领域通用称呼，便于与规范对照；**用户向名称**为产品界面展示用语。  
> **优先级**：**P0**＝GA 必达；**P1**＝完整版必达（**验收覆盖率 ≥ 95%**，未达标须列入已知限制）；**P2**＝尽力识别。  
> **呈现**列对齐 FEAT-004：可读 / 图片预览 / 视频播放 / 可读+预览 / 可读+播放 / 可读+十六进制辅助。

### 目录总规则

- 文件中**每出现一个可独立定界的标记段/数据段**，均须在分区列表中有对应节点（未知段归入「未识别/自定义段」类，见 PAR-JPEG-099）。
- **顺序**：分区列表须按在文件中的**出现顺序**排列；同一父段下的子结构（如 EXIF 内 IFD）在 P1 阶段以**可展开子节点**展示。
- **负载判定**：每节点须映射为一种负载类型（图片 / 视频 / 文本·元数据 / 其他·二进制），并触发 §呈现 列要求。

## FR / NFR *（必填）*

### FR（Functional Requirements）

- **FR-001**：系统**必须**对当前会话中的 JPEG 主文件构建**层级分区列表**（或等价树形导航），用户能展开/折叠层级。
- **FR-002**：系统**必须**按 §解析内容目录 识别并列出分区：**P0 目录项 100%**；**P1 目录项 ≥ 95%** 或落入 §已知限制；未识别段归入 PAR-JPEG-099。
- **FR-009**：对 PAR-JPEG-004/005 的 EXIF 结构，系统**必须**展开 **IFD0、Exif IFD、GPS IFD（若存在）、Interop IFD（若存在）**；每个标准字段以**人类可读的字段名与取值**展示（PAR-JPEG-C06）；缩略图（PAR-JPEG-025）**必须**与主 IFD 区分。
- **FR-010**：对 PAR-JPEG-019 多图对象，系统**必须**为每一帧提供独立列表节点及图片预览路径。
- **FR-011**：对 PAR-JPEG-026 / PAR-JPEG-C03 MakerNote，系统**必须**按 §MakerNote 厂商字段级要求 输出字段级可读内容；对 P1 列表内厂商在对应样例中 **≥ 95%** 字段可解析；未知厂商走 LIM-JPEG-05。
- **FR-012**：对 PAR-JPEG-022 IPTC，系统**必须**解析并展示新闻元数据常见字段（标题、说明、关键词、版权、署名等），不得仅显示原始二进制摘要。
- **FR-003**：用户选中任一分区时，系统**必须**判定负载类型（**图片** / **视频** / **音频** / **文本·元数据** / **其他**）并调用 FEAT-004；MakerNote/EXIF/IPTC 为文本·元数据；嵌入音轨（若存在）为音频。
- **FR-004**：对负载类型为「图片」的分区，系统**必须**向 FEAT-004 提供可用于静态预览的内容引用；不得仅展示十六进制而无预览路径（除非预览失败走 FEAT-004 降级）。
- **FR-005**：对负载类型为「视频」的分区（如 Motion JPEG 等样例中存在的少数情况），系统**必须**按视频路径调用 FEAT-004；无视频负载的常规 JPEG 样例可不触发本 FR。
- **FR-006**：对无法识别、长度异常或校验失败的段，系统**必须**在列表中标注警告状态，并允许用户查看可读说明（若可提取）或错误原因。
- **FR-007**：分区列表**必须**展示用户可理解的类型标识与在文件中的顺序/偏移摘要（偏移是否展示由产品冻结，至少要有稳定排序）。
- **FR-008**：解析完成后，系统**必须**向 FEAT-001 回传解析结果状态：成功 / 部分成功 / 失败，并附简要原因（供工作台展示）。

### NFR（Non-Functional Requirements）

- **NFR-PERF-001**：对 ≤ **20MB** 标准 JPEG 样例，从工作台触发解析到分区列表首次完整渲染，**P95 ≤ 10 秒**（与 EPIC 一致）。
- **NFR-PERF-002**：用户选中另一分区后，列表选中态更新与呈现触发 **P95 ≤ 500ms**（不含 FEAT-004 媒体解码时间）。
- **NFR-POWER-001**：**N/A**——Web 端；解析过程须支持用户取消（与 FEAT-001 FR-009 联动）。
- **NFR-MEM-001**：解析 ≤ **20MB** JPEG 时，本 Feature 额外内存峰值 **≤ 150MB**（相对解析前基线，常规设备）。
- **NFR-SEC-001**：分区原始字节**不得**传出浏览器会话；向 FEAT-004 传递的引用须限于会话内安全边界。
- **NFR-OBS-001**：部分成功与失败**必须**区分统计；测试可核对失败样例 ID 列表。
- **NFR-REL-001**：标准样例集（≥ **10** 个 JPEG）分区列表主要层级正确率 **≥ 95%**（与 EPIC 一致）；损坏样例 **100%** 不导致工作台崩溃。

## AC（验收标准）*（必填）*

- **AC-001**：S-JPEG-01～02 上 **100%** 满足全部 P0 目录项；完整样例集（≥20）对 P0 **100%**、对 P1 **≥ 95%**（引用 FR-002、§解析内容目录）。
- **AC-007**：S-JPEG-03 含 GPS 时 GPS 子节点可读；S-JPEG-08 动态 JPEG 可播放或命中 LIM 说明（引用 FR-009、FR-010、PAR-JPEG-024）。
- **AC-008**：S-JPEG-11～13 对应厂商 MakerNote **≥ 95%** 标准字段以字段名+取值展示（引用 FR-011、§MakerNote）。
- **AC-009**：S-JPEG-15 IPTC 常见字段可读（引用 FR-012）。
- **AC-002**：样例集中所有「图片负载」分区 **100%** 触发 FEAT-004 预览路径（引用 FR-003、 FR-004）。
- **AC-003**：用户能在 **2 分钟**内从列表定位到指定「应用标记段」并看到可读内容（可用性试点，引用 FR-001、FR-003）。
- **AC-004**：损坏 JPEG **100%** 返回部分成功或失败+原因，且 FEAT-001 状态正确（引用 FR-006、FR-008）。
- **AC-005**：与 FEAT-004 契约字段满足 **100%** 契约测试用例（引用 FR-003、FEAT-004 FR-007）。
