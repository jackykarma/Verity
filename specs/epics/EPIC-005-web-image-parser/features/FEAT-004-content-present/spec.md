## 背景与价值 *（必填）*

| 项 | 内容 |
|---|---|
| 背景 | JPEG/HEIC 分区内容形态多样（元数据、嵌入图、视频轨等），若各格式 Feature 各自定义呈现规则，用户在不同格式间体验割裂，验收口径不一致。 |
| 目标 | 提供统一的跨格式分区内容呈现能力：按负载类型自动选择可读、图片静态预览或视频可播放预览，并统一错误与降级语义。 |
| 价值 | 用户在任何格式下查看分区时获得一致的「读得懂 / 图看得见 / 片播得出」体验；消费方 Feature 只需上报负载类型与内容引用。 |
| In Scope | 呈现策略矩阵；图片静态预览；视频/音频可播放预览；可读呈现（含结构化字段、十六进制辅助）；深度/辅助图预览；加载/失败/过大/不支持等统一提示；供 FEAT-002/003 调用的呈现契约。 |
| Out of Scope | 文件上传与全局工作台壳（FEAT-001）；各格式分区树构建与语义解析（FEAT-002/003）；编辑/导出文件；账号与云端持久化。 |

## FR / NFR *（必填）*

### FR（Functional Requirements）

- **FR-001**：系统须维护并执行**呈现策略矩阵**：**图片**→静态预览；**视频**→可播放预览（画面）；**音频**→可播放预览（声音，含起播/暂停/进度/音量或静音能力）；**文本/元数据**→可读为主；**其他/未知**→可读+十六进制辅助；**混合**→按 FR-005。
- **FR-010**：当消费方上报负载类型为「音频」且提供有效内容引用时，系统**必须**提供可播放预览；用户**必须**能够起播、暂停并查看进度与总时长（若可获取）；**不得**仅展示十六进制或元数据摘要代替播放（除非播放失败走 FR-009 同类降级）。
- **FR-011**：当消费方为**深度图、透明度蒙版、HDR 增益图**等辅助图像（消费方标注子类型）时，系统**必须**在可解码时提供静态预览（允许灰度/伪彩等等价可视化）；不可解码时**必须**可读说明子类型与失败原因。
- **FR-002**：当消费方上报负载类型为「图片」且提供有效内容引用时，系统**必须**展示静态预览；用户须能辨识预览内容与分区对应关系。
- **FR-003**：当消费方上报负载类型为「视频」且提供有效内容引用时，系统**必须**提供可播放预览；用户**必须**能够完成起播、暂停，并查看当前进度与总时长（若时长可获取）。
- **FR-004**：对非图片/视频类负载，系统**必须**提供至少一种可读呈现（结构化字段说明、文本摘要和/或十六进制辅助阅读，具体组合在验收样例中冻结）。
- **FR-005**：当同一分区消费方标注「混合负载」时，系统**必须**按矩阵优先级呈现（默认：可同时提供可读摘要 + 主媒体预览/播放；具体优先级在样例验收表中列明）。
- **FR-006**：系统**必须**对以下状态给出统一、可理解的提示文案（口径一致，不随 JPEG/HEIC 变化）：内容加载中、无可用内容、预览失败、播放失败、负载过大无法完整展示、浏览器/环境不支持播放。
- **FR-007**：系统**必须**向消费方 Feature 暴露稳定的呈现调用契约：输入至少包含「分区标识、负载类型（图片/视频/音频/文本元数据/其他/混合）、可选子类型（如深度图/HDR 增益/MakerNote 字段组）、内容引用」；输出至少包含「呈现结果状态及用户可见说明」。
- **FR-008**：用户**必须**能在可读视图与预览/播放视图之间切换（当分区同时支持多种呈现时）；切换不得丢失已加载的可读摘要（若已加载成功）。
- **FR-009**：当视频或音频无法播放时，系统**不得**假装播放成功；**必须**说明无法播放原因，并在消费方提供时展示可读元数据（时长、编码类型等用户向字段）。

### NFR（Non-Functional Requirements）

- **NFR-PERF-001**：对体积 ≤ 5MB 的图片负载，从消费方触发呈现到首屏可见预览，**P95 ≤ 2 秒**（常规办公环境、单文件解析会话内）。
- **NFR-PERF-002**：对体积 ≤ 20MB 的视频负载，从用户触发播放到起播（首帧可感知），**P95 ≤ 3 秒**（在声明支持的浏览器与样例编码范围内）。
- **NFR-POWER-001**：**N/A**——Web 浏览器端工具无独立应用电量计量；须避免无用户交互时持续全速解码预览超过 **5 分钟**（与 NFR-REL-001 联动，支持用户取消或切换分区）。
- **NFR-MEM-001**：单次呈现会话中，同时为可见区域维持的「全分辨率解码缓存」不超过 **3** 个分区；超出时须释放最早未查看分区的解码缓存，且不影响当前选中分区操作。
- **NFR-SEC-001**：呈现过程**不得**将分区原始内容上传至外部服务；所有解码与渲染在用户当前浏览器会话内完成；错误提示**不得**泄露用户本地文件路径等敏感信息。
- **NFR-OBS-001**：呈现失败（预览失败、播放失败、不支持）**必须**可被测试复现并记录：至少包含失败类型、负载类型、分区标识（不含文件系统路径）；不要求对接第三方分析平台（本期）。
- **NFR-REL-001**：呈现模块失败**不得**导致整个解析工作台不可用；用户**必须**能切换其他分区或重新选择文件；单分区呈现失败率（标准样例集）**≤ 5%**（不含已知不支持编码样例）。

## AC（验收标准）*（必填）*

- **AC-001**：标准样例集中所有标注「图片负载」的分区，**100%** 进入静态预览路径；失败样例**100%** 显示可归因的失败说明（引用 FR-002、FR-006、NFR-REL-001）。
- **AC-002**：标准样例集中标注「视频负载」且在支持环境内的分区，**≥ 90%** 可起播并连续播放 **≥ 3 秒**；不支持样例**100%** 显示无法播放原因（引用 FR-003、FR-009、NFR-PERF-002）。
- **AC-008**：含音频轨样例（≥ **3** 个）在支持环境内 **≥ 90%** 可起播并连续播放 **≥ 3 秒**（引用 FR-010）。
- **AC-009**：含深度图/人像模式辅助图样例（≥ **3** 个）**≥ 90%** 可静态预览或明确 LIM 说明（引用 FR-011）。
- **AC-003**：JPEG 与 HEIC 消费方各至少 **5** 个分区场景下，相同负载类型的提示文案与交互能力一致（引用 FR-006、FR-007）。
- **AC-004**：混合负载样例（≥ **3** 个）同时满足可读摘要与主媒体呈现策略（引用 FR-005、FR-008）。
- **AC-005**：内存约束下连续查看 **10** 个含大图分区，当前选中分区预览仍可用，且先前分区可重新加载（引用 NFR-MEM-001）。
- **AC-006**：网络断开或飞行模式下（文件已本地加载），已缓存分区的可读/预览仍可用；不得因无网络阻止本地呈现（引用 NFR-SEC-001）。
