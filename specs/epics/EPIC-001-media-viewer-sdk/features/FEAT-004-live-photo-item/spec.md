## 背景与价值 *（必填）*

- **背景**：现代 Android 设备（Pixel 系列等）拍摄的实况图（Google Motion Photo）以 JPEG 内嵌视频片段的形式存储。接入方的媒体浏览器需要在浏览实况图时提供动效预览能力，但目前 SDK 缺乏对该格式的封装支持，接入方需自行处理解析、播放和降级逻辑，成本高且质量参差不齐。
- **目标**：SDK 提供开箱即用的实况图 Item 类型，支持静态封面默认展示、长���触发动效播放、松手恢复静态，并提供扩展接口以支持三星等非 Google 标准格式；接入方零成本接入实况图浏览能力。
- **价值**：
  - 用户浏览实况图时无缝体验动效内容，不感知格式差异；
  - 接入方通过注入解析器即可扩展非��格式支持，无需 fork SDK；
  - SDK 统一兜底降级逻辑，确保任意损坏格式下不崩溃。
- **范围（In Scope）**：
  - 实况图（olive）作为独立 Item 类型集成到 Pager；
  - 默认以封面帧（静态图片）展示；
  - 用户长按实况图区域，SDK 提取内嵌视频片段并触发播放；
  - 用户松手，停止播放，恢复静态封面��显示；
  - SDK 内置支持 Google Motion Photo（JPEG + 内嵌视频片段，通过 XMP 元数据标记）；
  - 接入方可实现并注入 `MotionPhotoParser` 接口，以支持三星 Moving Photo / 苹果 Live Photo 等非 Google 标准格式；SDK 优先使用注入的解析器，未注入则回退到内置实现；
  - 内嵌视频损坏/格式解析失败时，降级为纯静态图片显示，不崩溃；
  - 长按实况图区域不触发 `onTapOutsideMedia` 沉浸式回调；
  - 实况图标识 icon 由接入方自定义，SDK 不提供默认标识。
- **范围外（Out of Scope）**：
  - 实况图标识 icon 的内置实现（由接入方提供）；
  - 非 Google 标准格式的内置支持（通过 `MotionPhotoParser` 扩展接口由接入方实现）；
  - 实况图的旋转手势支持。

## 依赖关系 *（必填）*

- **上游依赖**：
  - FEAT-002（Pager 容器）：实况图 Item 作为独立 Item 类型挂载到 Pager，依赖 Pager 提供的 Item 注册、生命周期回调（进入/离开视口）与手势协调机制；
  - FEAT-001（图片浏览能力）：封面帧静态展示复用图片 Item 的加载与渲染能力，依赖其提供的缩放/平移手势基础。
- **下游影响**：
  - 接入方：调用 `MotionPhotoParser` 接口扩展非标格式解析；
  - FEAT-002 Pager：新增 Item 类型后需确保 Pager 页面回收与复用逻辑不受影响。
- **外部依赖故障模式**：
  - FEAT-002 Pager 生命周期回调未触发（如快速翻页）：播放资源需在 Item 离屏时自行释放，不依赖回调触发才能清理；
  - FEAT-001 图片加载失败：封面帧降级为空白占位，不影响实况图整体交互流程。

## 验收与场景 *（必填）*

> 说明：本节用于"可测试"的需求验收；**不等同于技术 Story**（技术 Story 在 Plan 阶段拆分）。

### 核心用户旅程（可选但强烈建议）

#### 旅程 1 - 正常实况图长按播放

- **描述**：用户在媒体列表中翻页至一张实况图，看到静态封面后长按，触发动效片段播放，松手后恢复静态封面。
- **成功信号**：用户能流畅地在静态与动态之间切换，长按有明确的视觉反馈（动效开始播放），松手后画面回归静态。
- **验收场景**：
  1. **前提** 实况图 Item 进入视口且封面帧已加载，**当** 用户对实况图区域执行长按手势，**则** SDK 提取内嵌视频片段并开始播放动效，封面帧被视频画面替代。
  2. **前提** 实况图 Item 正在播放动效，**当** 用户松开手指，**则** 动效停止播放，画面切换回封面帧静态显示。
  3. **前提** 实况图 Item 正在播放动效，**当** 用户松手后再次长按，**则** 动效从头开始重新播放。

#### 旅程 2 - 内嵌视频损坏降级

- **描述**：用户浏览一张内嵌视频片段已损坏的实况图，SDK 检测到解析/解码失败，自动降级为纯静态图片展示，用户无感知异常，不发生崩溃。
- **成功信号**：应用不崩溃，封面帧正常显示，长按后无异常弹窗或黑屏。
- **验收场景**：
  1. **前提** 内嵌视频字节流损坏（文件截断或编码错误），**当** 实况图 Item 进入视口，**则** SDK 完成降级，以静态图片模式渲染该 Item，不崩溃。
  2. **前提** 实况图 Item 已降级为静态图片模式，**当** 用户对该 Item 执行长按手势，**则** 长按无动效响应，Item 保持静态显示，不崩溃。
  3. **前提** XMP 元数据缺失（无法定位内嵌视频偏移量），**当** SDK 尝试提取内嵌视频，**则** 解析失败，Item 降级为静态显示，不崩溃，日志输出降级原因。

### 边界与异常场景（必填）

- **XMP 元数据缺失**：无法定位内嵌视频片段偏移量 → Item 静默降级为静态图片，日志记录 `MotionPhotoParser` 解析失败原因，不向上抛出异常。
- **内嵌视频字节流损坏**：解码器抛出异常 → SDK 捕获异常，Item 降级为静态显示，播放状态重置为 `STATIC`，不崩溃。
- **快速翻页时长按**：用户在快速翻页过程中对实况图 Item 执行长按 → Item 离屏时立即停止播放并释放解码资源；下次进入视口重新以静态封面显示，不发生资源泄漏。
- **注入自定义解析器抛出异常**：接入方注入的 `MotionPhotoParser` 实现抛出任意异常 → SDK 捕获后对 Google Motion Photo 格式回退内置实现，对未知格式降级静态显示，不崩溃。
- **长按期间触发沉浸模式切换**：实况图 Item 上长按手势 → 不触发 `onTapOutsideMedia` 回调，沉浸模式状态不变。
- **双指旋转手势**：在实况图 Item 上触发双指旋转手势 → 手势被拦截，不执行旋转，不崩溃，其余手势（缩放/平移）正常工作。
- **内嵌视频播放完毕仍长按中**：动效片段播放至末尾且用户仍长按 → 视频循环播放（具体策略在 Plan 阶段确认），不崩溃，松手后恢复封面帧。
- **接入方未注入解析器且文件为非 Google 格式**：内置解析器无法识别格式 → Item 降级为静态显示，日志记录格式不支持原因。

## FR / NFR *（必填）*

### FR（Functional Requirements）

> 规则：每条 FR 必须**可测试**，避免"提升体验/更快/更稳定"这类不可验证表述。

- **FR-001**：实况图 Item 进入视口后必须以封面帧（静态图片）默认展示，不自动播放动效。
- **FR-002**：用户对实况图 Item 区域执行长按手势时，SDK 必须提取内嵌视频片段并开始播放动效；用户松手后必须停止播放并恢复封面帧静态显示。
- **FR-003**：SDK 必须内置支持 Google Motion Photo 格式（JPEG + 内嵌视频片段，通过 XMP 元数据标记）的解析与播放，不需要接入方注入任何解析器即可工作。
- **FR-004**：SDK 必须提供 `MotionPhotoParser` 接口，接入方可注入自定义实现；注入后 SDK 优先使用注入的解析器；未注入时回退内置实现。
- **FR-005**：当内嵌视频损坏或格式解析失败时，SDK 必须将该实况图 Item 降级为纯静态图片展示，不崩溃，不向���抛出未处理异常。
- **FR-006**：实况图 Item 上的长按手势必须不触发 `onTapOutsideMedia` 沉浸式回调。
- **FR-007**：实况图 Item 上的双指旋转手势必须被拦截，不执行旋转，不崩溃。
- **FR-008**：实况图标识 icon 的显示由接入方负责；SDK 不提供默认标识，也不干预接入方标识的渲染。
- **FR-009**：实况图 Item 离屏（Pager 切走或应用切后台）时，SDK 必须立即停止播放并释放内嵌视频解码资源。

### NFR（Non-Functional Requirements）

> 规则：每条 NFR 必须**量化**并附带验收方式；细化评估在 Plan 阶段完成。

#### 性能（Performance）

- **NFR-PERF-001**：用户长按后，从手势确认长按到动效开始播放第一帧的响应时间，在内嵌视频已缓存至内存的情况下，p95 ≤ 300 ms（在主流中端设备 Pixel 6a / Samsung A54 上测量）。验收方式：插桩日志记录长按确认时间戳与第一帧渲染时间戳，压测 50 次取 p95。
- **NFR-PERF-002**：用户松手后恢复静态封面帧的渲染时间 p95 ≤ 100 ms。验收方式：插桩日志记录松手时间戳与封面帧重新渲染完成时间戳，压测 50 次取 p95。

#### 功耗（Power）

- **NFR-POWER-001**：实况图动效播放功耗仅由内嵌视频解码引起，SDK 不在长按播放期间发起任何额外网络请求、后台任务或持有 WakeLock；实况图 Item 离屏后解码器立即释放，不引起任何后台功耗。验收方式：使用 Android Battery Historian 在连续长按播放 30 秒场景下抓取耗电分布，确认无 SDK 相关后台 WakeLock 记录。

#### 内存（Memory）

- **NFR-MEM-001**：实况图 Item 离屏后，内嵌视频解码器及其关联缓冲区必须在 500 ms 内完成释放；单个实况图 Item 播放期间解码器占用的堆内存增量不超过 50 MB（以典型 3 秒 1080p 内嵌片段为基准）。验收方式：Android Studio Memory Profiler 抓取 Item 进出视口前后堆快照，对比增量，确认离屏 500 ms 后无残留解码器引用。

#### 安全与隐私（Security/Privacy）

- **NFR-SEC-001**：实况图（含内嵌视频片段）的数据仅在本地设备内读取与解码，SDK 不将任何实况图数据、元数据或播放行为上传至网络；接入方注入的 `MotionPhotoParser` 实现由接入方自行负责其数据安全，SDK 不对注入实现的网络行为负责。验收方式：代码审计 + 网络抓包（Charles/tcpdump）���认 SDK 代码路径无出网行为。

#### 可观测性（Observability）

- **NFR-OBS-001**：以下事件必须输出结构化日志（Debug 级别），日志 tag 统一为 `MediaViewerSDK/LivePhoto`：
  - 内嵌视频解析成功（含格式类型、解析耗时）；
  - 内嵌视频解析失败（含失败原因：XMP 缺失 / 字节流损坏 / 格式不支持）；
  - Item 降级为静态模式（含触发原因）；
  - 注入解析器调用成功/失败（含解析器类名）；
  - 播放开始（含长按确认时间戳）；
  - 播放停止（含停止原因：松手 / 离屏 / 解码错误）；
  - 离屏资源释放完成（含释放耗时）。

  验收方式：在 Logcat 过滤 `MediaViewerSDK/LivePhoto` tag，覆盖以上所有场景均有对应日志输出。

#### 可靠性（Reliability）

- **NFR-REL-001**：在 100 次连续快速翻页（每次停留 < 100 ms）场景中，包含实况图 Item 的 Pager 不发生崩溃，且内存无持续增长（100 次翻页后 HeapSize 回归基准 ±10%）。验收方式：自动化 UI 测试模拟 100 次快速翻页，结合 Memory Profiler 观察堆内存曲线。
- **NFR-REL-002**：注入的 `MotionPhotoParser` 实��抛出任意异常（含 `RuntimeException`、`OutOfMemoryError` 等）时，SDK 必须捕获并执行降级逻辑，不将异常传播至接入方 UI 层导致崩溃。验收方式：注入一个总是抛出 `RuntimeException` 的 Mock 解析器，执行长按操作，验证应用不崩溃且 Item 降级为静态显示。

## 核心实体（如涉及数据则必填）

- **LivePhotoSource**：实况图数据源实体，表示一张实况图的完整信息。核心属性：封面帧 URI/Bitmap（用于静态展示）、原始文件 URI（供解析器提取内嵌视频）、格式标识（Google Motion Photo / 自定义扩展格式）。关系：作为 Pager Item 的数据载体，由接入方构造并传入 SDK；`MotionPhotoParser` 消费其原始文件数据���产出可播放的 `VideoSegment`。
- **MotionPhotoParser**（接口）：实况图解析器接口，定义从原始文件中提取内嵌视频片段的契约。核心方法：`parse(source: LivePhotoSource): VideoSegment?`（返回可播放视频片段描述，解析失败返回 `null` 或抛出异常；SDK 均安全处理）。关系：SDK 持有该接口引用；接入方可注入自定义实现以扩展非标格式支持；SDK 内置 `GoogleMotionPhotoParser` 为默认实现，未注入时自动使用。
- **VideoSegment**：从实况图中提取出的可播放视频片段描述。核心属性：视频数据来源（字节数组或文件偏移量+长度）、MIME 类型（如 `video/mp4`）。关系：由 `MotionPhotoParser` 产出，交由 SDK 内部播放器（`MediaExtractor`/`MediaCodec`）消费；播放结束后由 SDK 负责释放相关资源。

## 假设与约束 *（必填）*

- **假设**：
  - Google Motion Photo 格式（XMP 元数据标记内嵌视频）在 SDK 支持的目标设备范围内保持稳定，不发生破坏性格式变更；若格式变更，内置解析器可通过 SDK 版本升级适配，已有 `MotionPhotoParser` 接口契约不受影响。
  - 接入方提供的 `LivePhotoSource` 中的文件 URI 在 Item 存活期间可访问；若 URI 在播放过程中失效，降级行为与内嵌视频损坏一致（静态显示）。
  - 接入方注入的 `MotionPhotoParser` 实现可在后台线程中调用（即线程安全）；若实现非线程安全，可能引发竞态，但 SDK 不对注入实现的线程安全性负责。
- **约束**：
  - 最低支持 Android 8.0（API 24），内置视频解码依赖 `MediaExtractor` + `MediaCodec`，API 24 起可用；
  - 目标 Android 15（API 35），需确保 `MediaCodec` 使用方式与最新 API 兼容；
  - 实况图旋转手势明确不支持（Out of Scope）；
  - SDK 不持有实况图文件的永久引用，所有文件访问在解码完成后释放；
  - 实况图 Item 不支持旋转，接入方不应在 `LivePhotoSource` 中提供旋转角度参数期望 SDK 处理。
