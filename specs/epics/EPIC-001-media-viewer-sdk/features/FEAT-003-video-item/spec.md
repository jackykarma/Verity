# Feature 规格说明：视频 Item 播放

**Epic**：EPIC-001 - Android 媒体浏览 SDK
**Feature 类型**：Product Feature
**Feature ID**：FEAT-003
**Feature Version**：v0.1.0
**EPIC 分支**：`epic/EPIC-001-media-viewer-sdk`
**Feature 目录**：`specs/epics/EPIC-001-media-viewer-sdk/features/FEAT-003-video-item/`
**创建时间**：2026-03-22
**状态**：草稿
**输入**：用户描述：`"视频 Item 播放"`

---

## 背景与价值

- **背景**：媒体浏览 SDK 需要支持视频类媒体 Item 的展示与播放能力。接入方（App 开发者）目前需要为每个业务场景重复开发视频容器、生命周期管理、手势处理等基础设施，造成大量重复建设。
- **目标**：SDK 提供完整的视频 Item 生命周期托管（封面显示、进出视口触发播放/暂停、后台暂停、手势支持），并通过抽象接口让接入方注入自有播放器，解耦 SDK 与具体播放框架。
- **价值**：
  - 用户：视频封面即时展示、播放流畅无黑屏、手势自然；
  - 接入方：无需重复开发视频容器，只需实现 SDK 定义的播放器接口并注入即可；
  - 平台：统一生命周期管理策略（单播、后台暂停），降低因多播导致的崩溃和资源泄漏风险。
- **范围（In Scope）**：
  - 视频 Item 进入视口后显示封面/首帧；
  - 支持自动播放模式（进入视口即播）和手动播放模式（等待外部触发），全局配置，不支持 per-item 级别切换；
  - 离页（滑动翻页离开该 Item）时 SDK 通知播放器暂停；
  - App 进入后台时 SDK 通知播放器暂停，返回前台不自动恢复；
  - 同一时刻最多一个视频处于播放状态（单播策略）；
  - 视频 Item 支持双指捏合缩放（放大/缩小）和单指平移手势；
  - 视频控制栏 UI 完全由接入方定义，SDK 不提供默认控制栏；
  - 播放框架通过抽象接口注入，SDK 不内置播放器；
  - 视频数据源支持：本地文件路径、ContentResolver URI、网络 URL；
  - 播放状态通过 FEAT-009 事件回调系统发布（首帧就绪、播放/暂停/结束/错误、音量/静音）。
- **范围外（Out of Scope）**：
  - 视频控制栏 UI（由接入方实现）；
  - 视频格式兼容性校验（由接入方注入的播放器决定）；
  - 实况图内嵌视频解码（在 FEAT-004）；
  - DRM、字幕、流媒体协议（HLS/DASH 等）的解析与处理；
  - per-item 级别的播放模式配置。

## 依赖关系

- **上游依赖**：
  - `FEAT-002`（Pager 容器）：提供 Item 进入/离开视口的生命周期回调，SDK 据此触发播放/暂停逻辑；
  - `FEAT-009`（事件回调系统）：视频播放状态变更事件（首帧就绪、播放/暂停/结束/错误等）通过该系统向接入方发布；
  - 接入方（App）：必须提供实现 SDK `VideoPlayerController` 抽象接口的播放器实例并在初始化时注入，否则视频 Item 无法播放（封面仍可展示）。
- **下游影响**：
  - 接入方的视频控制 UI 依赖 FEAT-009 事件回调感知播放状态；
  - FEAT-002 的 Item 生命周期调度逻辑需要感知当前是否有视频正在播放（单播策略）。
- **外部依赖故障模式**：
  - FEAT-002 未就绪：视频 Item 的进出视口回调无法触发，自动播放无法工作；Feature 可降级为仅展示封面，待 FEAT-002 就绪后联调；
  - FEAT-009 未就绪：播放状态无法回调至接入方，接入方控制 UI 无法感知状态；Feature 内部逻辑可先实现，状态发布接口预留桩；
  - 接入方未注入播放器：SDK 检测到无 `VideoPlayerController` 实现时，视频 Item 以"仅封面"模式展示，不崩溃，不抛出未捕获异常；
  - 网络 URL 不可达或本地文件不存在：SDK 通过 FEAT-009 发布 `VideoError` 事件，封面持续展示，不黑屏。

> 本 Feature 依赖 FEAT-009（事件回调系统）作为横切能力 Feature。视频播放状态的回调口径（事件类型、数据字段）在 FEAT-009 中定义，本 Feature 只描述"需要哪些事件"，不重复定义事件结构。

## 验收与场景

> 说明：本节用于"可测试"的需求验收；**不等同于技术 Story**（技术 Story 在 Plan 阶段拆分）。

### 核心用户旅程

#### 旅程 1 - 自动播放模式下浏览视频

- **描述**：用户在媒体列表（Pager）中滑动浏览，当视频 Item 滑入视口时，封面瞬间可见，随后视频自动开始播放；用户继续滑动离开该 Item 后视频自动暂停。
- **成功信号**：用户无需任何额外操作即可看到视频播放，离开后无声音/画面残留。
- **验收场景**：
  1. **前提** SDK 配置为自动播放模式，视频 Item 携带有效封面图与本地视频文件路径，**当** 用户将该 Item 滑入视口（Item 完全可见），**则** 封面图立即展示且视频在 2 秒内自动开始播放，播放期间不出现黑屏帧。
  2. **前提** 视频正在播放，**当** 用户将该 Item 滑出视口（完全不可见），**则** SDK 通知播放器暂停，视频停止播放，封面恢复展示。
  3. **前提** 视频正在播放，**当** 用户快速连续滑过多个视频 Item（每个停留不足 500ms），**则** 各 Item 均不自动播放（未充分进入视口），无崩溃，无内存泄漏。

#### 旅程 2 - 手动播放模式下触发播放

- **描述**：SDK 配置为手动播放模式，视频 Item 进入视口后仅展示封面，用户（或接入方逻辑）��动触发播放后视频开始播放。
- **成功信号**：封面状态稳定持续展示，播放触发后流畅切换，不出现未经触发的自动播放。
- **验收场景**：
  1. **前提** SDK 配置为手动播放模式，**当** 视频 Item 滑入视口，**则** 封面图展示，视频不自动播放；直至接入方显式调用播放触发接口后视频才开始播放。
  2. **前提** 手动播放模式，一个视频正在播放，**当** 第二个视频 Item 进入视口并由接入方触发播放，**则** 第一个视频暂停，第二个视频开始播放（单播策略生效）。
  3. **前提** 手动播放模式，视频正在播放，**当** App 进入后台（按 Home 键），**则** SDK 通知播放器暂停；**当** App 返回前台，**则** 视频保持暂停状态，不自动恢复播放。

### 边界与异常场景

- **视频数据源为无效本地路径** → SDK 通过 FEAT-009 发布 `VideoError` 事件，封面持续展示，不崩溃，不黑屏；
- **视频文件格式接入方播放器不支持** → 由接入方播放器返回错误，SDK 捕获并通过 FEAT-009 发布 `VideoError` 事件，封面持续展示；
- **接入方未注入 VideoPlayerController** → SDK 以"仅封面"模式展示视频 Item，不崩溃，日志记录缺失播放器配置的警告；
- **App 进入后台期间（后台状态）返回前台** → 当前可见 Item 的视频保持暂停状态，不自动恢复播放；
- **快速连续翻页导致多个视频 Item 短暂进入视口** → 单播策略确保同一时刻最多一个视频播放，资源及时释放，无内存泄漏，无崩溃；
- **视频 Item 上执行双指旋转手势** → 手势被忽略，内容不旋转，不崩溃；
- **ContentResolver URI 对应的媒体文件被删除** → SDK 通过 FEAT-009 发布 `VideoError` 事件，封面持续展示；
- **网络 URL 请求超时** → 由接入方播放器处理超时逻辑，SDK 通过 FEAT-009 透传 `VideoError` 事件，封面持续展示；
- **视频 Item 封面图未提供** → 视频 Item 展示空白占位背景（纯色），不崩溃；
- **同一时刻触发两次播放（竞态）** → 单播调度器串行处理，确保最后生效的播放请求执行，无多个播放器同时工作。

## FR / NFR

### FR（Functional Requirements）

> 规则：每条 FR 必须**可测试**，避免"提升体验/更快/更稳定"这类不可验证表述。

- **FR-001**：视频 Item 进入视口后，系统必须立即展示该视频的封面图（或首帧缩略图）；若封面图未提供，展示空白占位背景。
- **FR-002**：当 SDK 全局配置为自动播放模式时，视频 Item 完全进入视口后，系统必须自动通知已注入的 `VideoPlayerController` 开始播放，无需接入方额外调用。
- **FR-003**：当 SDK 全局配置为手动播放模式时，视频 Item 进入视口后系统不得自动触发播放；播放仅在接入方显式调用播放触发接口后发生。
- **FR-004**：视频 Item 离开视口（被 Pager 滑出可见区域）后，系统必须通知 `VideoPlayerController` 暂停当前播放。
- **FR-005**：App 进入后台时，系统必须通知 `VideoPlayerController` 暂停当前播放；App 返回前台后，系统不得自动恢复播放。
- **FR-006**：系统必须在同一时刻最多保持一个视频 Item 处于播放状态；当新视频触发播放时，系统必须先暂停当前正在播放的视频。
- **FR-007**：接入方必须能够通过实现 SDK 定义的 `VideoPlayerController` 抽象接口并在 SDK 初始化时注入，以使用自有播放框架驱动视频 Item 的播放。
- **FR-008**：SDK 不得渲染任何默认视频控制栏（播放/暂停按钮、进度条等），控制 UI 完全由接入方通过 FEAT-009 事件回调自行构建。
- **FR-009**：系统必须支持以下三种视频数据源类型：本地文件路径（`file://` 或绝对路径）、ContentResolver URI（`content://`）、网络 URL（`http://` / `https://`）。
- **FR-010**：视频 Item 必须支持双指捏合缩放手势（放大/缩小），缩放后内容清晰，不模糊；必须支持单指平移手势；不得响应双指旋转手势（旋转手势被忽略）。
- **FR-011**：视频首帧画面就绪前，系统必须持续展示封面图，不得展示黑屏帧。
- **FR-012**：系统必须通过 FEAT-009 事件回调系统向接入方发布以下视频状态变更事件：首帧就绪（`VideoFirstFrameReady`）、播放（`VideoPlaying`）、暂停（`VideoPaused`）、结束（`VideoEnded`）、错误（`VideoError`）、音量/静音变更（`VideoVolumeChanged`）。

### NFR（Non-Functional Requirements）

> 规则：每条 NFR 必须**量化**并附带验收方式；细化评估在 Plan 阶段完成。

#### 性能（Performance）

- **NFR-PERF-001**：视频 Item 进入视口后，封面图必须在 **100ms 内**完成渲染展示（p95，基于本地缓存封面）；若封面图需从网络加载，展示时间不计入本指标，但必须有占位背景立即展示。
- **NFR-PERF-002**：自动播放模式下，视频 Item 完全进入视口至 `VideoPlayerController.play()` 被调用的延迟必须在 **200ms 以内**（p95）。
- **NFR-PERF-003**：快速连续翻页场景（每个 Item 停留时间 < 300ms），SDK 的帧率影响不得超过 **3fps**（在搭载骁龙 665 级别 SoC 的设备上测量）。

#### 功耗（Power）

- **NFR-POWER-001**：视频播放期间的功耗由接入方注入的播放器决定，SDK 自身（生命周期调度、手势处理、封面渲染）不额外引起超过 **1mAh/小时** 的功耗增量（通过 Android Battery Historian 验证）。
- **NFR-POWER-002**：视频 Item 不在视口内时（封面展示状态），SDK 不得维持任何持续性后台任务或定时轮询，不引起额外唤醒（通过 Systrace 或 Battery Historian 验证无 Wakelock 持有）。

#### 内存（Memory）

- **NFR-MEM-001**：视频 Item 快速滑过（进入视口后 500ms 内滑出）时，为该 Item 分配的播放器资源必须在滑出后 **2 秒内** 完成���放（通过 Android Profiler Memory 验证，无持续增长）。
- **NFR-MEM-002**：连续快速翻页 50 个含视频 Item 的页面后，SDK 持有的总内存增量不得超过 **基线 + 20MB**（通过自动化内存测试用例验证）。

#### 安全与隐私（Security/Privacy）

- **NFR-SEC-001**：视频数据（本地文件、URI、网络 URL）仅用于本地播放，SDK 不得将视频内容、路径或 URI 上传至任何网络端点。
- **NFR-SEC-002**：SDK 访问 ContentResolver URI 时不得请求超出播放所需的最小权限；不得持久化存储任何视频文件路径或 URI。

#### 可观测性（Observability）

- **NFR-OBS-001**：SDK 必须在以下事件发生时输出 **Debug 级别日志**：播放器注入成功/失败、视频 Item 进入/离开视口、播放触发/暂停、后台暂停、单播策略抢占（记录被暂停的 Item 标识）。
- **NFR-OBS-002**：发生 `VideoError` 事件时，日志必须包含数据源类型（不含具体路径/URL）、错误码（来自接入方播放器）和错误描述，日志级别为 **Error**。
- **NFR-OBS-003**：SDK 须通过 FEAT-009 事件系统暴露 FR-012 中定义的所有播放状态事件，接入方可通过事件订阅实现完整的播放状态监控。

#### 可靠性（Reliability）

- **NFR-REL-001**：快速连续翻页（每次停留 < 300ms）自动化测试 100 次循环不得出现崩溃（Crash），通过自动化 UI 测试验证。
- **NFR-REL-002**：App 前后台切换（进入后台 → 返回前台）自动化测试 20 次循环不得出现崩溃，播放状态符合 FR-005 定义。
- **NFR-REL-003**：接入方未注入 `VideoPlayerController` 的情况下，完整浏览含视频 Item 的列表不得出现崩溃，视频 Item 以封面模式降级展示。
- **NFR-REL-004**：视频数据源不可达（路径不存在、文件损坏、网络超时）时，SDK 不得崩溃，必须通过 FEAT-009 发布 `VideoError` 事件，封面持续展示。

## 验收标准（Feature Level）

- **AC-001**（对应 FR-001，AC-028）：视频 Item 进入视口后，封面图在 100ms 内可见（p95，基于本地缓存封面）；未提供封面时展示空白占位背景，不崩溃。
- **AC-002**（对应 FR-002，AC-029）：SDK 配置为自动播放模式时，视频 Item 完全进入视口后 200ms 内 `VideoPlayerController.play()` 被调用，视频自动播放。
- **AC-003**（对应 FR-003，AC-030）：SDK 配置为手动播放模式时，视频 Item 进入视口后封面持续展示，`VideoPlayerController.play()` 不被自动调用；仅在接入方显式触发后播放。
- **AC-004**（对应 FR-004，AC-031）：视频 Item 滑出视口后，`VideoPlayerController.pause()` 在 200ms 内被调用，视频停止播放。
- **AC-005**（对应 FR-005，AC-032）：App 进入后台时（`ON_STOP` 生命周期），`VideoPlayerController.pause()` 被调用；App 返回前台时，视频保持暂停状态，`play()` 不被自动调用。
- **AC-006**（对应 FR-006，AC-033）：同一时刻最多一个视频处于播放状态；触发新视频播放时，当前播放视频的 `pause()` 在新视频 `play()` 之前被调用。
- **AC-007**（对应 FR-007，AC-034）：接入方实现并注入 `VideoPlayerController` 后，视频 Item 使用该播放器实例播放；SDK 内部不调用任何具体播放框架 API。
- **AC-008**（对应 FR-008，AC-035）：SDK 渲染的视频 Item 视图层级中不包含任何控制栏相关 View（播放按钮、进度条等）；通过 Layout Inspector 验证视图层级。
- **AC-009**（对应 FR-009）：分别使用本地文件路径、`content://` URI、`https://` URL 作为数据源时，视频均可正常播放（依赖接入方播放器能力），无崩溃。
- **AC-010**（对应 FR-010，AC-014）：双指捏合放大后，视频画面清晰（无明显像素化），双指捏合缩小可恢复；单指拖动可平移画面。
- **AC-011**（对应 FR-010，AC-044）：视频 Item 上执行双指旋转手势，画面不旋转，不崩溃。
- **AC-012**（对应 FR-011）：视频首帧就绪前，封面图持续展示；首帧就绪后封面切换至视频画面；整个过程中不出现黑屏帧（录屏逐帧验证）。
- **AC-013**（对应 FR-012）：视频进入播放状态时，FEAT-009 事件总线收到 `VideoPlaying` 事件；暂停时收到 `VideoPaused` 事件；播放结束时收到 `VideoEnded` 事件；发生错误时收到 `VideoError` 事件（含错误码）。
- **AC-014**（对应 NFR-MEM-001，NFR-REL-001）：快速连续翻页 100 次自动化测试无崩溃；翻页后 2 秒内 Android Profiler 中相关 Item 的播放器资源无内存持续增长。
- **AC-015**（对应 NFR-REL-003）：接入方未注入 `VideoPlayerController` 时，滑动浏览含视频 Item 的列表不崩溃，视频 Item 显示封面/占位背景。

## 核心实体

- **VideoSource（视频数据源）**：描述视频内容来源的值对象，包含数据源类型（本地文件路径 `FILE`、ContentResolver URI `CONTENT_URI`、网络 URL `NETWORK_URL`）、对应的地址字符串，以及可选的封面图 URI。不包含播放状态，不持有任何系统资源。与 `VideoPlayerController` 是使用关系（Controller 接受 VideoSource 作为播放目标参数）。

- **VideoPlayerController（播放器控制接口）**：SDK 定义的抽象接口，描述 SDK 与具体播放框架之间的契约，主要职责包括：接受 `VideoSource` 设置播放源、提供 `play()`/`pause()`/`release()` 生命周期控制方法、提供视图绑定入口（将播放器渲染 Surface 嵌入 SDK 提供的容器 View）。接入方通过实现此接口将自有播放框架（如 ExoPlayer、MediaPlayer 等）接入 SDK；SDK 仅通过此接口与播放器交互，不依赖任何具体实现类。

## 假设与约束

- **假设**：
  - 接入方已集成 FEAT-002 提供的 Pager 容器，且 Item 生命周期回调（进入/离开视口）正常工作；若 FEAT-002 未就绪，自动播放功能无法工作，Feature 降级为仅展示封面。
  - 接入方会在 SDK 初始化阶段注入有效的 `VideoPlayerController` 实现；若未注入，视频 Item 仅展示封面（功能降级，不崩溃）。
  - 视频格式的播放能力（编解码器支持、流媒体协议等）完全由接入方选择的播放框架决定，SDK 不做任何格式层面的保证或约束。
  - 封面图加载（网络封面）由接入方或 SDK 图片加载模块负责，本 Feature 仅负责在封面就绪前展示占位背景、就绪后展示封面。
- **约束**：
  - **平台约束**：最低支持 Android 8.0（API 24），目标版本 Android 15（API 35）；
  - **架构约束**：SDK 内不引入任何具体播放框架依赖（ExoPlayer、MediaPlayer 等均不作为 SDK 的传递依赖）；
  - **手势约束**：支持缩放（双指捏合）和平移（单指），明确不支持旋转（双指旋转）；
  - **播放模式约束**：自动/手动播放模式为全局配置，不支持 per-item 级别切换；
  - **单播约束**：同一时刻最多一个视频播放，此为 SDK 强制行为，接入方不可覆盖；
  - **后台约束**：App 进入后台时强制暂停，返回前台不自动恢复，此为 SDK 强制行为。
