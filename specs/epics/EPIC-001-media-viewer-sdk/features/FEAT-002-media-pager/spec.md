## 背景与价值

- **背景**：Android 媒体浏览场景（相册、消息图片预览、电商图文详情等）普遍需要承载混合类型媒体的左右翻页容器。现有方案各接入方自行实现，存在翻页动画不一致、手势与上层 View 冲突、视频资源未及时释放、多种 Item 类型混排困难等共性痛点，导致重复开发成本高且体验参差不齐。
- **目标**：提供一个标准化、高性能、深度可定制的媒体列表翻页容器（Pager），作为 SDK 的核心承载结构，使接入方无需重复开发翻页逻辑即可获得一致的流畅体验。
- **价值**：
  - 用户：混合媒体内容翻页流畅，边界有阻尼感，翻页后状态符合预期（缩放重置、旋转保留）；离页时视频自动暂停，不干扰体验。
  - 接入方：通过统一接口配置每页独立布局，叠加贴图/文字/模糊背景，或完全替换内容区，无需关注手势分发细节。
  - 系统/平台：作为 SDK 骨架，其他 Feature（FEAT-001/003/004/006/007）均挂载于此容器之上，确保整体架构内聚。
- **范围（In Scope）**：
  - 左右滑动翻页，不支持循环翻页，首/尾两端边界有阻尼不跳转
  - 未达翻页阈值时松手自动回弹到当前 Item
  - 四种内置 Item 类型：图片（Image）、视频（Video）、实况图（LivePhoto/Olive）、自定义（Custom）；同一列表每个位置可独立指定类型
  - Item 布局深度自定义：默认大图/视频居中，支持叠加边框区域（边框内可渲染文字与图片）、贴图层、模糊背景层，以及完全替换内容区
  - 同一列表中每个 Item 的布局配置相互独立，由接入方按 position 提供
  - SDK 负责手势识别与透传/分发，保证接入方叠加在媒体上方的 View 不干扰 SDK 手势
  - 当某个位置为完全自定义 Item 时，SDK 不触发任何媒体加载逻辑
  - 翻页后图片缩放状态重置为 1×，旋转状态保留
  - 离页（滑离）视频 Item 时，SDK 通过回调通知播放器暂停
  - 预加载相邻页数量可配置（默认值 1）
- **范围外（Out of Scope）**：
  - 图片解码与渲染（属于 FEAT-001）
  - 视频播放控制逻辑（属于 FEAT-003）
  - 实况图动效播放（属于 FEAT-004）
  - Indicator/页码指示 UI（属于 FEAT-006）
  - 幻灯片自动播放（属于 FEAT-007）

## 依赖关系

- **上游依赖**：
  - **FEAT-001（图片 Item 核心）**：图片类型 Item 的渲染能力、缩放/平移手势由 FEAT-001 提供；本 Feature 依赖 FEAT-001 暴露的 Item 视图接口，以便将图片 Item 嵌入 Pager 的对应 position。
  - **FEAT-009（事件回调接口契约）**：离页暂停通知、翻页事件等回调接口定义由 FEAT-009 统一维护；本 Feature 依赖其接口契约（`OnPageChangeCallback`、`OnItemVisibilityCallback` 等）进行回调触发。
- **下游影响**：
  - FEAT-003（视频 Item）、FEAT-004（实况图 Item）、FEAT-006（Indicator）、FEAT-007（幻灯片）均依赖本 Feature 提供的 Pager 容器作为宿主，其 Item 挂载、事件监听、生命周期联动均通过本 Feature 定义的接口进行。
- **外部依赖故障模式**：
  - FEAT-001 图片 Item 视图接口未就绪：Pager 可降级显示占位图，不影响 Pager 容器自身的翻页功能验证。
  - FEAT-009 回调接口契约变更：可能导致离页暂停等回调时序错误；需接口版本锁定或协议冻结后同步。

> 本 Feature 作为 SDK 核心骨架（Capability Feature），其他业务类 Feature 均以此为宿主，建议优先交付。依赖的 Capability Feature：`FEAT-009`（事件回调契约）。

## 验收与场景

> 说明：本节用于"可测试"的需求验收；**不等同于技术 Story**（技术 Story 在 Plan 阶段拆分）。

### 核心用户旅程

#### 旅程 1 - 混合媒体列表翻页

- **描述**：用户打开包含图片、视频、实况图混合内容的媒体列表，通过左右滑动在各 Item 之间自由翻页，离开视频页时视频自动暂停，进入图片页后缩放状态为初始 1×。
- **成功信号**：用户能顺畅地在任意媒体类型之间翻页，不卡顿、不崩溃，视频离页必暂停，图片缩放始终从 1× 开始。
- **验收场景**：
  1. **前提** 列表含 [图片, 视频, 实况图, 图片] 4 个 Item，当前页为第 2 页（视频），**当** 用户向左滑动超过翻页阈值松手，**则** 切换到第 3 页（实况图），动画流畅（≥60fps），视频收到暂停通知。（→ AC-015, AC-040）
  2. **前提** 当前页为第 3 页（实况图），**当** 用户向左滑动未达阈值后松手，**则** 自动回弹到第 3 页，不发生页面切换。（→ AC-016）
  3. **前提** 从视频页（第 2 页）翻到图片页（第 1 页），之后用户放大图片到 3×，**当** 再次翻页到第 3 页后���回第 1 页，**则** 第 1 页图片缩放比例重置为 1×。（→ AC-072）
  4. **前提** 从图片页翻到任意页后翻回，图片曾被旋转 90°，**当** 翻回该图片页，**则** 旋转角度保持 90°，不重置。（→ AC-073）

#### 旅程 2 - 自定义布局与自定义 Item 场景

- **描述**：接入方为某个 position 注册完全自定义的 View（如地图），以及为另一个 position 配置叠加贴图/文字/模糊背景的图片布局；用户浏览时自定义页不触发媒体加载，叠加层不干扰图片手势。
- **成功信号**：自定义 Item 页面内容正确显示且 SDK 不加载任何媒体资源；图片叠加层存在时，缩放/平移手势依然可用；不同 position 的布局完全独立。
- **验收场景**：
  1. **前提** 列表第 3 页为自定义（地图）Item，**当** 用户翻到第 3 页，**则** 地图正常显示，SDK 不发起图片/视频加载请求。（→ AC-017, AC-043）
  2. **前提** 列表第 1 页图片上叠加贴图层和文字层，**当** 用户在图片区域执行双指缩放，**则** 图片正常缩放，叠加层不拦截手势（手势透传由 SDK 保障）。（→ AC-018）
  3. **前提** 第 1 页配置边框区域（边框内含文字），第 2 页无边框，**当** 用户在两页间翻页，**则** 两页布局结构完全独立，第 2 页不出现第 1 页的边框元素。（→ AC-019, AC-042）
  4. **前提** 第 1 页图片下层配置模糊背景，**当** 用户查看第 1 页，**则** 模糊背景可见，图片居中正常渲染，缩放不受影响。（→ AC-041）

### 边界与异常场景

- **空列表（count = 0）** → Pager 显示空白区域，不崩溃，不触发任何 Item 创建或媒体加载。
- **只有一个 Item** → 左右两侧均有阻尼感，无法翻页，不跳转，不崩溃。（→ AC-025）
- **第一页继续左滑 / 最后一页继续右滑** → 呈现阻尼效果（橡皮筋感），松手后弹回当前页，不切换到不存在的页。（→ AC-025）
- **快速连续翻页 100 次** → 不崩溃，不出现内存泄漏，页面状态正确（当前页显示正确 Item）。（→ NFR-REL-001）
- **快速翻页经过视频/实况图 Item** → 每次离页均触发暂停/释放通知，资源正确回收，不崩溃。（→ AC-040, NFR-REL-002）
- **叠加层手势与 SDK 手势冲突** → SDK 通过手势分发机制保证图片缩放/平移手势优先于叠加层触摸事件；接入方 View ���声明消费特定手势，SDK 不重复消费。（→ AC-018, FR-008）
- **预加载数量配置为 0** → 仅加载当前页，相邻页在进入时按需加载，Pager 功能不受影响。
- **应用退到后台时** → 当前视频 Item 收到暂停通知，Pager 保持当前 position，重新进入前台时不自动恢复播放（播放恢复由 FEAT-003 控制）。
- **Item 数量动态变化（运行时增减）** → Pager 刷新内容，当前 position 若仍合法则保持，否则移动到合法边界，不崩溃。

## FR / NFR

### FR（Functional Requirements）

> 规则：每条 FR 必须**可测试**，避免"提升体验/更快/更稳定"这类不可验证表述。

- **FR-001**：Pager 必须支持左右滑动翻页，在同一列表内按顺序展示 Item；翻页方向固定为水平方向，不支持垂直翻页。
- **FR-002**：当用户滑动超过可配置的翻页阈值时，Pager 必须切换到相邻 Item，切换时有过渡动画；未达阈值松手后必须自动回弹到当前 Item。
- **FR-003**：Pager 不支持循环翻页；在第一页继续左滑或在最后一页继续右滑时，必须呈现阻尼（橡皮筋）效果，松手后回到当前页，不发生页面跳转。
- **FR-004**：Pager 必须支持四种内置 Item 类型：图片（Image）、视频（Video）、实况图（LivePhoto）、自定义（Custom）；同一列表中每个 position 的类型可独立指定。
- **FR-005**：接入方必须能够通过 ItemAdapter 接口按 position 独立配置每个 Item 的布局，包括：叠加边框区域（边框内可渲染文字与图片）、贴图层、模糊背景层，以及完全替换内容区。
- **FR-006**：同一列表中各 Item 的布局配置必须相互独立，一个 Item 的配置不得影响其他 Item 的渲染结构。
- **FR-007**：当某个 position 的 Item 类型为 Custom（完全由接入方提供 View）时，SDK 不得触发任何媒体（图片/视频/实况图）加载逻辑。
- **FR-008**：SDK 必须负责手势识别与透传/分发；接入方叠加在媒体上方的 View 不得干扰 SDK 的缩放/平移等手势识别；接入方可声明其 View 消费的手势类型，SDK 据此分发，不重复消费。
- **FR-009**：Pager 切换到新 Item 时，图片的缩放状态必须重置为 1×；旋转状态必须保留（不重置为 0°）。
- **FR-010**：当用户翻页离开视频类型 Item 时，Pager 必须通过 FEAT-009 ��义的回调接口，通知宿主/播放器对该视频执行暂停操作。
- **FR-011**：预加载相邻页数量必须可配置（接受非负整数）；默认预加载数量为 1（即提前加载当前页左右各 1 页）。
- **FR-012**：Pager 必须支持运行时动态更新 Item 列表（增加/删除/替换），更新后刷新显示，当前 position 若仍合法则保持，否则移动至最近合法边界。

### NFR（Non-Functional Requirements）

> 规则：每条 NFR 必须**量化**并附带验收方式；细化评估在 Plan 阶段完成。

#### 性能（Performance）

- **NFR-PERF-001**：翻页过渡动画帧率在普通设备（60Hz）上必须达到 ≥ 60fps，在高刷设备（120Hz）上必须达到 ≥ 120fps；验收方式：使用 Perfetto/FrameMetrics 在中端机（Snapdragon 778G 或同档位）上录制翻页过程，主线程帧时间 p95 ≤ 16.7ms（60Hz）/ ≤ 8.3ms（120Hz），不得出现连续 3 帧及以上丢帧。
- **NFR-PERF-002**：Pager 首次渲染当前 Item 的时间（从 `setAdapter` 到首帧可见）在 Release 构建下 p95 ≤ 300ms（不含图片网络加载时间）；验收方式：Systrace/Logcat 打点测量。

#### 功耗（Power）

- **NFR-POWER-001**：Pager 在静止展示当前 Item（无用户交互、无动画运行）时，不得持续触发主线程绘制或后台解码任务；不可见的预加载页在内容就绪后必须停止渲染循环；60 秒静默场景下 CPU 增量 ≤ 2%（Perfetto 能耗轨迹，Pixel 6 同档位设备验证）。

#### 内存（Memory）

- **NFR-MEM-001**：在预加载数量为默认值 1 时，Pager 实例化后（含当前页及相邻各 1 页）的总内存增量不超过 80MB（3GB RAM 中端机，Android Profiler 堆快照验收）；离屏 Item 超出预加载范围后，其持有的 Bitmap 资源必须被回收或降级为缩略图占位。
- **NFR-MEM-002**：快速连续切换 100 次后，Pager 的堆内存增量不超过初始状态的 20%，无 OOM 崩溃，LeakCanary 检测无内存泄漏。

#### 安全与隐私（Security/Privacy）

- **NFR-SEC-001**：SDK 不收集、不上报任何用户行为数据（翻页次数、浏览时长、内容信息等）；不读取、不持久化接入方注入的 View 内容或媒体数据；不申请任何额外 Android 运行时权限。
- **NFR-SEC-002**：接入方通过 ItemAdapter 提供的 View 或配置数据由接入方自行负责内容合规；SDK 对外部数据不做反序列化操作，不存在注入风险。

#### 可观测性（Observability）

- **NFR-OBS-001**：SDK 必须提供 Debug 级别日志（通过 `MediaPagerLogger` 或等效接口），记录以下关键事件：页面切换（from/to position、Item 类型）、离页暂停回调触发、预加载启动/完成/取消、边界阻尼触发；日志默认关闭，接入方可通过 SDK 配置开启。
- **NFR-OBS-002**：翻页动画出现连续 3 帧超时时，SDK 必须通过日志输出 FrameDrop 警告，包含时间戳与当前 position，方便接入方排查性能问题。

#### 可靠性（Reliability）

- **NFR-REL-001**：快速连续切换 100 次（每次切换间隔 < 100ms，通过 UI 自动化测试模拟）不崩溃、不 ANR，翻页后当前 position 与预期一致。
- **NFR-REL-002**：快速翻页连续经过 10 个视频/实况图 Item 时，每次离页暂停回调均被触发（不遗漏），资源无泄漏（Android Profiler 验证），不崩溃。
- **NFR-REL-003**：最低支持 Android 8.0（API 26）；目标版本 Android 15（API 35）；在最低支持版本上所有 FR 功能必须可用，不得使用低于 API 26 的平台 API。

## 验收标准（Feature Level）

- **AC-015**：滑动超过翻页阈值后，Pager 切换到相邻 Item，切换动画帧率 ≥ 60fps，切换完成后 position 更新正确。（→ FR-002, NFR-PERF-001）
- **AC-016**：滑动未达翻页阈值时松手，Pager 自动回弹到当前 Item，position 不发生变化。（→ FR-002）
- **AC-017**：某个 position 注册为 Custom Item 后，翻到该页时显示接入方提供的自定义内容，SDK 不发起任何图片/视频/实况图加载请求。（→ FR-004, FR-007）
- **AC-018**：图片 Item 上叠加贴图层或文字层后，在图片区域执行双指缩放和单指平移手势，图片正常缩放/平移，叠加层不拦截上述手势。（→ FR-008）
- **AC-019**：配置边框区域的 Item 页面，边框内可渲染文字和图片，图片内容区居中显示；未配置边框的相邻页面不出现边框元素。（→ FR-005, FR-006）
- **AC-025**：第一页左滑或最后一页右滑时，出现阻尼效果（视觉弹性阻力），松手后回到当前页，position 不变，不崩溃。（→ FR-003）
- **AC-039**：同一列表中混合包含图片、视频、实况图、自定义 Item 时，可在任意位置之间正常翻页，每页正确展示对应类型内容。（→ FR-004）
- **AC-040**：翻页离开视频 Item 后，通过 FEAT-009 回调接口，播放器收到暂停通知，视频停止播放。（→ FR-010）
- **AC-041**：图片 Item 配置模糊背景后，模糊背景在图片下方可见，图片正常居中渲染，图片缩放/平移不受影响。（→ FR-005）
- **AC-042**：同一列表中相邻两页可使用完全不同的布局结构，两页布局不互相干扰。（→ FR-006）
- **AC-043**：某页注册地图 View 作为 Custom Item，翻到该页后地图正常显示，SDK 不加载图片、视频或实况图资源，不崩溃。（→ FR-007）
- **AC-072**：翻页切换到新 Item 后，图片的缩放比例重置为 1×（即使之前已缩放到更大比例）。（→ FR-009）
- **AC-073**：翻页切换到新 Item 后，再切换回图片 Item，图片旋转角度保留，不重置为 0°。（→ FR-009）
- **AC-074**：快速连续翻页 100 次后，不崩溃，当前 position 与预期一致，LeakCanary 检测无内存泄漏。（→ NFR-REL-001, NFR-MEM-002）
- **AC-075**：快速翻页经过 10 个视频 Item，每次离页均触发暂停回调，Android Profiler 验证无 Bitmap/View 内存泄漏。（→ NFR-REL-002）
- **AC-076**：在 Android 8.0（API 26）真机或模拟器上，所有 FR 功能正常可用。（→ NFR-REL-003）
- **AC-077**：Pager 静止展示当前 Item 60 秒，Perfetto 能耗轨迹显示 CPU 增量 ≤ 2%，不可见预加载页无持续绘制任务。（→ NFR-POWER-001）

## 核心实体

- **Item（媒体条目）**：Pager 中单个位置所展示的内容单元。核心属性：`position`（在列表中的索引，从 0 开始）、`type`（ItemType 枚举值）、`layoutConfig`（该位置的布局配置，引用 ItemLayoutConfig）、`mediaSource`（媒体来源描述符，Custom 类型时为 null）。每个 Item 的所有属性相互独立，不与其他 Item 共享可变状态。

- **ItemType（Item 类型枚举）**：标识 Item 承载的媒体类型，枚举值：`IMAGE`（图片，渲染能力由 FEAT-001 负责）、`VIDEO`（视频，播放逻辑由 FEAT-003 负责）、`LIVE_PHOTO`（实况图，动效由 FEAT-004 负责）、`CUSTOM`（完全由接入方提供 View，SDK 不加载任何媒体资源）。

- **ItemAdapter（接入方配置���口）**：接入方实现此接口向 Pager 提供内容与布局。核心职责：按 position 返回 Item 总数（`getItemCount()`）、Item 类型（`getItemType(position)`）、该位置的布局配置（`getLayoutConfig(position): ItemLayoutConfig`）、Custom Item 的 View 实例（`createCustomView(position): View`，仅 CUSTOM 类型时调用）。Adapter 必须保证同一 position 在未触发 `notifyDataChanged()` 前返回一致的类型。

- **ItemLayoutConfig（Item 布局配置）**：描述单个 Item 的视觉结构配置。包含：是否启用边框区域及边框宽度（`borderWidth`）、边框内内容列表（文字/图片）、贴图层列表（`overlayLayers`，每层含位置/尺寸/内容描述）、是否启用模糊背景（`blurBackground`）、内容区替换 View（`contentReplacementView`，非 null 时完全替换默认媒体渲染区域）。所有字段可选，未配置时使用默认布局（媒体居中、无叠加）。

- **ViewportState（视口状态）**：描述 Pager 当前的显示状态。核心属性：`currentPosition`（当前完全可见的 Item 索引）、`scrollOffset`（当前滑动偏移量，用于阻尼效果计算）、`isDragging`（用户是否正在拖动）、`isSettling`（是否正在执行惯性/回弹动画）。ViewportState 变化时通过 FEAT-009 定义的回调接口通知宿主。

## 假设与约束

- **假设**：
  - 接入方保证同一 position 在刷新前 `getItemType()` 返回值不变；若违反，Pager 行为未定义，需接入方主动调用 `notifyDataChanged()` 后重建 Item。
  - 接入方在 Custom Item 的 View 中自行处理生命周期（onResume/onPause 等），SDK 仅通知翻页事件，不管理 Custom View 的内部状态；若接入方未处理，可能导致 Custom Item 资源泄漏，责任由接入方承担。
  - 图片缩放/平移手势由 FEAT-001 的手势检测器实现；若 FEAT-001 延期，Pager 的手势分发验收需要 mock 替代实现，不阻塞 Pager 容器自身的翻页验证。
  - FEAT-009 回调接口在本 Feature 开发期间稳定；若接口变更，需同步更新本 Feature 的回调触发逻辑。
- **约束**：
  - 最低支持 Android 8.0（API 26），不得使用 API 26 以下的平台 API。
  - 目标版本 Android 15（API 35），需在目标版本上通过所有验收测试。
  - SDK 不申请任何 Android 运行时权限，不依赖外部网络（媒体资源加载由接入方通过图片加载库自行处理，FEAT-001 负责集成）。
  - 翻页阈值的默认值与可配置范围在 Plan 阶段由技术设计决定；本 spec 仅要求该参数可配置。
  - Pager 的宿主接口形态（Compose 组件或 View 体系）在 Plan 阶段确定；本 spec 不预设实现方式，只定义行为契约。
