# EPIC 规格说明：Android 媒体浏览 SDK

**EPIC ID**：EPIC-001
**EPIC Version**：v0.1.0
**创建时间**：2026-03-22
**状态**：就绪（可拆分 Feature）
**输入**：`docs/requirements/media-viewer-sdk-spec.md`

## 背景、目标与价值 *（必填）*

- **背景**：App 内存在媒体浏览场景，列表中的每个 Item 可能是图片、视频、实况图（olive/Live Photo），也可能是完全自定义的布局。现有解决方案在超大图（2亿像素级别）加载、HDR 显示、实况图播放、视频 Item 集成、深度自定义布局等方面能力不足，需要一套专为 Android 打造的高性能媒体浏览 SDK。
- **目标**：
  - 提供一个可接入主流 Android 应用的媒体浏览 SDK 组件，使接入方无需自行实现复杂的图片/视频/实况图浏览逻辑。
  - 最终用户能流畅浏览各种格式、各种分辨率的图片，观看视频，体验实况图动效，支持手势操控、HDR 效果。
- **价值**：将媒体浏览核心能力沉淀为可复用 SDK，降低接入方研发成本，提供统一、高质量的媒体浏览体验。
- **产品竞争力**：支持超大图（2亿像素）无 OOM 浏览、HDR 显示、实况图动效、双形态无缝动画切换，提供业内领先的沉浸式媒体浏览体验；同时具备完全可定制的布局能力，满足接入方个性化场景。
- **技术竞争力**：分块区域解码（Tile-based）策略应对超大图内存挑战；Ultra HDR 渲染支持高亮色彩表现；可扩展 MotionPhotoParser 接口兼容多厂商实况图格式；播放器抽象注入架构消除视频框架绑定。
- **成功标准（EPIC Level）**：
  - 2亿像素图片可稳定加载、分块显示，无 OOM
  - 手势操作（缩放/平移/旋转/翻页）帧率 ≥ 60fps
  - 视频 Item 正常播放，翻页离开时自动暂停，不影响相邻图片 Item 的手势交互
  - 接入方可在不修改 SDK 源码前提下完全自定义每页布局
  - SDK 以 AAR 形式交付，新建空项目可独立集成验证通过

## 范围 *（必填）*

- **In Scope**：
  - 图片格式解码与渲染（JPEG / PNG / HEIF / WebP / BMP / GIF）
  - 超大图分块（Tile）加载与区域解码
  - 手势交互：双击放大、双指缩放、单指平移、双指旋转（旋转仅适用于图片 Item）
  - 媒体列表（Pager）左右翻页，支持四种内置 Item 类型：图片、视频、实况图（olive）、自定义
  - 视频 Item 播放（作为 Pager 独立 Item 类型）
  - 实况图（olive / Live Photo）Item：静态展示 + 长按播放动效
  - 每页 Item 布局完全可自定义（支持纯自定义 View 替代整页内容）
  - HDR 效果显示（Android 14+）
  - 沉浸式浏览：edge-to-edge 内容延伸、点击空白区触发 UI 显隐回调
  - 翻页指示器（Indicator）：SDK 提供默认样式，支持自定义替换，支持进度显示
  - 幻灯片自动播放（Slideshow）
  - 双形态动态布局切换：展示态（图片+周边装饰）↔ 浏览态（纯媒体），无缝动画过渡
  - SDK 事件回调系统（翻页、媒体加载状态、视频播放状态等）
  - Demo App：与 SDK 一同交付，演示各典型使用场景
- **Out of Scope**：
  - 图片编辑（裁剪、滤镜、标注等）
  - 图片/视频上传、分享、下载功能
  - 图片压缩工具
  - 非 Android 平台（iOS、Web 等）
  - 通用流媒体播放器（视频 Item 为本地/URI 播放，不含直播流、HLS 等）
  - Jetpack Compose 接入（仅 View 体系）
- **上项范围**：
  - 设备类型：Android 手机、平板
  - OS 版本：Android 8.0（API 26）及以上；HDR 功能需 Android 14（API 34+）
  - 保密等级：内部
- **上项节奏**：SDK 全功能完成后整体交付，Demo App 同步交付

## 约束与假设 *（必填）*

- **约束**：
  - 目标平台仅为 Android（View 体系，不含 Jetpack Compose）
  - 超大图区域解码依赖 `BitmapRegionDecoder`，部分格式在低版本系统上支持有限（HEIF 需 API 28+）
  - Ultra HDR 渲染 API 需要 Android 14（API 34）及以上
  - SDK 不内置视频播放器，由接入方注入抽象实现
  - SDK 以 AAR 方式分发，不强制要求接入方升级/降级任何已有依赖
- **假设**：
  - 接入方负责提供图片/视频的数据源（本地路径、ContentResolver URI、网络 URL）
  - 网络图片/视频 URL 加载依赖接入方注入的图片加载框架（如 Glide/Coil）
  - 图片加载失败的 error placeholder UI 由接入方完全自定义
  - 若假设（图片加载框架由接入方注入）不成立，SDK 需内置默认加载框架，影响包体积和依赖管理

## 依赖关系 *（必填）*

- **上游依赖**：接入方提供图片/视频数据源；接入方注入视频播放器抽象实现；接入方提供图片加载框架（Glide/Coil 等）
- **下游影响**：所有集成本 SDK 的业务 App
- **外部依赖故障模式**：接入方播放器不可用时 SDK 提供降级占位展示；图片加载框架不可用时显示 error placeholder（由接入方定义）

### Feature 边界说明（每个 Feature 必填）

#### FEAT-001 - 图片浏览核心能力

- **类型**：Product
- **用户价值**：用户能够流畅查看各种格式（JPEG/PNG/HEIF/WebP/BMP/GIF）的图片，包括 2 亿像素级超大图，并通过双击放大、双指缩放（最大5倍）、单指平移、双指旋转等手势操控图片，任意缩放倍率下图片保持清晰。
- **目标**：提供单张图片浏览的完整核心能力（多格式解码、超大图分块加载、手势交互）。
- **范围（In）**：多格式图片解码（JPEG/PNG/HEIF/WebP/BMP/GIF）；超大图 Tile 分块加载与区域解码；双击放大（相对当前比例2倍）、双指无极缩放[1x,5x]、单指平移（放大后）、双指旋转（松手对齐90°倍数）；图片放大后按当前倍率重新解码 Tile 保持清晰；GIF 动图按帧率自动播放。
- **非范围（Out）**：视频播放；实况图动效；HDR 渲染（在 FEAT-005）；Pager 翻页容器（在 FEAT-002）。
- **依赖**：无上游 Feature 依赖；外部依赖 BitmapRegionDecoder、图片加载框架（接入方注入）。
- **验收意图**：各格式图片正确渲染；2亿像素图在4GB RAM设备不OOM；手势操作帧率≥60fps；缩放不模糊。
- **拆分动机**：图片解码与手势交互是整个 SDK 的核心地基，其他 Feature 都依赖此基础能力，必须先行完成并独立验收。
- **交接给 `/aisdd.featurespec` 的输入**：`图片浏览核心能力：多格式图片解码（JPEG/PNG/HEIF/WebP/BMP/GIF）、超大图 Tile 分块加载与区域解码、手势交互（双击放大2倍、双指无极缩放[1x~5x]+回弹、单指平移+边缘回弹、双指旋转松手对齐90°倍数）、GIF 动图自动播放；非范围：视频/实况图/HDR/Pager 容器；关键 NFR：内存（超大图 OOM 防护）、手势帧率 ≥60fps、兼容性（API 26+，HEIF API 28+）`

#### FEAT-002 - 媒体列表 Pager

- **类型**：Capability
- **用户价值**：用户能够在混合媒体列表中左右翻页浏览图片、视频、实况图或自定义内容，每页布局独立可配，翻页流畅有回弹机制，离开视频页时自动暂停。
- **目标**：提供承载多种 Item 类型的列表翻页容器，支持深度自定义布局，是其他媒体 Item 类型的宿主平台。
- **范围（In）**：左右滑动翻页（非循环，边界阻尼）、翻页回弹；四种内置 Item 类型（图片/视频/实况图/自定义）；每个 Item 布局独立配置；Item 布局深度自定义（叠加层、完全替换内容区、每页不同布局）；翻页后图片缩放重置为1×、旋转状态保留；离页视频自动暂停；接入方叠加层不干扰 SDK 手势识别。
- **非范围（Out）**：图片解码渲染（在 FEAT-001）；视频播放逻辑（在 FEAT-003）；实况图播放（在 FEAT-004）；Indicator UI（在 FEAT-006）。
- **依赖**：FEAT-001（图片 Item 依赖图片浏览能力）。
- **验收意图**：混合列表翻页流畅；各 Item 类型正确渲染互不干扰；深度自定义布局可行；翻页后状态管理正确。
- **拆分动机**：Pager 是整个 SDK 的架构中枢，也是多个 Product Feature（视频、实况图、沉浸式、幻灯片、双形态）的共同依赖，需要作为独立 Capability 先行设计验收。
- **交接给 `/aisdd.featurespec` 的输入**：`媒体列表 Pager 容器：四种 Item 类型（图片/视频/实况图/自定义）混合翻页；非循环翻页+边界阻尼回弹；Item 布局深度自定义（叠加层/完全替换/每页独立布局）；手势透传分发机制（叠加层不干扰 SDK 手势）；翻页后缩放重置/旋转保留；离页视频自动暂停；关键 NFR：翻页动画性能≥60fps、多 Item 并发预加载内存控制`

#### FEAT-003 - 视频 Item 播放

- **类型**：Product
- **用户价值**：用户能在媒体列表中查看视频，视频封面即时展示，点击后流畅播放；接入方无需重复开发视频容器，只需注入已有播放器即可接入。
- **目标**：视频作为独立 Item 类型集成到媒体 Pager，支持自动/手动播放配置，控制栏 UI 完全由接入方实现，播放器框架由接入方注入。
- **范围（In）**：视频 Item 封面/首帧展示；自动/手动播放配置（全局）；离页/后台自动暂停；同一时刻最多一个视频播放；视频缩放（双指捏合）和平移（放大后单指）；视频 Item 不响应旋转手势；播放器抽象接口注入；播放状态回调（首帧就绪、播放/暂停/结束/错误、音量/静音）。
- **非范围（Out）**：视频控制栏 UI（由接入方定义）；视频格式兼容性（由接入方播放器决定）；实况图内嵌视频（在 FEAT-004）。
- **依赖**：FEAT-002（Pager 容器）；接入方提供视频播放器实现。
- **验收意图**：视频正常播放；首帧就绪前不黑屏；翻页离页/后台暂停；接入方控制栏可由回调驱动。
- **拆分动机**：视频播放涉及播放器抽象接口设计和防黑屏回调机制，是独立可交付的业务能力，可独立验收。
- **交接给 `/aisdd.featurespec` 的输入**：`视频 Item 播放：视频封面/首帧展示；自动/手动播放（全局配置）；离页/后台自动暂停；同一时刻最多一路视频；视频缩放+平移手势（不支持旋转）；播放器抽象接口注入（SDK 不内置播放器）；首帧就绪/播放状态/音量回调；关键 NFR：稳定性（快速滑过不崩溃、资源正常释放）、首帧防黑屏`

#### FEAT-004 - 实况图（olive）Item 播放

- **类型**：Product
- **用户价值**：用户浏览实况图时默认看到清晰静态封面，长按即可欣赏动效片段，松手恢复；接入方可扩展支持三星等非 Google 标准格式。
- **目标**：实况图作为独立 Item 类型，默认��态展示封面帧，长按触发内嵌动效片段播放，支持多厂商格式扩展注入。
- **范围（In）**：实况图 Item 封面帧静态展示；长按触发动效片段播放、松手停止；Google Motion Photo 格式内置支持；MotionPhotoParser 扩展接口（接入方可注入自定义解析器）；视频片段损坏/格式解析失败降级为静态图片。
- **非范围（Out）**：实况图标识 icon（由接入方自定义）；循环播放还是单次播放（待技术方案确认）；长按实况图不触发 onTapOutsideMedia 回调。
- **依赖**：FEAT-002（Pager 容器）。
- **验收意图**：封面帧静态显示；长按触发/松手停止动效；内嵌视频损坏不崩溃，降级正确。
- **拆分动机**：实况图有独特的长按播放交互与格式解析逻辑，可独立交付验收，不阻塞其他图片/视频 Feature。
- **交接给 `/aisdd.featurespec` 的输入**：`实况图（olive）Item：封面帧静态展示；长按触发内嵌动效片段播放/松手停止；Google Motion Photo 格式内置支持；MotionPhotoParser 扩展接口（支持三星 Moving Photo 等非标格式注入）；视频片段损坏/格式解析失败降级为静态图片不崩溃；关键 NFR：稳定性（降级不崩溃）、兼容性（Google Motion Photo 格式正确解析）`

#### FEAT-005 - HDR 图片显示

- **类型**：Product
- **用户价值**：在支持 HDR 的设备上，含 HDR 元数据的图片以超出 SDR 范围的亮度和色域呈现，带来更真实的视觉体验；不支持 HDR 的设备自动降级显示。
- **目标**：检测图片 HDR 元数据与设备 HDR 能力，条件满足时使用 HDR 渲染路径，否则自动降级 SDR，不崩溃。
- **范围（In）**：图片 HDR 元数据检测（Gainmap / Ultra HDR）；设备/窗口 HDR 能力检测；HDR 渲染路径（Android 14+ Ultra HDR API）；低版本/不支持设备自动降级 SDR。
- **非范围（Out）**：视频 HDR（超出 SDK 范围）；HDR 开关 UI（由接入方实现，SDK 提供配置接口）。
- **依赖**：FEAT-001（图片解码管线基础）。
- **验收意图**：HDR 图片在支持设备亮度/色域超 SDR；不支持设备正常 SDR 显示不崩溃。
- **拆分动机**：HDR 功能有明确的 API 版本约束（API 34+），可作为渐进增强能力独立交付，不阻塞图片浏览核心功能。
- **交接给 `/aisdd.featurespec` 的输入**：`HDR 图片显示：含 HDR 元数据图片（Gainmap / Ultra HDR）在支持设备上使用 HDR 渲染路径（Android 14+ API 34+）；不支持设备/版本自动降级 SDR 不崩溃；关键 NFR：兼容性（API 34+；低版本 SDR 降级）、稳定性（降级路径不报错）`

#### FEAT-006 - 沉浸式体验与 Indicator

- **类型**：Product
- **用户价值**：用户浏览时内容延伸至系统栏下方，点击空白区域可触发菜单/状态栏显隐，底部 Indicator 直观展示当前页位置，支持接入方完全自定义 Indicator 样式。
- **目标**：SDK 容器支持 edge-to-edge 布局；提供点击空白区域回调；内置翻页 Indicator（默认横线样式，支持自定义替换、显隐控制、进度显示）。
- **范围（In）**：edge-to-edge 内容延伸；系统栏 insets 信息透传给接入方；点击非媒体区域触发 onTapOutsideMedia 回调（媒体手势不触发）；SDK 默认 Indicator（底部横线，距底24dp）；自定义 IndicatorAdapter 完全替换；Indicator 翻页同步、进度显示、显隐控制（setIndicatorVisible）；Indicator 支持脱离 SDK 容器独立放置。
- **非范围（Out）**：系统栏显隐操作（由接入方通过 WindowInsetsController 执行，SDK 仅提供回调）；菜单 UI（由接入方实现）。
- **依赖**：FEAT-002（Pager 容器翻页事件）。
- **验收意图**：内容 edge-to-edge；点击回调正确触发；Indicator 翻页同步；自定义 Indicator 可替换；显隐控制有效。
- **拆分动机**：沉浸式布局与 Indicator 是用户浏览体验的关键 UI 层，可在 Pager 完成后独立实现和验收。
- **交接给 `/aisdd.featurespec` 的输入**：`沉浸式体验与 Indicator：edge-to-edge 内容延伸至系统栏下方；insets 信息透传接入方；点击非媒体区域触发 onTapOutsideMedia 回调（手势不触发）；SDK 默认 Indicator（底部横线，支持进度显示）；自定义 IndicatorAdapter 完全替换默认样式；setIndicatorVisible 控制显隐；Indicator 支持脱离 SDK 容器独立布局；关键 NFR：兼容性（API 26+ edge-to-edge）`

#### FEAT-007 - 幻灯片自动播放

- **类型**：Product
- **用户价值**：用户无需手动翻页，媒体列表可按配置间隔自动播放，Indicator 实时显示每页剩余时间，手动操作后自动暂停，空闲后自动恢复，提供展览/演示场景的自动化浏览体验。
- **目标**：接入方可开启 Slideshow 模式，SDK 按 intervalMs 自动翻页循环；手动翻页触发暂停，空闲超时后从当前页继续；Indicator 进度同步。
- **范围（In）**：startSlideshow(intervalMs) / stopSlideshow() API；自动翻页（按间隔，到达最后页循环回第一页）；手动翻页触发暂停/Indicator 进度冻结；空闲 resumeDelayMs（默认10s，可配置）后继续；恢复后进度从冻结位置续播；视频 Item 按固定 intervalMs 翻页，不等视频播完。
- **非范围（Out）**：Indicator 渲染（在 FEAT-006，幻灯片向 FEAT-006 的 Indicator 推送进度）。
- **依赖**：FEAT-002（Pager 翻页控制）；FEAT-006（Indicator 进度驱动）。
- **验收意图**：自动翻页按间隔执行；Indicator 进度实时推进；手动操作暂停/空闲恢复逻辑正确；stopSlideshow 彻底停止。
- **拆分动机**：幻灯片是在 Pager 和 Indicator 完成后可独立叠加的场景能力，不影响其他 Feature 的验收。
- **交接给 `/aisdd.featurespec` 的输入**：`幻灯片自动播放（Slideshow）：startSlideshow/stopSlideshow API；按 intervalMs 自动翻页并循环；手动翻页触发暂停（Indicator 进度冻结）；空闲 resumeDelayMs（默认10s，可配置）后从当前页继续；恢复后 Indicator 从冻结位置续播不重置；视频 Item 按固定 intervalMs 翻页；关键 NFR：稳定性（边界循环不崩溃）、Indicator 进度推送精度`

#### FEAT-008 - 双形态动态布局切换

- **类型**：Product
- **用户价值**：接入方可为每个 Item 定义展示态（图片+周边装饰）和浏览态（纯媒体）两种形态，用户触发切换时媒体内容区域在两种形态间执行流畅的位置/尺寸动画，提升浏览体验的仪式感与沉浸感。
- **目标**：Item 支持展示态↔浏览态双形态切换，SDK 对媒体内容区域执行 Rect 插值动画过渡，切换期间手势禁用，动画不可打断。
- **范围（In）**：switchLayout(LayoutMode) API；展示态/浏览态两种形态定义；SDK 对媒体区域 Rect 差异执行插值动画；动画时长可配置；切换期间手势禁用；动画不可打断（进行中再次触发忽略）；切换到浏览态后缩放重置1×；不同 Item 可独立处于不同形态；未声明媒体区域时降级为无动画直接切换；onLayoutSwitchComplete 回调。
- **非范围（Out）**：周边装饰的具体淡入/淡出实现（SDK 提供驱动接口，接入方可自行实现）；媒体区域声明方式的具体接口（留技术方案确定）。
- **依赖**：FEAT-002（Pager Item 容器）；FEAT-001（图片浏览手势状态管理）。
- **验收意图**：媒体区域平滑过渡无跳变；切换期间手势正确禁用；动画不可打断；未声明区域降级不崩溃。
- **拆分动机**：双形态切换是一个独立的动画交互能力，有明确的触发 API 和完成回调，可在其他核心功能完成后独立验收。
- **交接给 `/aisdd.featurespec` 的输入**：`双形态动态布局切换：switchLayout API 触发展示态↔浏览态；SDK 对媒体区域 Rect 执行位置/尺寸插值动画（动画时长可配置）；切换期间手势禁用；动画不可打断（进行中触发忽略）；切换到浏览态后缩放重置1×；不同 Item 可独立处于不同形态；未声明媒体区域时降级无动画直接切换不崩溃；onLayoutSwitchComplete 回调；关键 NFR：动画帧率≥60fps、稳定性（降级不崩溃）`

#### FEAT-009 - SDK 事件回调系统

- **类型**：Capability
- **用户价值**：接入方能够通过标准回调接口感知 SDK 内部所有关键状态变化（翻页、图片加载进度、视频首帧就绪、视频播放状态），从而驱动自定义 UI 并有效避免黑屏等过渡体验问题。
- **目标**：SDK 提供完整事件回调体系，覆盖翻页、媒体加载、视频播放状态，所有回调在主线程执行，不注册回调时 SDK 正常工作不报错。
- **范围（In）**：onPageChanged / onPageScrolled；onThumbnailLoaded / onHighResLoaded（防黑屏机制）；onVideoFirstFrameReady（视频防黑屏）；onVideoPlaybackStateChanged / onVideoVolumeChanged；onLoadError；回调主线程执行；不注册回调 SDK 正常运行。
- **非范围（Out）**：具体事件触发逻辑分散在各 Feature 中（此 Feature 仅定义回调接口和发布机制）。
- **依赖**：FEAT-002（翻页事件）；FEAT-003（视频播放状态）。
- **验收意图**：所有回调在正确时机以正确参数触发；主线程执行；不注册不崩溃。
- **拆分动机**：事件回调是跨多个 Feature 的横切关注点，被 FEAT-003（视频）、FEAT-006（Indicator 联动）等多个 Feature 依赖，单独管理接口契约有助于保证一致性。
- **交接给 `/aisdd.featurespec` 的输入**：`SDK 事件回调系统：翻页回调（onPageChanged/onPageScrolled）；图片加载回调（onThumbnailLoaded/onHighResLoaded，防黑屏机制）；视频回调（onVideoFirstFrameReady 防黑屏、onVideoPlaybackStateChanged、onVideoVolumeChanged）；错误回调（onLoadError）；所有回调主线程执行；不注册回调 SDK 正常运行不崩溃；关键 NFR：可观测性（回调时机准确、参数正确）、稳定性（不注册不崩溃）`
