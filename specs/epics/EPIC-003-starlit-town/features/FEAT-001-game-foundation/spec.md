# Feature 规格说明：游戏基础框架与地图

**Epic**：EPIC-003 - 星光小镇（Starlit Town）
**Feature 类型**：Platform-Capability Feature
**Feature ID**：FEAT-001
**Feature Version**：v0.1.0
**EPIC 分支**：`epic/EPIC-003-starlit-town`
**Feature 目录**：`specs/epics/EPIC-003-starlit-town/features/FEAT-001-game-foundation/`
**创建时间**：2025-02-04
**状态**：草稿
**输入**：用户描述：`"星光小镇 HTML 游戏基础框架与地图导航、每日循环骨架、本地存储"`

## 背景与价值 *（必填）*

- **背景**：星光小镇需一套 HTML 游戏骨架，作为所有业务 Feature 的共用基础设施；若无入口、场景切换、每日循环与存储，后续小镇生活、装扮、角色关系等无法落地。
- **目标**：提供 HTML 游戏入口、地图导航、场景切换、每日循环骨架（早上/白天/晚上）、本地存储基础，使业务 Feature 可在此之上构建。
- **价值**：为 EPIC-003 奠定技术底座，统一场景切换与进度持久化能力；用户可打开游戏、在地图间切换、完成一日循环骨架、进度可本地保存。
- **范围（In Scope）**：HTML 游戏入口；场景切换；地图导航；每日循环骨架（早上/白天/晚上）；本地存储基础（进度、状态持久化）。
- **范围外（Out of Scope）**：具体业务玩法（装扮、NPC 逻辑、小游戏）；美术资源与动效；后端账号体系。

## 依赖关系 *（必填）*

- **上游依赖**：无
- **下游影响**：小镇生活系统（FEAT-003）、装扮与创造系统（FEAT-004）、角色关系系统（FEAT-005）、动效与交互体验能力（FEAT-002）、AI 小故事（FEAT-006）
- **外部依赖故障模式**：localStorage/IndexedDB 不可用时，游戏可启动但进度无法持久化，需友好提示

## 验收与场景 *（必填）*

### 核心用户旅程（可选但强烈建议）

#### 旅程 1 - 首次进入并完成一日骨架

- **描述**：用户打开游戏 URL，期间展示加载动画或进度提示；加载完成后看到入口界面；进入后可在地图上切换场景（家/学校/公园/商店/森林）；经历早上→白天→晚上的循环骨架；关闭后再次打开，进度可恢复。
- **成功信号**：用户可在 5 分钟内完成首次探索与一日循环骨架；进度可本地保存并恢复。
- **验收场景**：
  1. **前提** 用户首次访问，**当** 打开游戏 URL，**则** 展示游戏入口/主界面
  2. **前提** 用户在主界面，**当** 选择地图/场景，**则** 成功切换到对应场景
  3. **前提** 用户完成一日循环，**当** 关闭并重新打开游戏，**则** 上次进度（如当前日、场景）可恢复

### 边界与异常场景（必填）

- 浏览器不支持 localStorage/IndexedDB → 提示“进度无法保存”，允许继续以无保存模式游玩
- 存储空间不足 → 按时间清理最早的游戏日数据，必要时提示用户
- 用户快速连续切换场景 → 不发生卡顿或状态错乱
- 页面刷新/意外关闭 → 尽量恢复至最近保存状态

## FR / NFR *（必填）*

### FR（Functional Requirements）

- **FR-001**：系统必须提供 HTML 游戏入口，用户打开 URL 可进入游戏主界面
- **FR-002**：系统必须支持场景切换，用户可在地图各场景（家/学校/公园/商店/神秘森林）间导航
- **FR-003**：系统必须实现每日循环骨架（早上、白天、晚上三个阶段），用户可推进至下一阶段
- **FR-004**：系统必须提供本地存储能力，将游戏进度（当前日、场景、阶段等）持久化
- **FR-005**：系统必须在用户再次打开游戏时，从本地存储恢复上次进度

### NFR（Non-Functional Requirements）

#### 性能（Performance）

- **NFR-PERF-001**：首屏加载时间 ≤ 3 秒（常规网络：4G/WiFi，RTT < 100ms）；场景切换响应 ≤ 500ms

#### 功耗（Power）

- **NFR-POWER-001**：不适用（Web 浏览器环境下无独立功耗预算）

#### 内存（Memory）

- **NFR-MEM-001**：单页应用内存增量 ≤ 100MB；页面长时间运行无显著泄漏

#### 安全与隐私（Security/Privacy）

- **NFR-SEC-001**：不收集个人敏感信息；本地存储仅用于游戏进度，符合儿童内容合规要求

#### 可观测性（Observability）

- **NFR-OBS-001**：关键操作（入口加载、场景切换、存储读写失败）可日志记录，便于排查问题

#### 可靠性（Reliability）

- **NFR-REL-001**：存储读写失败时，有降级策略（提示用户、允许无保存模式继续游玩）

## 验收标准（Feature Level）*（必填）*

- **AC-001**：用户打开游戏 URL 可进入主界面，符合 FR-001
- **AC-002**：用户可在地图各场景间切换，无阻塞或错误，符合 FR-002
- **AC-003**：用户可完成早上→白天→晚上的循环骨架，符合 FR-003
- **AC-004**：用户关闭并重新打开游戏后，进度可恢复，符合 FR-004、FR-005
- **AC-005**：首屏加载 ≤ 3 秒，场景切换 ≤ 500ms，符合 NFR-PERF-001
- **AC-006**：存储不可用时，有明确提示，符合 NFR-REL-001

## 核心实体（如涉及数据则必填）

- **GameState**：游戏状态；核心属性：当前日（游戏内第 N 天，整数递增，与真实时间解耦）、当前场景、当前阶段（早上/白天/晚上）；关系：持久化至 IndexedDB（localStorage 降级）
- **Scene**：场景；核心属性：场景 ID、名称（家/学校/公园/商店/森林）；关系：可切换
- **DayCycle**：每日循环；核心属性：阶段（早上、白天、晚上）；关系：可推进

## 假设与约束 *（必填）*

- **假设**：目标用户使用主流现代浏览器（Chrome、Safari、Edge 等）；优先使用 IndexedDB 存储（支持更大容量与结构化数据，localStorage 作为降级）；常规网络为 4G/WiFi（RTT < 100ms）。若假设不成立，需有降级与提示。
- **约束**：HTML/CSS/JavaScript 技术栈；兼容 EPIC 上项范围（PC 与平板浏览器）；面向 7–8 岁儿童的合规要求。

## 澄清内容

### 会话 2025-02-05

- 问题：本地存储技术选型：规格说明提到「localStorage 或 IndexedDB」，应优先使用哪种？ → 答案：IndexedDB（支持更大容量与结构化数据，适合游戏进度扩展）
- 问题：GameState 中「当前日」的数据语义应表示为？ → 答案：游戏内第 N 天（整数递增，与真实时间解耦）
- 问题：首屏加载 NFR 中「常规网络」的假设条件？ → 答案：4G/WiFi，RTT < 100ms
- 问题：存储空间不足时的清理策略？ → 答案：按时间清理最早的游戏日数据
- 问题：用户打开 URL 到展示主界面之间，是否需要有明确的加载反馈？ → 答案：需要加载动画或进度提示
