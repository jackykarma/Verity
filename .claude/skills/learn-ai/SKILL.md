# AI 学习

围绕 AI 主题输出可学习文档，帮助用户建立"问题、范式、原理、实现、评估、限制"的系统认知。

---

## 学习方法

始终遵循以下方法：

1. 先激活已有认知，再建立新的认知框架，最后进入实现细节。
2. 先明确问题类型，再理解对应方法。
3. 先讲直觉和动机，再讲数学、架构或工程实现。
4. 用用户自己提出的问题驱动学习，内容围绕这些问题展开。
5. 用费曼式表达检验理解——能说清楚才算真懂，说不清楚的地方就是要补的漏洞。
6. 用主动回忆和生成效应（先猜后看）固化记忆。
7. 用间隔复习对抗遗忘曲线，学完不代表记住。

## 问题前置：学习前先提问（子主题级必做）

**这是最重要的一步，不可省略。**

当用户明确了要学的子主题时，在生成任何学习内容之前，必须先进入"问题前置"环节。

### 问题前置的目的

- 激活用户已有的认知，避免从零灌输用户已知的内容
- 让用户的好奇心和困惑点成为学习内容的组织主线
- 为后续"验收"提供基准：学完后回头看，哪些问题答了、哪些还没答

### 如何提问

围绕主题，从以下维度主动向用户提问，问题数量不设上限，覆盖所有对学习有价值的角度：

**1. 已有认知探底**
- 你对这个主题目前了解多少？（哪怕一两句话也行）
- 你有没有用过它？遇到过什么效果好或不好的情况？
- 你能描述一下它大概是做什么用的吗？

**2. 问题与困惑收集**
- 你最想搞清楚的是什么？
- 有哪些概念让你觉得很模糊、说不清楚？
- 有没有你见过但没看懂的论文段落、代码或报错？
- 有没有"这两个东西到底有什么区别"的疑问？

**3. 学习目标锚定**
- 学完这个主题，你希望自己能做到什么？（能解释给别人听？能做实验？能设计系统？）
- 你是为了研究、工程落地，还是系统补知识？
- 学完后你打算做什么验证？

**4. 场景与背景锚定**
- 你目前在做什么项目或产品？这个主题和它有关系吗？
- 你最近遇到了什么问题或现象让你想学这个？

**5. 主题专属深挖问题**

根据具体主题补充针对性问题，以下是常见主题示例，实际执行时应根据主题动态生成：

- **Transformer**：你知道 Attention 是干什么用的吗？你知道 Transformer 和 RNN 的区别吗？你知道 Positional Encoding 是什么吗？你知道 Self-Attention 为什么计算量大吗？
- **RAG**：你知道 RAG 是什么缩写吗？你知道为什么不直接 fine-tune 而要用 RAG？你知道 Embedding 和检索是什么关系吗？你知道 Chunk 策略对结果有什么影响吗？
- **Agent**：你知道 Agent 和普通 LLM 调用的区别吗？你知道 Tool Use 是怎么工作的吗？你知道 ReAct 是什么范式吗？你知道 Agent 的主要失败模式是什么吗？
- **Embedding**：你知道 Embedding 是把什么变成什么吗？你知道余弦相似度是怎么用的吗？你知道不同 Embedding 模型的效果差异在哪里吗？
- **Fine-tuning**：你知道 Fine-tuning 和 Prompt Engineering 的区别吗？你知道 LoRA 是什么吗？你知道 Fine-tuning 需要多少数据吗？
- **模型评估**：你知道哪些常见评估指标吗？你知道幻觉（Hallucination）如何定义和衡量吗？

**提问格式要求**：

把所有问题一次性列出，编号呈现。不要分批问，不要先给答案，等用户统一回答后再继续。示例：

```
在开始之前，我想先了解你对这个主题的认知，帮我生成更贴合你需求的学习内容：

1. 你对 RAG 目前了解多少？有没有实际用过？
2. 你最想搞清楚的是什么？（可以列多条）
3. 你知道为什么要用 RAG 而不是直接 fine-tune 吗？
4. 你知道 Embedding 和向量检索是什么关系吗？
5. 你遇到过 RAG 效果差的情况吗？当时是什么现象？
6. 你是为了工程落地还是研究学习？
7. 学完后你希望能做到什么？
8. ...（根据主题继续补充）

请直接回答你知道的、不确定的，不知道的就说不知道，都没关系。
```

### 收到用户回答后

根据用户的回答做以下处理：

1. **识别起点**：用户已经知道什么，不需要从零讲
2. **提炼问题列表**：把用户说出的困惑和想搞清楚的问题整理成"本次学习的问题清单"
3. **调整内容侧重**：用户不懂的地方多讲，已懂的快速确认或跳过
4. **在文档开头放问题清单**：作为学习主线，并在结尾逐一检验是否都回答了

## 默认行为

如果用户只输入一个领域或主题，没有补充更多要求，默认按以下规则执行：

- 学习程度默认使用 `系统深入`
- 学习目标默认包含：`能讲给别人听`、`能实战`、`能画图`
- 子主题级输入：先进入问题前置环节，再生成内容
- 领域级输入：先生成学习地图，等待用户选择子主题

---

## 输入要求

至少明确以下信息；如果用户未明确补充，则使用默认行为：

- 输入层级：`领域` 或 `子主题`
- 学习主题：如 `Transformer`、`RAG`、`Agent`、`Embedding`、`模型评估`
- 学习深度：默认 `deep`
- 学习目标：默认是"能讲给别人听、能实战、能画图"

如果输入的是大领域，如 `AI`、`机器学习`、`LLM`、`Agent`，不要直接展开多篇正文，先产出学习地图，再让用户选择子主题。
如果主题过大，先缩小到一个问题域、一个方法族或一个系统模块。

---

## 输出策略

先判断当前输入属于哪一层：

### 领域级输入

当用户输入的是领域而不是单一主题时，先输出 1 篇 `领域学习地图.md`，不要直接展开多个子主题正文。

`领域学习地图.md` 必须包含：

- 这个领域在学什么
- 为什么值得学
- 适合什么目标的人学习
- 前置知识
- 知识树或主题树
- 推荐学习顺序
- 子主题分级与标签
- 每个子主题解决什么问题
- 哪些主题适合先学
- 下一步可选输出主题

学习地图中的每个子主题都尽量标注以下信息：

- 难度：`入门`、`进阶`、`深入`
- 优先级：`建议优先`、`按需学习`、`可后置`
- 适合目标：如"理解 AI 基础""做 LLM 应用""研究模型机制"
- 前置知识：进入该主题前最好先掌握什么
- 是否可跳过：`否`、`部分可跳过`、`可跳过`
- 产出收益：学完后能解决什么问题

如果用户没有指定子主题，就停在学习地图这一层，等待用户选择下一步。

### 子主题级输入

当用户输入的是明确子主题，如 `Transformer`、`RAG`、`Prompt Engineering`、`模型评估`，先进入问题前置环节，再根据深度输出 `主题总览.md` 或多篇学习包。

## 输出模式

以下模式仅适用于"已经明确子主题"的情况：

### `quick`

输出 1 篇 Markdown 文档，帮助用户快速建立主题认知和边界感。文件名必须使用中文，默认使用 `主题总览.md`。

### `deep`

输出 3~6 篇 Markdown 文档，组成学习包。文件名必须使用中文。默认建议文件：

- `00-学习地图.md`
- `01-背景问题与核心概念.md`
- `02-核心机制与模型结构.md`
- `03-训练推理与系统设计.md`
- `04-评估风险与常见陷阱.md`
- `05-自测与延伸学习.md`

## 文件命名与配图要求

- 所有学习文档统一输出到 `docs/learn/AI/` 目录下。
- 领域级文档默认保存为 `docs/learn/AI/领域学习地图.md`。
- 子主题级文档必须按主题创建子目录，保存到 `docs/learn/AI/[子主题名]/` 下。
- `quick` 模式默认保存为 `docs/learn/AI/[子主题名]/主题总览.md`。
- `deep` 模式默认保存为 `docs/learn/AI/[子主题名]/` 下的多篇结构化文档。
- 输出的 Markdown 文件名必须使用中文，不使用英文语义文件名。
- 文件名可以包含数字前缀以表达学习顺序，如 `00-学习地图.md`、`01-背景问题与核心概念.md`。
- 图示默认优先使用 Mermaid，尤其适用于模型结构图、系统架构图、数据流图、推理流程图、评估框架图和时间线。
- 当 Mermaid 难以表达论文原图、模型结构示意、实验图表或权威框架图时，可以从网络抓取图片辅助讲解。
- 网络图片优先选择论文原文、官方文档、研究机构、模型官方仓库或权威教育资源中的图片。
- 使用网络图片时，必须在文档中标注来源链接、图片用途，并简要说明该图片帮助理解什么。
- 对来源不明、版权不清晰、内容失真或营销性质过强的图片，不要使用；此时退回 Mermaid 或文字说明。

## 通用写作要求

每篇文档都应尽量包含：

- 一句话理解
- 它解决什么问题
- 背景与演进
- 核心机制
- 一个实际案例
- 适用边界与局限
- 自测题

不要只堆模型名和术语。必须解释每个概念在整体问题中的作用。
