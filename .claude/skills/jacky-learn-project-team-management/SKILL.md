# 项目与团队管理学习

围绕项目管理与团队管理主题输出可学习文档，帮助用户理解“目标、协作、节奏、风险、反馈、成长”的管理闭环。

## 学习方法

始终遵循以下方法：

1. 从实际管理问题出发，而不是从术语出发。
2. 先明确目标和约束，再讲流程和方法。
3. 用场景化案例学习，如延期、沟通失真、责任不清、资源冲突。
4. 用框架帮助思考，但必须说明适用边界。
5. 用复盘思维总结经验，形成可迁移的管理判断。
6. 每篇结尾必须有自测题、场景题或复盘题。

## 默认行为

如果用户只输入一个领域或主题，没有补充更多要求，默认按以下规则执行：

- 学习程度默认使用 `系统深入`
- 学习目标默认包含：`能讲给别人听`、`能实战`、`能画图`
- 输出要求默认使用：`先生成学习地图`

因此，除非用户显式修改，否则不需要反复追问“学到什么程度”“学习目标是什么”“是否先出学习地图”。

## 输入要求

至少明确以下信息；如果用户未明确补充，则使用默认行为：

- 输入层级：`领域` 或 `子主题`
- 学习主题：如 `项目计划拆解`、`风险管理`、`跨团队协作`、`一对一沟通`
- 学习深度：默认 `deep`
- 学习目标：默认是“能讲给别人听、能实战、能画图”

如果输入的是大领域，如 `项目管理`、`团队管理`、`跨团队协作`、`管理者成长`，不要直接展开多篇正文，先产出学习地图，再让用户选择子主题。
如果主题过大，优先缩小到一个问题域、一个管理动作或一个典型场景。

## 输出策略

先判断当前输入属于哪一层：

### 领域级输入

当用户输入的是领域而不是单一主题时，先输出 1 篇 `领域学习地图.md`，不要直接展开多个子主题正文。

`领域学习地图.md` 必须包含：

- 这个领域在学什么
- 为什么值得学
- 适合什么目标的人学习
- 前置知识
- 知识树或主题树
- 推荐学习顺序
- 子主题分级与标签
- 每个子主题解决什么问题
- 哪些主题适合先学
- 下一步可选输出主题

学习地图中的每个子主题都尽量标注以下信息：

- 难度：`入门`、`进阶`、`深入`
- 优先级：`建议优先`、`按需学习`、`可后置`
- 适合目标：如“带项目”“带团队”“提升协作”“做管理者成长”
- 前置知识：进入该主题前最好先掌握什么
- 是否可跳过：`否`、`部分可跳过`、`可跳过`
- 产出收益：学完后能解决什么问题

如果用户没有指定子主题，就停在学习地图这一层，等待用户选择下一步。

### 子主题级输入

当用户输入的是明确子主题，如 `风险管理`、`项目计划拆解`、`一对一沟通`、`跨团队协作`，再根据深度输出 `主题总览.md` 或多篇学习包。

## 输出模式

以下模式仅适用于“已经明确子主题”的情况：

### `quick`

输出 1 篇 Markdown 文档，帮助用户快速建立主题框架和行动建议。文件名必须使用中文，默认使用 `主题总览.md`。

### `deep`

输出 3~6 篇 Markdown 文档，组成学习包。文件名必须使用中文。默认建议文件：

- `00-学习地图.md`
- `01-背景核心原则与模型.md`
- `02-项目场景与团队场景.md`
- `03-方法工具与关键决策点.md`
- `04-常见失败与恢复策略.md`
- `05-自测与延伸学习.md`

## 文件命名与配图要求

- 所有学习文档统一输出到 `docs/learn/项目与团队管理/` 目录下。
- 领域级文档默认保存为 `docs/learn/项目与团队管理/领域学习地图.md`。
- 子主题级文档必须按主题创建子目录，保存到 `docs/learn/项目与团队管理/[子主题名]/` 下。
- `quick` 模式默认保存为 `docs/learn/项目与团队管理/[子主题名]/主题总览.md`。
- `deep` 模式默认保存为 `docs/learn/项目与团队管理/[子主题名]/` 下的多篇结构化文档。
- 输出的 Markdown 文件名必须使用中文，不使用英文语义文件名。
- 文件名可以包含数字前缀以表达学习顺序，如 `00-学习地图.md`、`01-背景核心原则与模型.md`。
- 图示默认优先使用 Mermaid，尤其适用于流程图、责任关系图、协作图、风险图、会议机制图和时间线。
- 当 Mermaid 难以表达成熟管理框架图、组织结构图或真实看板示意时，可以从网络抓取图片辅助讲解。
- 网络图片优先选择权威管理资料、公开课程资料、知名咨询框架资料或官方组织发布的图片。
- 使用网络图片时，必须在文档中标注来源链接、图片用途，并简要说明该图片帮助理解什么。
- 对来源不明、版权不清晰、内容失真或营销性质过强的图片，不要使用；此时退回 Mermaid 或文字说明。

## 通用写作要求

每篇文档都应尽量包含：

- 一句话理解
- 这个主题解决什么管理问题
- 背景与演进
- 核心原则或框架
- 一个典型场景
- 常见误区
- 自测题或场景题

不要只讲流程名词。必须补充管理者在真实压力下如何判断和行动。

## 领域专用模块

项目与团队管理主题优先补充以下内容：

- 目标、角色、边界、责任
- 节奏、依赖、沟通、反馈
- 风险识别与升级路径
- 决策点与权衡
- 常见失败模式和恢复策略
- 可执行的会议、文档、机制建议

## 领域质量标准

生成内容时必须做到：

- 对项目管理主题，讲清楚目标、里程碑、依赖、风险、同步机制。
- 对团队管理主题，讲清楚角色期望、反馈机制、培养路径、冲突处理。
- 对方法论内容，必须说明适用边界，不神化框架。
- 对沟通和协作主题，必须补充实际话术、文档或会议动作建议。
- 对风险和复盘主题，必须补充可观察信号与纠偏动作。

## 结尾要求

结尾固定给出：

- 这次学习最值得记住的 3 句话
- 适合马上实践的 1~3 个管理动作
- 下一步建议：继续学什么、做什么复盘、建立什么机制

如果当前输出的是 `领域学习地图.md`，则把结尾改为：

- 建议先学的 1~3 个子主题
- 每个子主题适合的学习目标
- 等待用户选择下一步要展开的主题
