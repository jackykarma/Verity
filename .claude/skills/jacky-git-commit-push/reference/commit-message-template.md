# Commit Message 模板

基于 Commitizen 中文规范的提交信息模板，适用于本项目 Git 提交流程。

## 一、基础格式

```
<类型>(<范围>): <简短描述>

<详细描述>

<Footer>
```

## 二、可复用模板（复制后替换占位符）

```
# 通用模板
<类型>(<范围>): <简短描述，不超过 50 字>

- 变更点 1
- 变更点 2
- 变更点 3

[Closes #<issue>]
[BREAKING CHANGE: 描述不兼容改动]
```

## 三、按类型分列的模板

### 新功能 (feat)

```
feat(<模块>): 添加<功能名称>

- 实现 <核心能力 1>
- 实现 <核心能力 2>
- 更新相关 <UI/逻辑/文档>

Closes #<issue>
```

### Bug 修复 (fix)

```
fix(<模块>): 修复<问题描述>

问题原因: <根因简述>
解决方案: <处理方式>
影响范围: <受影响功能>

Fixes #<issue>
```

### 文档 (docs)

```
docs(<文档/模块>): <更新内容>

- 更新 <章节/说明>
- 新增 <示例/说明>
- 修正 <错误描述>
```

### 样式/格式 (style)

```
style(<模块>): <统一/调整的样式>

- 统一 <组件> 的 <样式属性>
- 调整 <布局/主题> 相关配置
```

### 重构 (refactor)

```
refactor(<模块>): <重构目标>

- 将 <旧实现> 替换为 <新实现>
- 简化 <逻辑/结构>
- 提取公共 <组件/工具>
```

### 性能优化 (perf)

```
perf(<模块>): 优化<性能指标>

- 优化 <具体操作> 的执行效率
- 减少 <资源> 占用
- 测试数据: <指标对比>
```

### 测试 (test)

```
test(<模块>): 添加/修改<测试范围>

- 新增 <测试场景> 单元测试
- 补充 <边界条件> 测试用例
```

### 构建/工具 (chore/build/ci)

```
chore(<范围>): <变更描述>

- 升级 <依赖/工具> 到 <版本>
- 配置 <构建/CI> 相关设置
```

### 回滚 (revert)

```
revert: 撤销 <原提交 hash 或描述>

原提交: <类型>(<范围>): <原描述>
回滚原因: <简述>
```

### 紧急修复 (hotfix)

```
fix(<模块>): 紧急修复<生产环境问题>

- 修复 <崩溃/异常> 问题
- 临时方案: <如适用>

Fixes #<issue>
```

## 四、类型与 Emoji 速查表

| 类型 | Emoji | 说明 |
|------|-------|------|
| feat | ✨ | 新功能 |
| fix | 🐛 | Bug 修复 |
| docs | 📝 | 文档 |
| style | 💄 | 格式/样式 |
| refactor | ♻️ | 重构 |
| perf | ⚡️ | 性能 |
| test | ✅ | 测试 |
| chore | 🔧 | 构建/工具 |
| ui | 🎨 | UI/UX |

## 五、范围参考

- **功能**: `登录`、`支付`、`首页`、`商品详情`
- **技术**: `网络`、`数据库`、`缓存`、`工具`
- **模块**: `用户模块`、`订单模块`、`评论模块`
- **文档**: `README`、`API`、`spec`

## 六、Footer 常用写法

```
Closes #123        # 关闭 Issue
Fixes #456         # 修复 Bug 并关联 Issue
Refs #789          # 仅关联参考
BREAKING CHANGE:   # 不兼容改动，需单独一行说明
```

## 七、Windows 下提交方式（避免中文乱码）

1. 将完整提交信息保存为 UTF-8 文件（如 `.git-msg.txt`）
2. 使用 `-F` 提交：

```bash
git commit -F .git-msg.txt
```

## 八、配置 Git 使用模板（可选）

```bash
git config commit.template docs/template/commit-message-template.md
```

或使用精简版 `.gitmessage`：

```bash
git config commit.template .gitmessage
```

## 九、描述规范

- **简短描述**: 不超过 50 个字符，使用祈使句，描述做了什么
- **详细描述**: 说明为什么做这个改动，改动的影响范围（可选）
- **Footer**: 关闭的 Issue 或 Breaking Changes（可选）

## 十、最佳实践

1. **原子提交**: 每次提交只做一件事
2. **有意义的信息**: 描述"做了什么"和"为什么"，不是"怎么做"
3. **使用中文**: 团队沟通更高效
4. **及时提交**: 完成一个功能点立即提交
