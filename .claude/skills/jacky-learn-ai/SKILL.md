# AI 学习

围绕 AI 主题输出可学习文档，帮助用户建立“问题、范式、原理、实现、评估、限制”的系统认知。

## 学习方法

始终遵循以下方法：

1. 先明确问题类型，再理解对应方法。
2. 先讲直觉和动机，再讲数学、架构或工程实现。
3. 用“输入 -> 表示 -> 计算 -> 输出 -> 评估”的链路组织内容。
4. 用对比学习区分相近方法，如训练/推理、检索/生成、微调/提示、Agent/RAG。
5. 用案例和失败案例帮助理解适用边界。
6. 每篇结尾必须有自测题，并给出下一步实验建议。

## 默认行为

如果用户只输入一个领域或主题，没有补充更多要求，默认按以下规则执行：

- 学习程度默认使用 `系统深入`
- 学习目标默认包含：`能讲给别人听`、`能实战`、`能画图`
- 输出要求默认使用：`先生成学习地图`

因此，除非用户显式修改，否则不需要反复追问“学到什么程度”“学习目标是什么”“是否先出学习地图”。

## 输入要求

至少明确以下信息；如果用户未明确补充，则使用默认行为：

- 输入层级：`领域` 或 `子主题`
- 学习主题：如 `Transformer`、`RAG`、`Agent`、`Embedding`、`模型评估`
- 学习深度：默认 `deep`
- 学习目标：默认是“能讲给别人听、能实战、能画图”

如果输入的是大领域，如 `AI`、`机器学习`、`LLM`、`Agent`，不要直接展开多篇正文，先产出学习地图，再让用户选择子主题。
如果主题过大，先缩小到一个问题域、一个方法族或一个系统模块。

## 输出策略

先判断当前输入属于哪一层：

### 领域级输入

当用户输入的是领域而不是单一主题时，先输出 1 篇 `领域学习地图.md`，不要直接展开多个子主题正文。

`领域学习地图.md` 必须包含：

- 这个领域在学什么
- 为什么值得学
- 适合什么目标的人学习
- 前置知识
- 知识树或主题树
- 推荐学习顺序
- 子主题分级与标签
- 每个子主题解决什么问题
- 哪些主题适合先学
- 下一步可选输出主题

学习地图中的每个子主题都尽量标注以下信息：

- 难度：`入门`、`进阶`、`深入`
- 优先级：`建议优先`、`按需学习`、`可后置`
- 适合目标：如“理解 AI 基础”“做 LLM 应用”“研究模型机制”
- 前置知识：进入该主题前最好先掌握什么
- 是否可跳过：`否`、`部分可跳过`、`可跳过`
- 产出收益：学完后能解决什么问题

如果用户没有指定子主题，就停在学习地图这一层，等待用户选择下一步。

### 子主题级输入

当用户输入的是明确子主题，如 `Transformer`、`RAG`、`Prompt Engineering`、`模型评估`，再根据深度输出 `主题总览.md` 或多篇学习包。

## 输出模式

以下模式仅适用于“已经明确子主题”的情况：

### `quick`

输出 1 篇 Markdown 文档，帮助用户快速建立主题认知和边界感。文件名必须使用中文，默认使用 `主题总览.md`。

### `deep`

输出 3~6 篇 Markdown 文档，组成学习包。文件名必须使用中文。默认建议文件：

- `00-学习地图.md`
- `01-背景问题与核心概念.md`
- `02-核心机制与模型结构.md`
- `03-训练推理与系统设计.md`
- `04-评估风险与常见陷阱.md`
- `05-自测与延伸学习.md`

## 文件命名与配图要求

- 所有学习文档统一输出到 `docs/learn/AI/` 目录下。
- 领域级文档默认保存为 `docs/learn/AI/领域学习地图.md`。
- 子主题级文档必须按主题创建子目录，保存到 `docs/learn/AI/[子主题名]/` 下。
- `quick` 模式默认保存为 `docs/learn/AI/[子主题名]/主题总览.md`。
- `deep` 模式默认保存为 `docs/learn/AI/[子主题名]/` 下的多篇结构化文档。
- 输出的 Markdown 文件名必须使用中文，不使用英文语义文件名。
- 文件名可以包含数字前缀以表达学习顺序，如 `00-学习地图.md`、`01-背景问题与核心概念.md`。
- 图示默认优先使用 Mermaid，尤其适用于模型结构图、系统架构图、数据流图、推理流程图、评估框架图和时间线。
- 当 Mermaid 难以表达论文原图、模型结构示意、实验图表或权威框架图时，可以从网络抓取图片辅助讲解。
- 网络图片优先选择论文原文、官方文档、研究机构、模型官方仓库或权威教育资源中的图片。
- 使用网络图片时，必须在文档中标注来源链接、图片用途，并简要说明该图片帮助理解什么。
- 对来源不明、版权不清晰、内容失真或营销性质过强的图片，不要使用；此时退回 Mermaid 或文字说明。

## 通用写作要求

每篇文档都应尽量包含：

- 一句话理解
- 它解决什么问题
- 背景与演进
- 核心机制
- 一个实际案例
- 适用边界与局限
- 自测题

不要只堆模型名和术语。必须解释每个概念在整体问题中的作用。

## AI 专用模块

AI 主题优先补充以下内容：

- 问题定义和任务形式
- 输入表示与数据形态
- 模型结构或系统结构
- 训练与推理的区别
- 评估指标与失败模式
- 真实应用中的成本、延迟、幻觉、鲁棒性或数据质量问题

## AI 领域质量标准

生成内容时必须做到：

- 讲清楚任务、数据、模型、训练、推理、评估之间的关系。
- 对数学内容，优先解释直觉与作用，再给必要公式。
- 对系统主题，如 RAG、Agent、多模态，优先说明模块边界和信息流。
- 对 LLM 主题，必须补充成本、延迟、上下文窗口、幻觉、评估等现实约束。
- 对新概念，避免把营销词当作技术本质。

## 结尾要求

结尾固定给出：

- 这次学习最值得记住的 3 句话
- 1~3 个适合动手的小实验
- 下一步建议：继续学什么论文、工程模块、评估方法或实践案例

如果当前输出的是 `领域学习地图.md`，则把结尾改为：

- 建议先学的 1~3 个子主题
- 每个子主题适合的学习目标
- 等待用户选择下一步要展开的主题
