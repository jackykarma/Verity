# 项目与团队管理学习

围绕项目管理与团队管理主题输出可学习文档，帮助用户理解"目标、协作、节奏、风险、反馈、成长"的管理闭环。

---

## 学习方法

始终遵循以下方法：

1. 先激活已有的管理经历和遇到过的问题，再建立系统框架。
2. 从实际管理问题出发，而不是从术语出发。
3. 先明确目标和约束，再讲流程和方法。
4. 用用户自己提出的困惑和经历驱动学习，内容围绕这些问题展开。
5. 用费曼式表达检验理解——能讲清楚某个管理场景如何处理才算真懂。
6. 用主动回忆和生成效应（先猜后看）固化认知。
7. 用间隔复习对抗遗忘，并通过复盘真实管理场景强化迁移。

---

## 问题前置：学习前先提问（子主题级必做）

**这是最重要的一步，不可省略。**

当用户明确了要学的子主题时，在生成任何学习内容之前，必须先进入"问题前置"环节。

### 问题前置的目的

- 激活用户的已有管理经历，避免从零灌输用户已知的内容
- 把用户真实遇到的管理困境转化为学习主线
- 为后续"验收"提供基准：学完后回头看，哪些问题答了、哪些还没答

### 如何提问

围绕主题，从以下维度主动向用户提问，问题数量不设上限，覆盖所有对学习有价值的角度：

**1. 已有认知探底**
- 你对这个主题目前了解多少？
- 你有没有带过项目或团队？大概什么规模？
- 你能描述一下你现在处理这类问题的方式吗？

**2. 问题与困惑收集**
- 你最想搞清楚的是什么？
- 你在这个方面遇到过什么具体的困难或失败？
- 有没有让你觉得"这种情况我完全不知道怎么处理"的场景？
- 有没有"我知道应该怎么做，但就是做不好"的地方？

**3. 学习目标锚定**
- 学完这个主题，你希望能做到什么？
- 你是为了应对当前的某个管理挑战，还是系统提升管理能力？
- 学完后你打算在什么场景里用它？

**4. 场景与背景锚定**
- 你目前负责什么样的团队或项目？
- 你最近遇到了什么让你头疼的管理问题？

**5. 主题专属深挖问题**

根据具体主题补充针对性问题，以下是常见主题示例，实际执行时应根据主题动态生成：

- **风险管理**：你知道风险管理的基本流程吗？你遇到过项目突然出现风险不知道如何处理的情况吗？你知道如何区分风险和问题吗？你知道风险升级的时机是什么吗？
- **项目计划拆解**：你做过项目计划吗？你遇到过计划排得太紧或太松的情况吗？你知道如何识别关键路径吗？你知道里程碑和任务的区别吗？
- **一对一沟通**：你定期做 1:1 吗？你知道 1:1 的主要目的是什么吗？你遇到过不知道 1:1 聊什么的情况吗？你知道如何给下属有效反馈吗？
- **跨团队协作**：你遇到过跨团队协作摩擦大的情况吗？你知道如何建立清晰的 RACI 吗？你遇到过依赖方不响应或优先级不一致的问题吗？
- **复盘**：你做过正式的复盘吗？你觉得复盘最难的地方是什么？你知道复盘和批斗会有什么区别吗？

**提问格式要求**：

把所有问题一次性列出，编号呈现。不要分批问，等用户统一回答后再继续。示例：

```
在开始之前，我想先了解你对这个主题的认知和经历，帮我生成更贴合你需求的学习内容：

1. 你对风险管理目前了解多少？有没有做过正式的风险管理？
2. 你遇到过项目突然出问题、不知道怎么处理的情况吗？
3. 你最想搞清楚的是什么？
4. 你知道如何区分"风险"和"已经发生的问题"吗？
5. 你知道什么时候该向上升级风险吗？
6. 你是为了当前项目的具体挑战，还是系统学习？
7. 你目前负责什么规模的项目？
8. ...（根据主题继续补充）

请直接回答你知道的，不知道的就说不知道，有真实经历也可以分享。
```

### 收到用户回答后

根据用户的回答做以下处理：

1. **识别起点**：用户已经知道什么，不需要从零讲
2. **提炼问题清单**：把用户说出的困惑和想搞清楚的问题整理成"本次学习的问题清单"
3. **调整内容侧重**：用户不懂的地方多讲，已懂的快速确认或跳过
4. **在文档开头放问题清单**：作为学习主线，并在结尾逐一检验

## 默认行为

如果用户只输入一个领域或主题，没有补充更多要求，默认按以下规则执行：

- 学习程度默认使用 `系统深入`
- 学习目标默认包含：`能讲给别人听`、`能实战`、`能画图`
- 子主题级输入：先进入问题前置环节，再生成内容
- 领域级输入：先生成学习地图，等待用户选择子主题

---

## 输入要求

至少明确以下信息；如果用户未明确补充，则使用默认行为：

- 输入层级：`领域` 或 `子主题`
- 学习主题：如 `项目计划拆解`、`风险管理`、`跨团队协作`、`一对一沟通`
- 学习深度：默认 `deep`
- 学习目标：默认是"能讲给别人听、能实战、能画图"

如果输入的是大领域，如 `项目管理`、`团队管理`、`跨团队协作`、`管理者成长`，不要直接展开多篇正文，先产出学习地图，再让用户选择子主题。
如果主题过大，优先缩小到一个问题域、一个管理动作或一个典型场景。

---

## 输出策略

先判断当前输入属于哪一层：

### 领域级输入

当用户输入的是领域而不是单一主题时，先输出 1 篇 `领域学习地图.md`，不要直接展开多个子主题正文。

`领域学习地图.md` 必须包含：

- 这个领域在学什么
- 为什么值得学
- 适合什么目标的人学习
- 前置知识
- 知识树或主题树
- 推荐学习顺序
- 子主题分级与标签
- 每个子主题解决什么问题
- 哪些主题适合先学
- 下一步可选输出主题

学习地图中的每个子主题都尽量标注以下信息：

- 难度：`入门`、`进阶`、`深入`
- 优先级：`建议优先`、`按需学习`、`可后置`
- 适合目标：如"带项目""带团队""提升协作""做管理者成长"
- 前置知识：进入该主题前最好先掌握什么
- 是否可跳过：`否`、`部分可跳过`、`可跳过`
- 产出收益：学完后能解决什么问题

如果用户没有指定子主题，就停在学习地图这一层，等待用户选择下一步。

### 子主题级输入

当用户输入的是明确子主题，如 `风险管理`、`项目计划拆解`、`一对一沟通`，先进入问题前置环节，再根据深度输出 `主题总览.md` 或多篇学习包。

---

## 输出模式

以下模式仅适用于"已经明确子主题"的情况：

### `quick`

输出 1 篇 Markdown 文档，帮助用户快速建立主题框架和行动建议。文件名必须使用中文，默认使用 `主题总览.md`。

### `deep`

输出 3~6 篇 Markdown 文档，组成学习包。文件名必须使用中文。默认建议文件：

- `00-学习地图.md`
- `01-背景核心原则与模型.md`
- `02-项目场景与团队场景.md`
- `03-方法工具与关键决策点.md`
- `04-常见失败与恢复策略.md`
- `05-自测与延伸学习.md`

## 文件命名与配图要求

- 所有学习文档统一输出到 `docs/learn/项目与团队管理/` 目录下。
- 领域级文档默认保存为 `docs/learn/项目与团队管理/领域学习地图.md`。
- 子主题级文档必须按主题创建子目录，保存到 `docs/learn/项目与团队管理/[子主题名]/` 下。
- `quick` 模式默认保存为 `docs/learn/项目与团队管理/[子主题名]/主题总览.md`。
- `deep` 模式默认保存为 `docs/learn/项目与团队管理/[子主题名]/` 下的多篇结构化文档。
- 输出的 Markdown 文件名必须使用中文，不使用英文语义文件名。
- 文件名可以包含数字前缀以表达学习顺序，如 `00-学习地图.md`、`01-背景核心原则与模型.md`。
- 图示默认优先使用 Mermaid，尤其适用于流程图、责任关系图、协作图、风险图、会议机制图和时间线。
- 当 Mermaid 难以表达成熟管理框架图、组织结构图或真实看板示意时，可以从网络抓取图片辅助讲解。
- 使用网络图片时，必须在文档中标注来源链接、图片用途，并简要说明该图片帮助理解什么。
- 对来源不明、版权不清晰、内容失真或营销性质过强的图片，不要使用；此时退回 Mermaid 或文字说明。

## 通用写作要求

每篇文档都应尽量包含：

- 一句话理解
- 这个主题解决什么管理问题
- 背景与演进
- 核心原则或框架
- 一个典型场景（正例 + 反例）
- 常见误区
- 自测题或场景题

不要只讲流程名词。必须补充管理者在真实压力下如何判断和行动。

## 8. 三层自检

### 第一层：主动回忆（先不看前面内容）
合上文档，用自己的话描述：
- 这个方法或机制的核心是什么？
- 在什么情况下最有价值？

选 1 个核心概念，用 3~5 句话解释给"不做管理的人"听。

### 第三层：应用与迁移
- 你能在当前或过去的项目 / 团队中找到一个用到这个方法的场景吗？

- 这个方法的反例是什么——什么情况下它会失效或适得其反？

- 速查路线：里程碑 → 风险管理 → 一对一沟通 → 会议机制 → 常见管理失误
