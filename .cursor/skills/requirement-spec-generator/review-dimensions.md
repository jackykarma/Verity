# PRD 评审维度清单

审查时按维度逐项扫描，避免遗漏。每个维度都要问：「这里有没有会让研发误解、返工或无法验收的问题？」

## 3.1 背景与目标

- 需求背景是否说清
- 目标是否可判断是否达成
- 是否缺少业务动机、价值说明
- 是否存在「为了优化体验」但没有定义优化指标

## 3.2 范围与边界

- 做什么写了，什么不做是否写清
- 是否缺少适用范围、非适用范围
- 是否缺少入口、出口、前置条件、终止条件
- 是否缺少边界条件说明

## 3.3 用户、角色与权限

- 谁可以使用是否明确
- 不同角色差异是否明确
- 是否有权限控制但未给规则
- 是否遗漏管理员 / 运营 / 普通用户等不同视角

## 3.4 业务规则

- 触发条件是否清楚
- 处理规则是否清楚
- 优先级、排序、去重、覆盖、失效规则是否明确
- 是否使用了「合理」「适当」「尽快」「相关」等模糊词
- 是否存在多个理解口径

## 3.5 数据定义与口径

- 字段含义是否明确
- 数据来源是否明确
- 新增 / 修改 / 删除的数据项是否完整
- 展示口径、统计口径、时间口径是否一致
- 是否缺少枚举值、单位、格式、精度、默认值

## 3.6 交互与流程

- 主流程是否完整
- 是否缺少异常流程、取消流程、返回流程
- 是否遗漏空状态、加载态、失败态、无权限态
- 是否缺少用户操作反馈
- 页面跳转、弹窗、提示文案是否清楚

## 3.7 异常与边界场景

- 网络异常怎么处理
- 数据为空怎么处理
- 重复提交怎么处理
- 并发 / 冲突 / 过期 / 回退怎么处理
- 超长文本、极值、非法输入、老数据兼容是否说明

## 3.8 依赖与约束

- 是否依赖其他团队、接口、配置、活动、策略
- 外部依赖是否已经就绪
- 是否有版本限制、灰度限制、平台限制
- 是否缺少上线条件和协作前提

## 3.9 验收标准

- 是否能判断「做完算成功」
- 是否有可验证、可测试、可回归的标准
- 是否存在「主观验收」而非「客观验收」
- 是否缺少埋点、日志、监控、风控等验收配套

## 3.10 一致性与冲突

- 前后描述是否矛盾
- 术语是否统一
- 图文是否一致
- 与现有产品逻辑是否冲突
- 一个地方说 A，另一个地方像是在说非 A
