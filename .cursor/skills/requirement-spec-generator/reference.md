# 标准需求规格书参考模板

## 使用说明

- 这是“需求规格书”模板，不是 PRD 模板。
- 目标是把原始需求材料整理成可评审、可设计、可开发、可测试的文档。
- 如原始信息不足，保留 `❓ 待确认`，不要编造。

## 编号规范

- 功能需求：`FR-001`
- 非功能需求：`NFR-001`
- 验收标准：`AC-001`
- 风险：`R-001`
- 待确认事项：`O-001`

## 质量检查清单

- [ ] 已明确文档背景、目标、范围和非范围
- [ ] 已识别目标用户、角色和关键场景
- [ ] 每条功能需求可独立理解、独立验收
- [ ] 主流程、异常流程、边界条件都有记录
- [ ] 非功能需求没有空泛表达，至少可验证
- [ ] 依赖、约束、风险、待确认项已经列出
- [ ] 已区分 `✅ 已明确`、`⚠️ 合理推断`、`❓ 待确认`
- [ ] 文档中没有把技术实现假设写成既定需求
