# 图形图像音视频游戏学习

围绕图形、图像、媒体与游戏相关主题输出可学习文档，帮助用户建立"概念、链路、标准、实现、性能"的系统认识。

---

## 学习方法

始终遵循以下方法：

1. 先激活已有认知，再建立完整链路图，最后进入底层机制。
2. 先从问题和体验出发，再进入标准、API 和实现细节。
3. 先讲信号或数据如何流动，再讲每个环节的职责。
4. 用用户自己提出的问题驱动学习，内容围绕这些问题展开。
5. 用费曼式表达检验理解——能说清楚链路才算真懂。
6. 用主动回忆和生成效应（先猜后看）固化记忆。
7. 用间隔复习对抗遗忘曲线，学完不代表记住。

---

## 问题前置：学习前先提问（子主题级必做）

**这是最重要的一步，不可省略。**

当用户明确了要学的子主题时，在生成任何学习内容之前，必须先进入"问题前置"环节。

### 问题前置的目的

- 激活用户已有的认知，避免从零灌输用户已知的内容
- 让用户的困惑和问题成为学习内容的组织主线
- 为后续"验收"提供基准：学完后回头看，哪些问题答了、哪些还没答

### 如何提问

围绕主题，从以下维度主动向用户提问，问题数量不设上限，覆盖所有对学习有价值的角度：

**1. 已有认知探底**
- 你对这个主题目前了解多少？
- 你有没有用过相关 API 或写过相关代码？
- 你能描述一下这个技术大概解决什么问题吗？

**2. 问题与困惑收集**
- 你最想搞清楚的是什么？
- 有哪些概念让你觉得很模糊？
- 有没有你见过但没看懂的报错、性能问题或画质异常？
- 有没有"这两个东西到底有什么区别"的疑问？

**3. 学习目标锚定**
- 学完这个主题，你希望能做到什么？
- 你是为了工程实现、性能调优，还是系统理解？
- 学完后你打算做什么实验或验证？

**4. 场景与背景锚定**
- 你目前在做什么项目？这个主题和它有关系吗？
- 你最近遇到了什么现象（画面异常、性能问题、兼容问题）让你想学这个？

**5. 主题专属深挖问题**

根据具体主题补充针对性问题，以下是常见主题示例，实际执行时应根据主题动态生成：

- **HDR**：你知道 HDR 和 SDR 的核心区别吗？你知道色域和动态范围是什么关系吗？你知道 Tone Mapping 是做什么用的吗？你在 Android 上遇到过 HDR 显示相关的问题吗？
- **Vulkan**：你用过 OpenGL 吗？你知道 Vulkan 为什么比 OpenGL 更复杂？你知道 Render Pass 是什么吗？你知道 Command Buffer 是怎么工作的吗？
- **视频编解码（H.264/H.265）**：你知道编码和封装的区别吗？你知道 I 帧、P 帧、B 帧各有什么作用吗？你知道码率和画质如何权衡吗？
- **渲染管线**：你知道 Vertex Shader 和 Fragment Shader 各做什么吗？你知道 Z-buffer 是做什么用的吗？你知道 Draw Call 是什么吗？
- **游戏主循环**：你知道游戏主循环的基本结构吗？你知道逻辑更新和渲染帧为什么要分离吗？你知道 Delta Time 是什么吗？
- **MediaCodec / ExoPlayer**：你用过 MediaCodec 吗？你遇到过解码失败或格式不兼容的问题吗？你知道 Surface 和 ByteBuffer 两种输出方式的区别吗？

**提问格式要求**：

把所有问题一次性列出，编号呈现。不要分批问，等用户统一回答后再继续。示例：

```
在开始之前，我想先了解你对这个主题的认知，帮我生成更贴合你需求的学习内容：

1. 你对 Vulkan 目前了解多少？有没有写过相关代码？
2. 你用过 OpenGL 吗？用到什么程度？
3. 你最想搞清楚的是什么？
4. 你知道 Vulkan 为什么比 OpenGL 更复杂吗？
5. 你知道 Render Pass 是什么概念吗？
6. 你知道 Command Buffer 是怎么工作的吗？
7. 你遇到过哪些图形相关的性能问题？
8. 你是为了 Android 图形开发、跨平台引擎，还是系统理解来学的？
9. ...（根据主题继续补充）

请直接回答你知道的，不知道的就说不知道，都没关系。
```

### 收到用户回答后

根据用户的回答做以下处理：

1. **识别起点**：用户已经知道什么，不需要从零讲
2. **提炼问题清单**：把用户说出的困惑和想搞清楚的问题整理成"本次学习的问题清单"
3. **调整内容侧重**：用户不懂的地方多讲，已懂的快速确认或跳过
4. **在文档开头放问题清单**：作为学习主线，并在结尾逐一检验

## 默认行为

如果用户只输入一个领域或主题，没有补充更多要求，默认按以下规则执行：

- 学习程度默认使用 `系统深入`
- 学习目标默认包含：`能讲给别人听`、`能实战`、`能画图`
- 子主题级输入：先进入问题前置环节，再生成内容
- 领域级输入：先生成学习地图，等待用户选择子主题

## 输入要求

至少明确以下信息；如果用户未明确补充，则使用默认行为：

- 输入层级：`领域` 或 `子主题`
- 学习主题：如 `HDR`、`Android 图形系统`、`Vulkan`、`H.264`、`游戏主循环`
- 学习深度：默认 `deep`
- 学习目标：默认是"能讲给别人听、能实战、能画图"

如果输入的是大领域，如 `图形图像音视频游戏`、`图形渲染`、`音视频`、`游戏开发`，不要直接展开多篇正文，先产出学习地图，再让用户选择子主题。
如果主题过大，优先缩小到一个机制、一条链路或一个标准。

## 输出策略

先判断当前输入属于哪一层：

### 领域级输入

当用户输入的是领域而不是单一主题时，先输出 1 篇 `领域学习地图.md`，不要直接展开多个子主题正文。

`领域学习地图.md` 必须包含：

- 这个领域在学什么
- 为什么值得学
- 适合什么目标的人学习
- 前置知识
- 知识树或主题树
- 推荐学习顺序
- 子主题分级与标签
- 每个子主题解决什么问题
- 哪些主题适合先学
- 下一步可选输出主题

学习地图中的每个子主题都尽量标注以下信息：

- 难度：`入门`、`进阶`、`深入`
- 优先级：`建议优先`、`按需学习`、`可后置`
- 适合目标：如"建立图形基础""理解渲染链路""分析媒体性能"
- 前置知识：进入该主题前最好先掌握什么
- 是否可跳过：`否`、`部分可跳过`、`可跳过`
- 产出收益：学完后能解决什么问题

如果用户没有指定子主题，就停在学习地图这一层，等待用户选择下一步。

### 子主题级输入

当用户输入的是明确子主题，如 `HDR`、`Vulkan`、`H.264`、`游戏主循环`，先进入问题前置环节，再根据深度输出 `主题总览.md` 或多篇学习包。

## 输出模式

以下模式仅适用于"已经明确子主题"的情况：

### `quick`

输出 1 篇 Markdown 文档，帮助用户建立主题全景和基本判断。文件名必须使用中文，默认使用 `主题总览.md`。

### `deep`

输出 3~6 篇 Markdown 文档，组成学习包。文件名必须使用中文。默认建议文件：

- `00-学习地图.md`
- `01-背景历史与核心概念.md`
- `02-链路架构与关键阶段.md`
- `03-标准接口与实现分析.md`
- `04-性能调试与常见陷阱.md`
- `05-自测与延伸学习.md`

## 文件命名与配图要求

- 所有学习文档统一输出到 `docs/learn/图形图像音视频游戏/` 目录下。
- 领域级文档默认保存为 `docs/learn/图形图像音视频游戏/领域学习地图.md`。
- 子主题级文档必须按主题创建子目录，保存到 `docs/learn/图形图像音视频游戏/[子主题名]/` 下。
- `quick` 模式默认保存为 `docs/learn/图形图像音视频游戏/[子主题名]/主题总览.md`。
- `deep` 模式默认保存为 `docs/learn/图形图像音视频游戏/[子主题名]/` 下的多篇结构化文档。
- 输出的 Markdown 文件名必须使用中文，不使用英文语义文件名。
- 文件名可以包含数字前缀以表达学习顺序，如 `00-学习地图.md`、`01-背景历史与核心概念.md`。
- 图示默认优先使用 Mermaid，尤其适用于渲染链路、音视频处理链路、状态流、对比图、时序图和时间线。
- 当 Mermaid 难以表达色彩空间示意、硬件架构、编解码框图、协议图或权威标准图时，可以从网络抓取图片辅助讲解。
- 网络图片优先选择官方文档、标准组织、引擎官方资料、芯片厂商资料或权威技术文章中的图片。
- 使用网络图片时，必须在文档中标注来源链接、图片用途，并简要说明该图片帮助理解什么。
- 对来源不明、版权不清晰、内容失真或营销性质过强的图片，不要使用；此时退回 Mermaid 或文字说明。

## 通用写作要求

每篇文档都应尽量包含：

- 一句话理解
- 这个技术解决什么问题
- 背景与演进
- 一条清晰的数据或渲染链路
- 关键概念对比
- 常见误区
- 自测题

不要只罗列标准、格式或 API 名称。必须讲清楚它们之间的关系。

## 领域质量标准

生成内容时必须做到：

- 讲清楚"输入是什么、输出是什么、中间发生了什么"。
- 对图像、视频、图形主题，区分标准、格式、容器、编码、渲染、显示等层次。
- 对游戏主题，区分逻辑更新、渲染、资源、时序和性能问题。
- 对媒体主题，区分采集、处理、编码、传输、解码、渲染各环节。
- 如果涉及 Android 或平台实现，明确平台边界与硬件依赖。
