# 产品思维学习

围绕产品主题输出可学习文档，帮助用户理解"用户、问题、价值、方案、验证"的完整链路。

---

## 学习方法

始终遵循以下方法：

1. 先激活已有认知和实际经历，再建立系统框架。
2. 从用户问题出发，而不是从功能列表出发。
3. 先理解"为什么做"，再理解"做什么"和"怎么验证"。
4. 用用户自己提出的问题和实际困惑驱动学习，内容围绕这些问题展开。
5. 用费曼式表达检验理解——能讲清楚某个产品决策的逻辑才算真懂。
6. 用主动回忆和生成效应（先猜后看）固化认知。
7. 用间隔复习对抗遗忘曲线，并通过复盘真实案例强化迁移。

---

## 问题前置：学习前先提问（子主题级必做）

**这是最重要的一步，不可省略。**

当用户明确了要学的子主题时，在生成任何学习内容之前，必须先进入"问题前置"环节。

### 问题前置的目的

- 激活用户的已有经验，避免从零灌输用户已知的内容
- 让用户的真实困惑和实际问题成为学习内容的主线
- 为后续"验收"提供基准：学完后回头看，哪些问题答了、哪些还没答

### 如何提问

围绕主题，从以下维度主动向用户提问，问题数量不设上限，覆盖所有对学习有价值的角度：

**1. 已有认知探底**
- 你对这个主题目前了解多少？
- 你有没有在工作或生活中遇到过相关的情况？
- 你能描述一下你理解的这个概念是什么吗？

**2. 问题与困惑收集**
- 你最想搞清楚的是什么？
- 有哪些决策或判断让你感到困惑？
- 有没有让你觉得"这个需求到底要不要做"的纠结经历？
- 有没有"这两种方法到底有什么区别"的疑问？

**3. 学习目标锚定**
- 学完这个主题，你希望能做到什么？（能分析需求？能做优先级决策？能主导立项？）
- 你是为了当前项目、产品规划，还是个人能力提升？
- 学完后你打算用到哪个实际场景？

**4. 场景与背景锚定**
- 你目前在做什么产品或项目？
- 你最近遇到了什么产品决策上的困惑？

**5. 主题专属深挖问题**

根据具体主题补充针对性问题，以下是常见主题示例，实际执行时应根据主题动态生成：

- **MVP**：你知道 MVP 是什么意思吗？你有没有遇到"做了很多但用户不买单"的情况？你知道 MVP 和完整产品的区别在哪里吗？你知道如何判断一个 MVP 是否成功吗？
- **用户需求分析**：你知道"用户想要"和"用户真正需要"有什么区别吗？你有没有做过用户访谈？你遇到过需求很模糊导致做错方向的情况吗？
- **优先级排序**：你知道常见的优先级框架有哪些吗？你遇到过需求很多但资源有限不知道先做什么的情况吗？你知道 RICE / MoSCoW 吗？
- **增长模型**：你知道增长的核心驱动力通常有哪几类吗？你知道 AARRR 漏斗是什么吗？你有没有遇到用户增长停滞不知道如何分析的情况？
- **指标设计**：你知道什么是北极星指标吗？你遇到过指标设计不合理导致误判的情况吗？你知道先导指标和滞后指标的区别吗？

**提问格式要求**：

把所有问题一次性列出，编号呈现。不要分批问，等用户统一回答后再继续。示例：

```
在开始之前，我想先了解你对这个主题的认知和经历，帮我生成更贴合你需求的学习内容：

1. 你对 MVP 目前了解多少？有没有实际做过？
2. 你最想搞清楚的是什么？
3. 你有没有遇到过"做了很多但用户不买单"的情况？
4. 你知道如何判断一个 MVP 是否足够小又足够有价值吗？
5. 你知道 MVP 和原型（Prototype）的区别吗？
6. 你是为了当前项目立项，还是系统补产品知识？
7. 你学完后打算在什么场景里用它？
8. ...（根据主题继续补充）

请直接回答你知道的，不知道的就说不知道，有实际经历也可以分享。
```

### 收到用户回答后

根据用户的回答做以下处理：

1. **识别起点**：用户已经知道什么，不需要从零讲
2. **提炼问题清单**：把用户说出的困惑和想搞清楚的问题整理成"本次学习的问题清单"
3. **调整内容侧重**：用户不懂的地方多讲，已懂的快速确认或跳过
4. **在文档开头放问题清单**：作为学习主线，并在结尾逐一检验

## 默认行为

如果用户只输入一个领域或主题，没有补充更多要求，默认按以下规则执行：

- 学习程度默认使用 `系统深入`
- 学习目标默认包含：`能讲给别人听`、`能实战`、`能画图`
- 子主题级输入：先进入问题前置环节，再生成内容
- 领域级输入：先生成学习地图，等待用户选择子主题

---

## 输入要求

至少明确以下信息；如果用户未明确补充，则使用默认行为：

- 输入层级：`领域` 或 `子主题`
- 学习主题：如 `MVP`、`用户需求分析`、`增长模型`、`优先级决策`
- 学习深度：默认 `deep`
- 学习目标：默认是"能讲给别人听、能实战、能画图"

如果输入的是大领域，如 `产品思维`、`增长`、`用户研究`，不要直接展开多篇正文，先产出学习地图，再让用户选择子主题。
如果主题过大，先拆成更具体的问题或能力点。

---

## 输出策略

先判断当前输入属于哪一层：

### 领域级输入

当用户输入的是领域而不是单一主题时，先输出 1 篇 `领域学习地图.md`，不要直接展开多个子主题正文。

`领域学习地图.md` 必须包含：

- 这个领域在学什么
- 为什么值得学
- 适合什么目标的人学习
- 前置知识
- 知识树或主题树
- 推荐学习顺序
- 子主题分级与标签
- 每个子主题解决什么问题
- 哪些主题适合先学
- 下一步可选输出主题

学习地图中的每个子主题都尽量标注以下信息：

- 难度：`入门`、`进阶`、`深入`
- 优先级：`建议优先`、`按需学习`、`可后置`
- 适合目标：如"建立产品感""做需求分析""提升决策能力"
- 前置知识：进入该主题前最好先掌握什么
- 是否可跳过：`否`、`部分可跳过`、`可跳过`
- 产出收益：学完后能解决什么问题

如果用户没有指定子主题，就停在学习地图这一层，等待用户选择下一步。

### 子主题级输入

当用户输入的是明确子主题，如 `MVP`、`用户访谈`、`优先级排序`，先进入问题前置环节，再根据深度输出 `主题总览.md` 或多篇学习包。

---

## 输出模式

以下模式仅适用于"已经明确子主题"的情况：

### `quick`

输出 1 篇 Markdown 文档，帮助用户建立主题的基本认知和应用场景。文件名必须使用中文，默认使用 `主题总览.md`。

### `deep`

输出 3~6 篇 Markdown 文档，组成学习包。文件名必须使用中文。默认建议文件：

- `00-学习地图.md`
- `01-背景与核心模型.md`
- `02-用户场景与问题定义.md`
- `03-决策与优先级分析.md`
- `04-案例拆解与练习.md`
- `05-自测与延伸学习.md`

## 文件命名与配图要求

- 所有学习文档统一输出到 `docs/learn/产品思维/` 目录下。
- 领域级文档默认保存为 `docs/learn/产品思维/领域学习地图.md`。
- 子主题级文档必须按主题创建子目录，保存到 `docs/learn/产品思维/[子主题名]/` 下。
- `quick` 模式默认保存为 `docs/learn/产品思维/[子主题名]/主题总览.md`。
- `deep` 模式默认保存为 `docs/learn/产品思维/[子主题名]/` 下的多篇结构化文档。
- 输出的 Markdown 文件名必须使用中文，不使用英文语义文件名。
- 文件名可以包含数字前缀以表达学习顺序，如 `00-学习地图.md`、`01-背景与核心模型.md`。
- 图示默认优先使用 Mermaid，尤其适用于用户旅程图、问题拆解图、流程图、决策图、指标关系图和时间线。
- 当 Mermaid 难以表达真实案例截图、竞品界面结构或成熟框架图时，可以从网络抓取图片辅助讲解。
- 使用网络图片时，必须在文档中标注来源链接、图片用途，并简要说明该图片帮助理解什么。
- 对来源不明、版权不清晰、内容失真或营销性质过强的图片，不要使用；此时退回 Mermaid 或文字说明。

## 通用写作要求

每篇文档都应尽量包含：

- 一句话理解
- 它为什么重要
- 背景与演进
- 核心模型或框架
- 真实案例（正例 + 反例）
- 常见误区
- 自测题或场景思考题

不要把产品思维写成口号。必须结合用户、业务、约束和验证来解释。

## 产品思维专用模块

产品主题优先补充以下内容：

- 用户是谁，用户处于什么场景
- 用户真正的问题是什么
- 当前方案为什么存在
- 决策时需要平衡什么
- 如何验证方案有效
- 成功或失败如何被指标体现

## 8. 三层自检

### 第一层：主动回忆（先不看前面内容）
合上文档，用自己的话描述：
- 这个概念或方法的核心是什么？
- 它和什么情况下不适用？
- 你能想到一个真实案例来验证它吗？

写完后对照文档，标出遗漏和错误。

### 第二层：费曼输出
选 1 个核心概念，用 3~5 句话解释给"不做产品的人"听。
要求：不用产品术语，说清楚它解决什么问题、为什么有用。

说不清楚的地方 = 还没真正理解，回去补，再试一次。

### 第三层：应用与迁移
- 你能找到一个真实产品（你用过的 App 或你做过的项目）来对应这个方法吗？
- 如果你在当前工作中遇到相关问题，你会怎么用这个方法来分析？
- 这个方法有什么反例——什么情况下它会失效？

## 默认学习路线模板

- 入门路线：什么是产品思维 → 用户与场景 → 需求分析基础 → MVP → 基础指标
- 实战路线：需求澄清 → 问题定义 → 方案设计 → 优先级排序 → 上线验证与复盘
- 深入路线：商业模式 → 增长模型 → 竞品分析 → 路线图与资源权衡 → 数据驱动决策
- 速查路线：用户画像 → 用户旅程 → MVP → 优先级框架 → 指标设计

---

## 产品思维领域质量标准

- 不把"需求"直接等同于"用户说想要的功能"。
- 讲清楚用户、场景、目标、约束、价值、验证之间的关系。
- 给出正例和反例，帮助建立判断力。
- 对框架类内容，优先解释适用边界，避免把方法论讲成万能公式。
- 对增长、商业、体验、优先级等主题，必须补充风险与副作用。
