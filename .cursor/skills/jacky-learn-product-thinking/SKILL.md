# 产品思维学习

围绕产品主题输出可学习文档，帮助用户理解“用户、问题、价值、方案、验证”的完整链路。

## 学习方法

始终遵循以下方法：

1. 从用户问题出发，而不是从功能列表出发。
2. 先理解“为什么做”，再理解“做什么”和“怎么验证”。
3. 用案例和反例学习抽象概念，避免空泛理论。
4. 用结构化拆解学习复杂问题：用户、场景、目标、约束、方案、指标。
5. 用主动回忆和复盘固化认知，每篇必须有自测题或思考题。
6. 深入模式必须包含“概念 -> 框架 -> 案例 -> 练习”的闭环。

## 默认行为

如果用户只输入一个领域或主题，没有补充更多要求，默认按以下规则执行：

- 学习程度默认使用 `系统深入`
- 学习目标默认包含：`能讲给别人听`、`能实战`、`能画图`
- 输出要求默认使用：`先生成学习地图`

因此，除非用户显式修改，否则不需要反复追问“学到什么程度”“学习目标是什么”“是否先出学习地图”。

## 输入要求

至少明确以下信息；如果用户未明确补充，则使用默认行为：

- 输入层级：`领域` 或 `子主题`
- 学习主题：如 `MVP`、`用户需求分析`、`增长模型`、`优先级决策`
- 学习深度：默认 `deep`
- 学习目标：默认是“能讲给别人听、能实战、能画图”

如果输入的是大领域，如 `产品思维`、`增长`、`用户研究`，不要直接展开多篇正文，先产出学习地图，再让用户选择子主题。
如果主题过大，先拆成更具体的问题或能力点。

## 输出策略

先判断当前输入属于哪一层：

### 领域级输入

当用户输入的是领域而不是单一主题时，先输出 1 篇 `领域学习地图.md`，不要直接展开多个子主题正文。

`领域学习地图.md` 必须包含：

- 这个领域在学什么
- 为什么值得学
- 适合什么目标的人学习
- 前置知识
- 知识树或主题树
- 推荐学习顺序
- 子主题分级与标签
- 每个子主题解决什么问题
- 哪些主题适合先学
- 下一步可选输出主题

学习地图中的每个子主题都尽量标注以下信息：

- 难度：`入门`、`进阶`、`深入`
- 优先级：`建议优先`、`按需学习`、`可后置`
- 适合目标：如“建立产品感”“做需求分析”“提升决策能力”
- 前置知识：进入该主题前最好先掌握什么
- 是否可跳过：`否`、`部分可跳过`、`可跳过`
- 产出收益：学完后能解决什么问题

如果用户没有指定子主题，就停在学习地图这一层，等待用户选择下一步。

### 子主题级输入

当用户输入的是明确子主题，如 `MVP`、`用户访谈`、`优先级排序`，再根据深度输出 `主题总览.md` 或多篇学习包。

## 输出模式

以下模式仅适用于“已经明确子主题”的情况：

### `quick`

输出 1 篇 Markdown 文档，帮助用户建立主题的基本认知和应用场景。文件名必须使用中文，默认使用 `主题总览.md`。

### `deep`

输出 3~6 篇 Markdown 文档，组成学习包。文件名必须使用中文。默认建议文件：

- `00-学习地图.md`
- `01-背景与核心模型.md`
- `02-用户场景与问题定义.md`
- `03-决策与优先级分析.md`
- `04-案例拆解与练习.md`
- `05-自测与延伸学习.md`

## 文件命名与配图要求

- 所有学习文档统一输出到 `docs/learn/产品思维/` 目录下。
- 领域级文档默认保存为 `docs/learn/产品思维/领域学习地图.md`。
- 子主题级文档必须按主题创建子目录，保存到 `docs/learn/产品思维/[子主题名]/` 下。
- `quick` 模式默认保存为 `docs/learn/产品思维/[子主题名]/主题总览.md`。
- `deep` 模式默认保存为 `docs/learn/产品思维/[子主题名]/` 下的多篇结构化文档。
- 输出的 Markdown 文件名必须使用中文，不使用英文语义文件名。
- 文件名可以包含数字前缀以表达学习顺序，如 `00-学习地图.md`、`01-背景与核心模型.md`。
- 图示默认优先使用 Mermaid，尤其适用于用户旅程图、问题拆解图、流程图、决策图、指标关系图和时间线。
- 当 Mermaid 难以表达真实案例截图、竞品界面结构或成熟框架图时，可以从网络抓取图片辅助讲解。
- 网络图片优先选择官方文档、知名产品博客、权威课程资料或研究报告中的图片。
- 使用网络图片时，必须在文档中标注来源链接、图片用途，并简要说明该图片帮助理解什么。
- 对来源不明、版权不清晰、内容失真或营销性质过强的图片，不要使用；此时退回 Mermaid 或文字说明。

## 通用写作要求

每篇文档都应尽量包含：

- 一句话理解
- 它为什么重要
- 背景与演进
- 核心模型或框架
- 真实案例
- 常见误区
- 自测题

不要把产品思维写成口号。必须结合用户、业务、约束和验证来解释。

## 产品思维专用模块

产品主题优先补充以下内容：

- 用户是谁，用户处于什么场景
- 用户真正的问题是什么
- 当前方案为什么存在
- 决策时需要平衡什么
- 如何验证方案有效
- 成功或失败如何被指标体现

## 产品思维领域质量标准

生成内容时必须做到：

- 不把“需求”直接等同于“用户说想要的功能”。
- 讲清楚用户、场景、目标、约束、价值、验证之间的关系。
- 给出正例和反例，帮助建立判断力。
- 对框架类内容，优先解释适用边界，避免把方法论讲成万能公式。
- 对增长、商业、体验、优先级等主题，必须补充风险与副作用。

## 结尾要求

结尾固定给出：

- 这次学习最值得记住的 3 句话
- 适合立刻实践的 1~3 个小练习
- 下一步建议：继续学什么、观察什么产品、做什么复盘

如果当前输出的是 `领域学习地图.md`，则把结尾改为：

- 建议先学的 1~3 个子主题
- 每个子主题适合的学习目标
- 等待用户选择下一步要展开的主题
