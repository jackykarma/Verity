# Feature Tree Generator

梳理并生成目标业务或功能的**完整功能树**，以层级结构展示所有功能节点及其上下级关系。

产出物可直接用于：
- 产品功能全景评审
- 新人快速了解产品功能边界
- 需求规划与优先级排期
- 功能缺口识别（已有哪些、缺少哪些）
- 技术方案拆解的起点

---

## 两种梳理粒度

| 粒度 | 说明 | 输入示例 | 输出示例 |
|------|------|----------|----------|
| **业务级功能树** | 一个产品/模块下所有一级功能及其子功能 | "梳理相机 App 的功能树" | 拍摄 → 录制 → 编辑 → 分享 → 设置... |
| **功能级功能树** | 某一具体功能内部的所有子功能与操作项 | "梳理编辑功能的功能树" | 编辑 → 滤镜 / 裁剪 / 旋转 / 调色 / 文字... |

两种粒度使用相同的流程与文档格式，差异仅在于根节点的层级定义。

---

## 信源模式识别（首先确认）

| 条件 | 模式 |
|------|------|
| 存在 `spec.md`、`epic.md`、PRD 文档 | **文档驱动模式** |
| 存在已有代码，无规范文档 | **代码逆向模式** |
| 用户口述或头脑风暴 | **口述构建模式** |
| 上述混合 | **混合模式**（优先文档，代码补充，口述补全） |

---

## 梳理流程

### 步骤 1：确认范围与粒度

向用户确认（如未明确）：
1. **目标**：是业务级（整个产品/模块）还是功能级（某一功能内部）？
2. **深度**：要展开到第几层？（建议不超过 4 层，否则用子树分拆）
3. **用途**：全景概览 / 缺口分析 / 需求规划 / 技术拆解？

---

### 步骤 2：信源收集

#### 文档驱动模式
按以下顺序读取：
1. `epic.md`（EPIC 概述与 Feature 列表）→ 确定一级功能节点
2. 各 Feature 的 `spec.md`（FR 章节）→ 提取二级/三级功能点
3. `ux-design.md`（交互规则）→ 补充隐性功能（状态、反馈、边界操作）

#### 代码逆向模式
读码顺序（外→内）：
```
① 导航图 / 路由定义（NavGraph、DeepLink）
   → 识别顶层页面/功能入口
        ↓
② Fragment / Screen 级别的 UI 结构
   → 识别页面内的功能区块与操作入口
        ↓
③ ViewModel 的公开方法与 StateFlow/LiveData
   → 识别每个功能区块对应的业务能力
        ↓
④ UseCase / Domain 层
   → 识别业务规则、子流程、分支条件
```

重点搜索：
- 菜单项定义、BottomSheet、Toolbar Action
- 枚举类（功能类型、操作类型）
- Feature Flag 与功能开关

#### 口述构建模式
按以下维度引导用户梳理：
1. **用户能做什么**（动作视角：拍照、裁剪、分享...）
2. **系统提供什么**（能力视角：存储、权限管理、推送...）
3. **有什么设置**（配置视角：隐私、通知、账号...）
4. **有什么流程**（场景视角：注册流程、购买流程...）

---

### 步骤 3：功能节点分类与命名规范

每个功能节点包含：
- **节点名称**：动词+名词（如「裁剪图片」）或名词（如「滤镜」）
- **节点类型**：功能区块 / 具体功能 / 操作项 / 配置项 / 系统能力
- **状态标注**（可选）：✅ 已实现 / 🚧 开发中 / ⬜ 规划中 / ❌ 已废弃

**命名原则：**
- 使用用户语言（产品语言），而非代码实现语言
- ✅ "滤镜" 而非 "ImageFilterProcessor"
- ✅ "分享到朋友圈" 而非 "ShareToWechatMoments"
- 同级节点粒度保持一致，避免混合"功能区块"与"操作项"

---

### 步骤 4：构建功能树结构

将收集到的节点按层级组织：

```
[根节点]（产品/业务/功能名称）
├── [一级功能]
│   ├── [二级子功能]
│   │   ├── [三级操作项]
│   │   └── [三级操作项]
│   └── [二级子功能]
├── [一级功能]
│   └── ...
└── [一级功能]
```

**层级定义建议：**

| 层级 | 业务级功能树 | 功能级功能树 |
|------|------------|------------|
| 第 1 层 | 产品模块（如：相机、相册、编辑） | 功能区块（如：基础编辑、高级编辑） |
| 第 2 层 | 具体功能（如：拍照、录制、变焦） | 具体子功能（如：滤镜、裁剪、旋转） |
| 第 3 层 | 子功能或操作项 | 操作项或参数项 |
| 第 4 层 | 细节操作项 | 参数选项或变体 |

---

### 步骤 5：生成文档

按[文档模板](#文档模板)生成 **`功能树.md`**（文件名须为中文），保存到对应目录：
- 业务级：`docs/project/[模块中文名]/功能树.md`
- 功能级：`docs/project/features/[功能中文名]/功能树.md`
- 无项目上下文时：直接在对话中输出，不强制写文件

---

## Mermaid 图表规范

- 层级 ≤ 3 层：使用 `mindmap`（结构清晰、易读）
- 层级 > 3 层或节点 > 30 个：拆为多张子树图，每张对应一个一级功能
- 所有图表使用项目标准 init 块（见 CLAUDE.md 图表规范）

**mindmap 节点形状参考：**
```
root((圆形根节点))
  普通节点
    [方框节点]
    (圆角方框)
    ((圆形))
```

---

## 实施规范

### 禁止事项

- 用代码类名、方法名作为功能节点名称
- 同级节点粒度差异过大（如"拍照"与"JPEG 压缩质量设置"并列）
- 节点层级超过 4 层（应拆分为子功能树）
- 遗漏说明文档中明确提及的功能
- 在未读取任何信源的情况下凭空构建功能树

### 必须事项

- 梳理前确认范围与粒度
- 节点名称使用产品语言（用户可理解）
- 不确定的节点用 ⚠️ 标注并说明推断依据
- 提供缺口分析（疑似缺失的常见功能）
- 同时输出层级列表与 Mermaid 思维导图

## 示例对话

**用户**：帮我梳理一下图片编辑功能的功能树

**助手**：
1. 确认粒度：功能级，根节点为「图片编辑」。
2. 询问信源：是否有 spec.md 或代码可参考？（若无，则使用口述构建模式）
3. 提取功能节点：
   - 基础调整：亮度、对比度、饱和度、色温、锐度
   - 裁剪与变形：自由裁剪、比例裁剪、旋转、翻转、透视矫正
   - 滤镜：预设滤镜（一键应用）、自定义滤镜强度
   - 标注与文字：文字标注、涂鸦、马赛克
   - 输出：保存原图、另存为、导出格式选择
4. 构建层级树，标注每个节点的状态（✅/⬜）。
5. 生成 Mermaid mindmap 与层级列表，输出 `功能树.md`。
6. 补充缺口分析：如「AI 智能增强」「去除背景」等常见功能是否在规划中？

---

**用户**：梳理一下我们相机 App 的整体功能树

**助手**：
1. 确认粒度：业务级，根节点为「相机 App」。
2. 读取信源：检索 `specs/epics/` 下的 epic.md，扫描 NavGraph 导航定义，从代码目录结构推断模块边界。
3. 提取一级功能：拍照、视频录制、图片编辑、相册管理、分享、设置。
4. 逐一展开二级/三级功能，代码逆向补充未文档化的功能点。
5. 生成完整功能树（含 Mermaid mindmap）+ 节点统计 + 缺口分析。
